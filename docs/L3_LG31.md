# L3 LG31: automatic loop frame clause for a push-only local `Vec`

Scope: G-LG28-2 (a syntactic push-only walk), G-LG28-3 (a non-reporting candidate loop invariant outside `--infer`)
and G-LG28-4 (the LG27 element clause of a push-only `Vec<S>` as such a candidate), which closes G-LG27-1 if it
lands. G-LG30-1..3, G-LG29-2 and G-LG29-4 are out of scope and unchanged.

Status: LG31: G-LG28-2 closed (push-only walk of a `while` body for an in-scope name, `push_only` in `pruvc/check.py` and `pruvc-rs/crates/pruv-proof/src/infer.rs`, the same answer in both compilers)
Status: LG31: G-LG28-3 closed (loop frame clauses: proved at entry and preservation, assumed after havoc; a failing one is dropped without an error and the function is verified again without it, in plain and `--infer` runs; both compilers, same trace)
Status: LG31: G-LG28-4 closed (each LG27 element clause of a push-only `Vec<S>` in scope at a `while` head is a frame candidate; positive and must_reject tests; bench/l3/claude a0-a4 proof time 199.6 s -> 197.4 s (-1.1%), within the 20% bound)
Status: LG31: G-LG27-1 partial (a `while` loop that only pushes onto a local or parameter `Vec<S>` no longer needs the element invariant written; a `Vec` field of a struct, a `for` loop over a map, and a loop that writes elements in place still need it: G-LG31-1, G-LG31-2)

## Step 1: the push-only walk (G-LG28-2)

`push_only(body, w)` walks a `while` body: statements of nested `if`, `match` arms, nested `while` and map `for`
bodies, and every expression (conditions, nested invariants and decreases, call arguments, `let` initialisers).
It is true when the body has at least one statement `w = vec_push::<T>(move w, x)` with `x` not mentioning `w`,
and every other occurrence of `w` is a plain read. Disqualifying: `w` as the root of an assignment target (any
other value, `w.f = e`, `w[i] = e`), the root of a `move` operand, the root of an argument at an `inout` position of
any call (user function or catalog form: `vec_clear`, `vec_reserve`, `vec_extend_from_slice`, `vec_at_mut`), the root
of any argument of `vec_pop`, and a `let`, match binder or map `for` key/value named `w`. The root of an expression
goes through field access, index, `inout` argument and variant field. A statement kind the walk does not know
disqualifies. A quantifier binder named `w` does not disqualify: it is a read-only expression scope.

Rule decision: the walk is syntactic and conservative, so it needs no new proof: it only selects where a candidate
is tried, and the candidate is itself proved (step 2). Being wrong in the permissive direction would cost a dropped
candidate and a re-verification, never soundness. The mutating forms are the `inout` ones of SPEC §6d plus
`vec_pop` (which takes the vector by value and returns a shorter one). Both compilers implement the same walk
(`push_only`, `lg31_*` helpers in Rust) and agree on every test program (the candidate ids and texts are in the
trace, diff_trace hard diff 0).

## Step 2: non-reporting loop candidates (G-LG28-3)

A frame candidate `F<loop>#<k>` is an extra loop invariant of `while` loop `<loop>` (the `--infer` loop numbering).
In the loop it comes after the written invariants and before `--infer` candidates; it is proved at entry and at
preservation (with its partial-operation domain obligations) and assumed after havoc and after the loop, the same
code path as an inferred invariant. Its what-strings are "loop frame clause `..` on entry" / "preserved" and
"partial operations in loop frame clause `..` (entry|preserved) are defined". When one of its obligations is not
proved (sat, unknown or error), the verifier records `(code, status)` for the candidate in `frame_failed` and appends
no error. The driver (`verify_program` `one(f)` / the Rust `one` closure) keeps a round with frame clauses only
if every frame clause was proved and the round reports no error. Otherwise the round's trace entries are rewound to
where it started (the sequence number is the trace length, so numbering stays dense), and its errors and inference
records are discarded; if some clause failed, the function (including `--infer` exploration) is verified again
without the failed ids; if none failed (another error, an inference timeout), the old path without frames decides.
So the final trace of a function is either one round in which every frame clause was proved and nothing was
reported, or exactly the old trace, and a rejected function always gets the old path's errors. Inside `--infer`
probes a frame obligation is not queried (the candidate is only assumed); the final run checks it.

Rule decision: a frame clause is a lemma the compiler proposes, so it may only add proofs. Assuming it is sound
only in the run where all its obligations were proved, and the driver commits exactly such a run. Dropping a failed
candidate and verifying again (rather than reporting it) keeps every program that verifies without frames
verifying, and no program the old path rejects is accepted: a kept round proved every assumed clause and reported
nothing, and every other outcome is the old path's. A frame can change an answer only from rejected to accepted.
Each retry drops at least one candidate, so the loop ends. Both compilers rewind the same entries, so traces stay
identical; a function with no candidate produces the old trace.

## Step 3: the element clause as a frame candidate (G-LG28-4)

For `while` loop `n` and each in-scope name (parameters and visible `let`s at the loop head, sorted) whose type is a
top-level `Vec<T>` with `T` reaching an invariant struct (the LG27 `vec_elem` test) and for which `push_only` holds,
each LG27 element clause `forall $inv_e in 0..len(w): C[w[$inv_e]]` is one candidate, with the text
"invariant of S (line L) for w[]" (the label LG27 uses). The push obligation is the existing struct-argument one.

Rule decision: preservation of the clause across `w = vec_push(move w, x)` follows from the `vec_push` contract
(old elements kept, new last element `x`) and the fact that `x` satisfies the invariant of `S` (a struct value), so
the candidate is proved for genuinely push-only loops and needs no new axiom. Shrinking or in-place writes are
excluded by the walk; if a body still breaks the clause (e.g. through a path the walk does not see) the candidate
fails and is dropped, so the program is judged exactly as before.

Evidence: `tests/runtime/lg31_push_frame.pruv` builds `Vec<P>` and `Vec<Q>` (an invariant struct inside an
invariant struct) in push-only loops (a plain loop, a conditional push, a push in a nested loop) with no element
invariant written; returning each vector needs the LG27 element check of the result, which holds only with the
frame (at 1a2221eb every one fails with `struct_invariant`). `tests/must_reject/lg31_frame_clear.pruv` is the plain
shape with a `vec_clear::<P>(inout w)` in the loop: the walk rejects it, no candidate is made and the return fails
with `struct_invariant` ("invariant of crate::P (line 5) for result[]") at line 23 in both compilers.

## Gaps

| Id | Gap |
|---|---|
| G-LG31-1 | A push onto a `Vec` that is a struct field (`s.items = vec_push(move s.items, x)`) or reached through a variant field gets no frame: the walk takes plain in-scope names only. Rule: extend the candidate names to field paths whose root is push-only and whose other fields are not moved, with the LG27 label of the path, in both compilers. |
| G-LG31-2 | `for` loops over a map get no frame clause (frame candidates follow the `while` numbering of `--infer`), and a loop that writes elements in place (`vec_at_mut`, `w[i] = e`) is not push-only. Rule: for the map `for` loop, number its frames separately and try them the same way; in-place writes need a per-element preservation proof of the written element, a new analysis. |
| G-LG31-3 | A discarded round costs a whole extra run of the function (plus `--infer` exploration): a failing frame clause, or any error in a function that has a frame candidate, verifies it again (the rejected function is verified twice). Rule: if a bench shows a measurable cost, cache the outcome of queries that do not depend on the dropped candidate, the same in both compilers. |
| G-LG31-4 | No test has a frame candidate that is generated and then fails (the dropped-and-retried path is exercised only by unit reasoning and the audit): an element that breaks the invariant is already stopped by the `vec_push` struct-argument obligation. Rule: add such a test once a push-only shape is found whose clause fails (e.g. through a path the walk does not see). |
| G-LG31-5 | With `--proof-cache`, a discarded frame round still stores its proved queries and counts its hits/misses, so the frame-free rerun of a rejected function can show `cached: true` entries the old path would not (both compilers alike; the cache key holds the assumptions and the negated goal, so nothing unproved is accepted). Found by the audit recheck after the last build. Rule: keep a round's new cache entries and statistics aside and commit them only when the round is kept, in both compilers. |
| G-LG31-6 | Rust `frame_candidates` still calls `scope_types(f, w)` per pushing `while` loop, and `find_loop_env` walks from the function start each time, so N sibling loops pushing the same `Vec` cost Θ(N²) statement visits (loops without a push are skipped). Rule: collect every loop head scope in one walk per function. |
| G-LG31-7 | Closed: codex test_impl passed 136/136 on all three pairs on the final build. Was: bench/l3/codex test_impl on the final build had not finished when LG31 was committed (all other checks above are on the final build). Rule: run it on this commit; a frame can only turn a rejected function into an accepted one, so a regression would show as a different emitted program, which the old/new compare did not find in tests/. |
