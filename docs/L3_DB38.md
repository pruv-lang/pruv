# L3 DB38: codex reader RSS split against hand, and a per-call compile wall limit (D-R09-1, D-R09-2, D-DB26-1, G-DB37-1)

Brief: size the codex reader's buffers to the input so the proportional RSS share drops to hand level (no run-time
check added), split RSS into a fixed and a proportional share, and fix G-DB37-1 in the harness only. Base: main
c807fa6f. The rs compiler was built once from this base (00:10 KST). No Pruv source changed in this bundle, so what is
proved is unchanged and no audit was run.

## What landed

- G-DB37-1 (`bench/g2/run.py`, `bench/l3/codex/test_impl.py`): `compile_pruv` takes a `wall` argument (seconds,
  default 600, so every other caller is unchanged). codex `test_impl.py` passes `CODEX_COMPILE_WALL` (default 3600).
  The proof and the solver timeouts are untouched; only the subprocess wall limit of the codex caller is raised.
- Buffer sizing: stopped before any Pruv change, because each remaining proportional copy needs a new analysis or a
  change outside this lane (D-DB38-1, G-DB38-1 .. G-DB38-3). The accounting below is from the existing layout
  (`root.pruv`, `read.pruv`, `util.pruv`, DB32's counting-allocator probe) and the measured fit.

## Where the RSS goes (L: 200 turns, 40 pages, 919,784 text bytes)

- Proportional, Pruv: `hb` grows by doubling (`util::grow_bytes`, 4 KiB .. 1 MiB); macOS keeps the freed medium
  blocks, so the chain touches about 2 MiB for 0.92 MB of held text. Then `replay` builds the store (0.92 MB) while
  `hb` is still live, drops `hb`, builds the wire (0.95 MB), and the host renders a `String` (1.02 MB). That is about
  5x the text, which is the fit below. The hand reader keeps one copy plus its output (1.02x).
- `hb` already grows only as needed (`needed = hs[1] + plen + rlen + 48`) with geometric steps; growing to exactly
  `needed` would touch more distinct block sizes, not fewer. The input is a stream from the child process and the
  protocol gives no total, so the only way to drop the chain is a per-page upper bound on the bytes a page adds to
  `hb` (decoded strings, folded replies, expanded stamps), which is a new proof (G-DB38-1).
- Fixed, Pruv: the per-read scratch arrays are small and the same size every read: `chunk` 64 KiB, `fb` 32 KiB,
  `pb` 18,024 B, `ht` 16,000 B, the tail buffer 16.4 KB, `s0` 9,600 B, `line` 4 KiB at start, the rest under 2 KB;
  about 0.16 MB. With 20 reads per process malloc hands the same blocks back to the next read, so reusing them across
  reads would save nothing measurable and would need a new entry signature (D-DB38-1). The runners are also
  0.17-0.31 MB larger than hand (842,048 / 984,480 B against 672,840 B). The rest of the 0.5-1.2 MB fixed gap is not
  attributed (G-DB38-3).
