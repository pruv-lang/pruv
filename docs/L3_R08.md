Proof fix by main: `turns.pruv` `plan_end` had two `assert forall` hints after `sl[1600 + i] = end`. With them, the rs
compiler timed out on the A3 root (`verify_unknown`, line 351), although the same file verified under the A4 root.
Adding frame asserts made it worse: both compilers then timed out. Removing both hints lets z3 prove the
`planned_spans(sl, b, i + 1, end)` postcondition directly on all 4 pairs and in all roots.

Not done (optional B item): direct source-span references, which would keep escape-free text as spans into the input
instead of copying it into the arena. A turn evicted from the ring also keeps its bytes in the arena until that input
ends. The arena does not compact.

## 4. Gaps

| Id | Gap | Workaround |
|---|---|---|
| G-R08-1 | The LLVM backend does not support `inout` structs or `take [u8]`. The arena cannot be a growing struct field that `turns` owns and resizes in place. | The arena is a plain `[u8]` passed `inout`. A new array is returned only when it has to grow (capacity doubling), and the caller swaps it in. |
| G-R08-2 | z3 does not reliably prove the quantified length-plan facts (`planned_spans`: modulo ring indexes inside `forall`). The result depends on the context: a hint that verified under one root timed out under another, and the outcome differed between the py and rs compilers. | The plan proof is split into two `forall` conditions (range and size bound), and one step is in its own `plan_end` function with no body hints, so that z3 proves the postcondition directly. |

point at the lines on each path. They come from reading the code and were not profiled.

That parser keeps a per-depth `[i64]` frame stack (`parse.pruv:123`), while the hand reader recurses with a native counter. The `import.pruv:507` `read_window` loop parses every line in full before `consume_entry` (`import.pruv:401`) looks at the type. |
| D-R08-2 | ring_wrap and turns200 window time (1.42x-1.65x), ring_wrap RSS 1.12x-1.18x | `turns.pruv` `answer`/`plan` keep evicted turns' bytes in the arena (no compaction), so the arena grows with every answer and `reserve` (`turns.pruv:68-76`, capacity doubling) copies it on each growth. The hand side drops evicted turns. Also `consume_entry` copies `title` and `model` on every `Effect::Done` return (`import.pruv:445-498`). |
| D-R08-3 | window_8MiB window time 1.56x-1.65x, RSS 1.65x | Text crosses the packet ABI as one `i64` per byte (`boundary.pruv:182` `write_bytes`). The exact-size packet from C is still 8 bytes per text byte, while the hand packet is built and dropped per entry. The arena copy of the 8MiB text sits next to that packet. |
| D-R08-4 | block_arrays window time py/llvm and rs/llvm 1.04x | Same per-line full parse as D-R08-1, on the LLVM backend only. The rust backend cells are 0.97x-1.00x. |
