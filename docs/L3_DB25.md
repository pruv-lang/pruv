# L3 DB25: claude window reader gating cells (D-DB16-1..6)

Brief: bring the claude window reader (`bench/l3/claude`) gating M/L cells to 1.0x hand Rust or below on time and
RSS, starting with D-DB16-4 (turns arena), then D-DB16-3, then D-DB16-1/2. Byte-identical output, no compiler edits.
Survey: docs/L3_DB16.md. Base: main 43b1bfb1.

## What landed

- `bench/l3/claude/turns.pruv`, `import.pruv`, `a3_root.pruv`: the turn arena grows in place.
  `reserve(inout buf: [u8], need: i64) -> ()` reassigns `buf = resize(buf, next, 0)`; `begin` and `answer` return
  `()`; `Step`, `BlockResult` and `Effect::Done` lost the `grown` field and `answer_blocks` returns `i64`. The
  `copy(replacement)` / `copy(grown)` calls on every growth are gone. Ensures now state `len(old(buf)) <= len(buf)`
  and `spans(st, sl, len(buf))`.
- `bench/l3/lib/access.pruv` `find_ascii`: an O(1) miss test before `ascii_equal` (key longer than the member
  span, or a first byte that is ASCII, not `\`, and differs). Profile share of `access::field` is unchanged
  (about 16% before and after, ring_wrap py/rust), so this is neutral; kept because the measured and tested tree
  includes it.
- `bench/l3/claude/q_mutants.py`: mutants 11 and 18 now delete `return;` instead of `return alloc(0, 0);`
  (the old text no longer exists after `answer` became `()`).
- `bench/l3/claude/q_measure.py`: `--rounds N` (default 7).
- Tried and reverted: `lib/parse.pruv` inline `tape = resize(tape, m, 0)` in place of `widened()`. It verified
  but gave no measurable change, because the Rust backend emits the resize as a copy (G-DB25-1).

## Remaining cost (ring_wrap py/rust, macOS `sample`)

`entry::parse_line` scan body is the largest share, then `access::field` (~16%), `string_is`, malloc/free and
memset/memmove (tape and arena resize copies, G-DB25-1). The arena change removed the growth replacement copy but
the time ratio moved only 0.03-0.12.

## Gaps

| id | gap | workaround |
|---|---|---|
| G-DB25-1 | `buf = resize(buf, n, 0)` on an inout or local array is emitted by the Rust backend as `Vec::with_capacity(n)` + `extend_from_slice(old)` + `resize` (a4.rs:1183 tape local, a4.rs:3995 `*buf` in `reserve`), a full copy, where hand Rust calls `Vec::resize` in place. | none; the growth policy (doubling) bounds the copies |
| G-DB25-2 | `JsonDocument` owns its `source`, so a scan of `data[lo..hi)` plus a literal suffix (`[]}`) cannot borrow the line; `scan_shortened` must copy it (entry.pruv). | per-line copy for depth-limited lines only |
