# L3 DB15: grok history reader time (D-DB7-1, D-DB7-2, D-DB7-3)

Goal: bring the grok history reader (dense, ord, ord-64k rows) toward hand Rust 1.0x with every observable
output byte-identical. Base is main at 3f4785ee.

## 1. Profile before the fix

`#[inline(always)]` removed and `#[inline(never)]` put on every generated `fn pruv_*`, and was built with
`rustc -C opt-level=3 -g`. Then macOS `sample` ran for 5 s on `perf_driver time pruv <row> 8000`. The numbers

Reading:
- ord: the line bytes are walked about five times: `validate_utf8`, `string_token` in the scan, the count and
  fill passes of `string_utf8`, and the host `from_utf8` check inside `utf8_to_string`. Decoding re-encodes

  small here.

## 2. What changed

- D-DB7-1 (UTF-8 pass): `read::line_step` calls `parse::scan_into` directly and no longer runs
  `lines::scan_span`, which ran `lex::validate_utf8` over the whole span first. The 16 MiB size check moved in
  front of the scan, and it returns 0 as before (`scan_span` gave kind 1 there, which also returned 0). An
  invalid line still fails in the scan: `string_token` validates UTF-8 inside strings and `token_at_span` rejects
  non-ASCII bytes outside strings. Both give a positive kind other than 18, and that skips the line as before.
  Scratch exhaustion (kind -1/-2) still takes `parse_range`, which validates. `view_root_type` stays because the
  scan does not report the root type.
- String decode: new additive `jstr::string_utf8_scanned` / `string_text_scanned` and
  `access::string_text_scanned`. A string span from a scanned (UTF-8 checked) document is copied raw with
  `copy_range` when it has no escape. Otherwise only the escapes are decoded and raw bytes are copied without
  the `step`/`scalar`/`width` re-encode. `util::str_at` uses it. The host `from_utf8` in `utf8_to_string` still
  runs (G-DB15-1).
- `entry::feed_user`: removed the extra `copy(txt)` of the prompt.
- Not done: D-DB7-2 subview turns feed and one raw-key pass, and D-DB7-3 scratch sizing.

Implementation: Codex gpt-6.2-sol (write delegation) did the five-file change. Claude Opus 5.5 did the review,
the `copy_range` change, the profile and the perf runs.
