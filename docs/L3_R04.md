## What landed

One change in `bench/l3/mcp/packet.pruv` (C, closes the data part of D-R00-1):

- `add_reserve` counts the bytes between the quotes of a string token (`end-start-2` when the token has at least two
  bytes). `put_units` decodes only `start+1..end-1`, and every unit consumes at least one of those bytes, so this is
  still an upper bound. The quotes were 6 spare words per tool, which `resize(p,want,0)` zero-filled.
- `add_raw` adds the raw tool-object length unchanged (one word per byte).
- `put_units_room` accepts `at + (inner bytes) <= len(q)`; its loop invariant is `at + cap <= len(q) || at + (stop-p0)
  <= len(q)` and follows from `k <= p-p0`. `put_field` tests the room with the inner length, so the unchecked path
  still runs for every field.

Effect (counters, `perf/work/counters.json`): zero-fill words now equal the written payload exactly (500 tools:
387873 = 392883 - 5010); before R04 the reserve was 3000 words over at 500 tools.

A (rebaseline): measured below. B (local bounds): the forward write cursor and per-tool descriptors are P05M (R00) work
and get no credit here; the remaining defensive guards are G-R04-1. C: the only measured byte handoff left is the prefix
copy (G-R00-2, carried); `root.pruv` handoffs are outside the measured core (G-R04-2).
