# L3 LG20: shared-context rs checks with isolated retry, count split staged in both verifiers, plain value temporaries

Scope: G-LG19-1, G-LG19-2, G-LG19-3 and G-LG19-4. Both compilers (Python `pruvc/`, Rust `pruvc-rs/`) where the item
has a Python side. No `bench/` file is changed. G-LG18-1/2/3, G-LG15-1, G-LG16-1 and G-DB31-x are out of scope and
unchanged.

Status: LG20: G-LG19-2 closed (the rs verifier checks each query in the shared context first and copies it into a fresh context with Z3_translate only when that check is unknown; g10a_v_wait_equal 0.02 s alone and assert under load, a4 within noise of the LG19 binary, the DB29 7-field struct repro verifies; a3 slowdown G-LG20-1)
Status: LG20: G-LG19-4 closed (Rust asserts the count split lemma only in a third attempt, after the attempts without lemmas and with the other aggregate lemmas, as Python; why the split slows Python boundary::copy_span stays unanalyzed, G-LG20-2)
Status: LG20: G-LG19-1 closed (a value-type temporary before `?` is bound only when its direct sub-expressions are plain; `lend(mk(2), 0) + need(x)?` is type/try_position in both compilers)
Status: LG20: G-LG19-3 closed (a plain argument may also be a node whose type, recorded on the temporary's typed copy, is a value type and whose own sub-expressions are plain, e.g. `eat(mk(len(s)), need(x)?)`; no second type check)

## What landed

- Shared check first, isolated retry (G-LG19-2, rs only). LG19 made `Solver::check` in `pruv-proof/src/sys.rs`
  translate every assertion into a fresh context for every query, which fixed G-DB29-1 (a datatype declared for another
  query perturbed the search) but cost every query the translation. A sat or unsat answer does not depend on which
  context found it; only an unknown answer can be the perturbation. `check` now runs the query in the shared context
  and returns sat or unsat from there; only on unknown it builds the isolated context (same timeout, rlimit and seed),
  translates the assertions and checks again, and `model` / `reason_unknown` then read the isolated solver. Chosen by
  measurement over a cached translated prefix: most queries are decided in the shared context, so the retry costs
  nothing for them, and the cached prefix would still translate each query's own assertions. The price is a second
  timeout for a query that is unknown in both contexts (G-LG20-1).
- Count split in a third attempt (G-LG19-4). The `count` range split lemma of R-6-4 goes into its own list
  (`split_lemmas` in `symbolic.rs`); `prove` and `probe_attempts` in `obligation.rs` try stage 0 (no lemmas), stage 1
  (aggregate lemmas) and, only when the module has split lemmas, stage 2 (aggregate and split lemmas), the same order
  as Python `run(2)`. With the split in the second attempt, Python `bench/l3/claude` a0 timed out in
  `boundary::copy_span`; Rust did not, but the two verifiers now prove with the same attempts. The trace still records
  `lemmas` as stage > 0, as Python. Measured on the rs a0-a4 roots below: a0, a1 and a2 got faster, a4 is unchanged.
- Plain value temporaries (G-LG19-1). The plain-argument rule of LG19 covered only owned call-result temporaries. A
  value temporary can also hold an owned value built inside it: `lend(mk(2), 0)` is an `i64`, but the `String`
  `mk(2)` that `lend` borrows is created in the temporary's `let` and dropped there, before `need(x)` runs. Python
  `try_temps` and Rust `try_temps` now reject a value temporary whose direct sub-expressions are not all plain, with
  `type/try_position`. `tests/runtime/lg18_try_owned_temps.pruv` used exactly that form in two functions; they now bind
  the borrowed call first (`let l: i64 = lend(mk(2), 0);`), with the same output.
- Value-typed calls as plain arguments (G-LG19-3). `try_plain_arg` (both compilers) also accepts a node whose type, as
  the temporary's own check recorded it on the typed copy (Python `a.ty`, Rust `expr_ty`), is a value type and whose
  own sub-expressions are plain (`len(s)`, `twice(len(s))`). Its result needs no drop, and the callee's own locals drop
  inside the callee. The owned branch now reads the arguments of the typed copy for this. A string literal stays not
  plain (`str` is not a value type), so `mk(len("a"))` keeps `type/try_position`. SPEC.md section 6 (the `?`
  paragraph and the `type/try_position` row) states the rule; R-6-4 states the staging.

## Gaps

| Id | Gap |
|---|---|
| G-LG20-1 | rs a3 got slower (27-30 s to 39 s), while a0, a1 and a2 got faster. Not attributed: both the isolated retry (a query unknown in the shared context pays a second timeout) and the split staging (a query that needed the split now runs a third attempt) can add time. Separating them needs a build with one of the two changes and a per-function timing of a3, which this lane had no build left for. |
| G-LG20-2 | Why the count split lemma in the second attempt slows the Python query of `boundary::copy_span`, which has no `count` term in its goal, is not analyzed (carried from G-LG19-4; both verifiers now avoid it the same way). |
| G-LG20-3 | A statement whose `?` operand borrows a name that another argument of the same call moves, with no other operand to lift, skips the borrow split check: `eat(read(s)?, move s)` is accepted because the check runs over the lifted temporaries only, and the `match` on `read(s)` separates the borrow from the move. Older than LG20 (both compilers, `try_temps` returns early when there are no temporaries). Needs the split check over the `?` operands themselves. |
| G-LG20-4 | A temporary that a `?` operand borrows (`need(mk(2))?`) lives until the end of the `match` arm, after the rest of the statement and the statements the lowering moves into the `Ok` arm, instead of ending with the original statement (SPEC section 6 lowering). Not a use after free, but the drop order differs from the statement before lowering. Older than LG20; a fix changes the lowering and the spec together. |
| G-LG20-5 | The rule is conservative: a value temporary whose sub-expression moves an owned call result into a take parameter (`eat(mk(1)) + need(x)?`, the String is dropped inside `eat`) or borrows a string literal (`string_eq(s, "a") == need_b()?`) is now `type/try_position`, although binding it would be safe. Accepting them needs the callee's take parameters and the literal lowering in `try_plain_arg`. |
