# L3 DB14: string pool behind ent_value helpers (stages 1 and 2 of the DB13 plan)

Brief: carry out the `docs/L3_DB13.md` staged plan for D-DB13-1 / D-DB13-3. Outputs byte-identical, cells at or below
DB12 (time M 0.931x, L 0.850x; RSS M 0.722x, L 0.646x), req no worse.

## What landed (commit 9870eb3e)

Stage 1, write side behind helpers. The coordinate is still `[6, unit_off, unit_len]` in UTF-16 units.

- `bench/l3/lib/ent_value.pruv` gains one helper block:
  - Pool shape: `pool_new`, `pool_words` (logical pool size), `slot_len_of`, `pkt_size` (logical packet size used by
    every limit and the op 9 numbers).
  - Writers: `pool_add` (append a string, return its slot offset), `pool_put` / `pool_put_lit` (append and write
    the slot).
  - Merging: `pool_cat` (merge two pools) and `pool_base` (rebase offset of the second pool).
  - Readers: `pstr_len`, `pstr_units`, `pstr_eq_lit`, `pstr_eq`, `pstr_cmp`. `pstr_cmp` is the one slot order used
    by `req_list`.
- Entry writers go through the helpers:
  - `ent_accounts`: home slot and account id read.
  - `ent_bound`: `threads_item` "codex" slot, `excluded_item` pool, `index_complete` value copy.
  - `ent_canon`: `folder_item`.
  - `ent_dispatch`: `rethrow` error and detail slots. The 200-unit title cut goes through a local
    `put_title_prefix`.
  - `ent_sources`: `emit_row` six-pool merge, and the `drive` pool accumulation and rebase.
  - `ent_state`: `repack` size, `with_prev` pool, `req_same` prefix, `ctx_path`.
  - `ent_packet`: `env_check` size limit, `mk_packet` / `boundary` pool length.
  - `entry_api`: op 9 `index_begin` / `index_step` limits through `pkt_size` and a private `logical_pool_words`.

Stage 2, req readers through the same helpers (D-DB13-3):

- `req_child::in1..in4`: pool size.
- `req_value`:
  - `units` now uses `pstr_units`.
  - `is_str_lit` / `slot_eq` use `pstr_*` when the slot is in range.
  - `truthy` now uses `pstr_len`.
- `req_list`:
  - `scmp` now uses `pstr_cmp`.
  - `pack` / `fin_pool` now use `pool_cat` and `slot_len_of`.
  - `make_keys` now uses `pool_put_lit`.
  - `fin_tabs` now uses `pool_base`.
- `req/root.pruv`: pool merges.
- `req/host.rs` `accept`: reads through one `eh::folder_units` in `req/host/src/lib.rs` instead of slicing the pool.
- `req_error`, `req_fill`, `req_packet` and `req_sources`: slot writes.

An out-of-range slot keeps the old clipped reading (`needs_clip` / `cmp_units` in req) so outputs stay identical.

Stages 3 and 4 did not land (see "Stage 3 scratch note").
