# L3 R07 opencode (A + B + C, fast mode)

Status: done, with debt. B (one admitted config root) and C (completion handoff) are in, and A (hand Rust lanes plus
`measure_r07.py`) is measured. Every time cell is over 1.0x, and each one is listed as a debt row D-R07-n. The main
conversation copies these rows into `docs/L3_RESTRUCTURE_SPEC.md` §7.4. This file does not edit the spec.

## 1. What landed

| Part | Files | What |
|---|---|---|
| B | `bench/l3/opencode/root.pruv`, `host.rs`, `harness.rs` | `opencode_begin` still runs the full `cfg_ok(cfg, t, true)` check, which includes the O(E^2) env uniqueness pass. The initial uniqueness validation stays. `opencode_step` is now a checked wrapper: it runs `cfg_ok(false)` (an O(E) walk) and then the old body, which moved unchanged into `step_body`. The new `opencode_step_admitted` has only O(1) `requires` (cfg length, mode, text length) and calls `step_body`. The host gets a `Sol::step_admitted` default and uses it after `begin` admits a config: `run_one` calls `step_admitted` when the begin packet is a full packet. The admitted root is the begin-checked `cfg`/`cfg_text` pair, which the host owns and does not mutate between steps. |
| C | `bench/l3/opencode/host.rs` | `completion_handoff` recognises the exact full-completion patch pair from `export.pruv:624` (`patch_resize(bank, n)` + `patch_copy(bank, 0, n, src 2, 0)`) on a byte bank. When it matches, the host moves the completion `Vec<u8>` into that bank (`std::mem::take`) instead of resizing and copying. Any other patch shape takes the old `apply_patches` path. |
| A | `bench/l3/opencode/hand/begin_hand.rs`, `hand/hand_main.rs`, `hand/perf_main.rs`, `measure_r07.py` | Hand Rust `begin` (the same geometry checks plus `HashSet` key uniqueness, O(E)) and hand `step` (the O(1) reentry/event check, which returns the outcome code only). `perf_main.rs` drives the generated `sol` with the same cfg (keys `K00000..`, value `v`), asserts that begin admits, and asserts that the checked and admitted steps give equal packets. The script builds both sides, runs them alternately, takes the median of 7 rounds and writes `bench/l3/opencode/work/r07/perf_cells.json`. |

Bugs: none found.

Copy sites seen but not changed (out of the C scope, kept as notes): `rows.pruv` decode copies (`copy(fr)`/`copy(fp)`),
the sql/rows relocate copies, `convert` `assemble_result` widening to one i64 per byte and the `assemble_step` copy

## 3. Perf (median of 7, alternating Pruv and hand, ratio = Pruv / hand)

M = begin E 1000, step E 1000 S 20000. L = begin E 4000, step E 1000 S 80000.

| Case | M time | M RSS | L time | L RSS |
|---|---|---|---|---|
| begin rs/rust | 25.4x | 0.98x | 217.9x | 0.93x |
| begin rs/llvm | 53.0x | 0.99x | 118.8x | 0.95x |
| step_checked rs/rust | 1393.7x | 1.06x | 1315.7x | 1.05x |
| step_checked rs/llvm | 1633.0x | 1.01x | 1368.6x | 1.01x |
| step_admitted rs/rust | 660.2x | 1.05x | 759.7x | 1.06x |
| step_admitted rs/llvm | 356.1x | 1.02x | 740.7x | 1.01x |

Admitted against checked, both on the Pruv side: rs/rust M 23.7 ms vs 50.1 ms, L 115 ms vs 189 ms. rs/llvm M 33.4 ms vs
58.4 ms, L 106 ms vs 222 ms. B removes about 1.3 us per step at E = 1000. The hand step times swing between runs
(36-152 us per 20000-80000 steps) because the hand loop returns only a code and the optimiser folds most of it away, so
the step ratios mostly measure the fixed Pruv packet cost.

## 4. Gaps

| Id | Gap | Workaround |
|---|---|---|
| G-R07-1 | A typed resident `inout st: S` host entry (an admitted config handle that the host keeps across steps) works only on the Rust backend. The LLVM backend and `--rust-bindings` reject it, so the admission cannot be a type that the step entry takes. | The host adapter owns the admission. `opencode_step_admitted` takes the same `[i64]`/`[u8]` cfg with O(1) `requires`, and the host calls it only after `opencode_begin` has admitted that exact pair. |

Test script note (not a language gap): `test_impl.py --verify-only` exits 2 on the rs compiler, because the rs `pruvc`
usage requires `-o` and the fallback only matches the text `verify-only`. Running the real tests (which verify and
compile) works.

## 5. Debt

| Id | Cells | Line-level cause |
|---|---|---|
| D-R07-1 | begin, all 4 time cells (25x-218x) | `root.pruv:86-98`: the uniqueness pass compares each key with every earlier key (`while j < i`, `key_same`), O(E^2), while the hand side inserts into a `HashSet`, O(E). It grows with E (rs/rust 25x at E 1000, 218x at E 4000). Pruv has no hash set over byte slices. A sort-based O(E log E) check is possible with current features but was not tried (fast mode, one try). |
| D-R07-2 | step_checked, all 4 time cells (1316x-1633x) | `root.pruv:106` `cfg_ok(cfg, t, false)` in the checked `opencode_step` walks all E env rows on every step. This is the cell that B removes for the host: the host now uses `step_admitted`. The checked entry stays for callers without a begin. |
| D-R07-3 | step_admitted, all 4 time cells (356x-760x) | `root.pruv:379-400` `step_body`: every step allocates `ctl_init(cfg[1], 999)` (a 76-word blank packet), runs `banks_ok` over 7 banks and `ctl_ok_at` over the 64 ctl words, and the reject path builds a full packet through `done_internal`. The hand `step` returns a single code with no allocation, so the ratio is the fixed packet cost of about 1.2-1.4 us per step. The lane is asymmetric by design, because the hand side has no packet protocol. |
| D-R07-4 | step_checked/step_admitted RSS 1.01x-1.06x | The same per-step packet `Vec` allocations as D-R07-3. The allocator high-water mark is a few tens of KiB above hand. |
