# L3 DB28: codex per-line and per-turn copies (D-DB5-4, D-DB26-1, D-DB26-2)

Base: main fe9d96ab. Survey: docs/L3_DB26.md, docs/L3_DB5.md and docs/L3_DB11.md (not repeated here).
Compiler: main's `pruvc-rs/target/release/pruvc` (same source as the branch point; compilers are not in this lane).

## 1. Profile

`sample` of the rs/rust runner on 200 L reads (4 s, 1 ms), before the changes. About half of the main thread is waiting
on the fake server (`read`, condvar waits in the effect runtime). Of the CPU part, in this order:

- `rpc::parse_line`: about 460 samples. It copied the line twice (`b`, then `util::trim` into a new buffer) before
  `lines::parse_range` copies it a third time into the document, validates UTF-8 and scans the tape.
- The inlined `read_wire` body (absorb, `item::read_turn`, `replay`): about 170.
- The effect runtime's `ev_proc_read` (`VecDeque` drain into a `Vec`, byte by byte): about 190 (G-DB28-1).
- `util::str_at` (decoded copy of each string value): about 160.
- Host `serde_json` string escaping in `render_read`: about 60.

## 2. Changes (bench/l3/codex only; pkgs/turns unchanged)

- `util.pruv`: `trim` (copying) is replaced by `trim_span(b, n, inout r)`, which returns the trimmed span of
  `b[0..n)` with `ensures 0 <= r[0] <= r[1] <= n`. `space_in` is `space` bounded by `n` instead of `len(b)`. The bounds
  are proved; there is no run-time check.
- `rpc.pruv` `parse_line`: passes `(line, r[0], r[1])` straight to `lines::parse_range`. The two copies of each line
  are gone; error positions stay relative to the trimmed start as before.
- `read.pruv` `replay`: `copy(fbuf)` and `copy(t)` are gone. The clipped reply is joined in place
  (`fbuf = join(fbuf, pad)`) and the decoded text is passed straight to `feed` (one call per branch, since a `str`
  cannot be moved into an outer `let mut`, G-DB28-2).
- `item.pruv` `read_turn`: the `RawTurn` fields are built by calls (`to_bytes`, a new `head`, `stamp`) instead of
  `let` then `copy(...)`, which removes a second copy of the prompt, reply, plan and stamps per turn.

Kept (D-DB28-1): `pbytes` and `fbuf` in `replay`. `turns::begin2`/`answer2` take `str` and clip with
`text::clip_bytes(str)`; feeding a span of `hb` needs a span form of both and of `clip_bytes` (pkgs/text is not in this
lane), and the store offsets proof needs `Store` invariants (G-DB26-1). The wire is still built from the `finish2`
text (`packet::wire_read`), for the same reason.

## 4. Perf (D-DB26-2)

`measure_r09.py` (rs/rust), 7 alternating rounds each, base (fe9d96ab, `/tmp/db28-base`) right before the change, same
window, load average 3.95-4.82 (1 min). Cells: `bench/l3/codex/work/perf_cells.json` and `perf_cells_base.json`
(not committed).

| cell | base Pruv/hand | DB28 Pruv/hand |
|---|---|---|
| M time | 1.506x | 1.497x |
| M RSS | 1.702x | 1.713x |
| L time | 1.844x | 1.800x |
| L RSS | 3.249x | 3.221x |

The change is within noise: no cell moved by more than about 2%, in either direction. The copies removed here are not where
the time goes. What remains is the JSON walk and string decoding (D-DB28-2), the runtime read copy (G-DB28-1) and the
waits on the fake server, which are the same for both sides. L time is above the DB26 range (1.74x) in both base and
DB28 in this window, so it is not a regression of this bundle. rs/llvm was not measured (D-DB28-3).

## 5. Debt and gaps

| id | what | next |
|---|---|---|
| D-DB28-1 | `replay` still copies each held turn's prompt and reply out of `hb` (`pbytes`, `fbuf`) and the wire still holds a second text next to the `finish2` result. | Span forms of `turns::begin2`/`answer2` and `text::clip_bytes` over `(buf, start, len)`, plus `Store` invariants (G-DB26-1) for the wire from store bytes. Needs the pkgs/text lane. |
| D-DB28-2 | The JSON walk itself is unchanged: `lines::parse_range` copies the line into the document, and each string value is decoded into a new `str` (`util::str_at`, `access::string_text`). The hand reader decodes once with serde. | A borrowed-span string API in pkgs/access/jstr (not in this lane), then `item_text` over spans. |
| D-DB28-3 | codex rs/llvm time and RSS not remeasured in DB28 (2 h cap); only rs/rust was measured against base. | Measure rs/llvm with the next codex perf bundle. |
| G-DB28-1 | The compiler-emitted effect runtime `ev_proc_read` moves child output from a `VecDeque` into a `Vec` byte by byte (`extend_desugared` over `Drain`), about 190 of 600 CPU samples on L. | Emit `extend` from the two `as_slices` halves (pruvc lane). |
| G-DB28-2 | A `str` local cannot be moved into an outer `let mut` `str` (`text = move t` is rejected as `array_alias`; only literals, `copy()`, `substr()` and calls are allowed). Worked around by calling `feed` in each branch. | Allow `move` of a `str` local into a `str` variable. |
