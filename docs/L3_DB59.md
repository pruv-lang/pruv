# L3 DB59: codex owned jstr decodes, reused line buffer for parse, perf old/new/hand

Brief: (1) G-DB56-1 / G-DB56-5, codex fresh-local decode callers and `pkgs/time` move to the DB56 owned decodes;
`return copy(x)` stays only where a move is impossible. (2) G-DB58-1, stop allocating a fresh `line.data` block per
page line with existing language features (a borrowing parse in bench/l3/pkgs over the reused line buffer, as
`hand/reader.rs:29-30`). (3) G-DB58-2, codex M/L old (main 5c13fb0b) vs new vs hand on all four pairs. Base: main
5c13fb0b. One release `pruvc-rs` build in the worktree; no compiler, runtime, stdlib, fixture or test change.

## What landed

- `bench/l3/pkgs/lines/lines.pruv`: new `parse_copy(data, lo, hi)`, the `parse_range` contract for a caller that
  keeps its buffer. `data[lo..hi)` is copied once into an exact-size block (`copy(subview(data, lo, hi))`, one
  allocate-and-fill) that `parse_owned` moves into the document. `parse_range` (zeroed block, byte loop, then a second
  `copy`) is unchanged because grok, mcp, qwen and lib/json call it.
- `bench/l3/codex/rpc.pruv` `parse_line`: trims the span and calls `parse_copy(line.data, lo, hi)`. `line.data` is no
  longer moved into the document, so it stays allocated at the longest line seen and `grow_bytes` does not regrow it
  per page line. The document keeps one exact-size block per line, as hand's `JsonDocument` keeps its own copy.
- Owned decodes (G-DB56-1):
  - `codex/util.pruv` `str_at`: `access::string_text` -> `access::string_text_owned`.
  - `codex/plan.pruv` `take_segment`: `adapter_probe(seg)` -> `owned_text(move seg)` (seg is a fresh local).
  - `codex/read.pruv` `stamp_str`: `adapter_probe(cb)` -> `owned_text(move cb)`, `return copy(s)` -> `return move s`.
  - `codex/item.pruv` `read_turn`: `plan = copy(x)` -> `plan = move x`; `codex/root.pruv`: `model = copy(mt)` ->
    `model = move mt`.
- `pkgs/time/time.pruv` (G-DB56-5; shared with grok and opencode): `iso_of` decodes with
  `access::string_text_owned`; `absent`, `defect`, `from_integer`, `from_string` and `iso_of` move their fresh local
  into `Iso { text }` instead of copying it; `copy_canonical` returns `out` instead of `copy(out)`.

## Copies kept, and why

| Site | Kept | Why a move is impossible |
|---|---|---|
| `codex/util.pruv` `str_at` | `return copy(x)` on the `Decoded(x)` arm | pruvc-rs rejects `move x` of a match binding (`foreign_move`: "moving a borrowed parameter"); pruvc py accepts it (G-DB59-1) |
| `codex/item.pruv` `stamp` | `return copy(iso.text)` | a field moved out must be reassigned by the next statement (`foreign_move`), and `Iso` has no destructuring |
| `codex/list.pruv:50` | `adapter_probe(iso.text)` | same field rule; `owned_text(move iso.text)` is rejected |
| `codex/read.pruv:44-45` | `copy(raw.completed/created)` | `raw` is read afterwards |
| `codex/plan.pruv` `take_segment` | `let mut u = copy(t)` | `t` is read after the copy (`marker_end`, `substr(t, m, len(t))`) |
| `pkgs/time` `present(t)` | `copy(t)` | `t` is a read parameter |

## Audit

One review (Codex gpt-6.2-astra ultra) of eb881bb0. Must-fix: `codex_list` started its line buffer at 8 MiB
(`root.pruv:35`); before DB59 `parse_owned` moved it into the first document and freed it, now it was kept for the
whole list. Fixed: it starts at 4 KiB like `codex_read_wire`; `receive` grows it up to the same 8 MiB line limit.
Advisory (kept): a final line with no surrounding blanks is copied once where it used to be moved; recorded as
G-DB59-2. No correctness defect found in `parse_copy`, `receive`/`step` length handling or the owned decodes.
