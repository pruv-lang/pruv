# L3 LG16: struct invariants (proof-only), and in-place resize in the Rust backend

Scope: G-DB26-1 (struct invariants) and G-DB25-1 (`x = resize(x, n, v)` copies). Both compilers (Python `pruvc/`,
Rust `pruvc-rs/`) change with the same output. No `bench/` fragment is changed.

Status: LG16: G-DB26-1 closed (struct invariant clauses, proof-only, modular rule below, same rejects and messages in both compilers)
Status: LG16: G-DB25-1 partial (Rust backend grows a local or resizable inout array in place; LLVM still copies, G-LG16-1)

## What landed

- Syntax: `struct S { a: i64, b: i64, invariant <bool expr>, invariant <bool expr> }`. Clauses follow the fields,
  name fields bare, and may call contract-callable user functions.
- Rule (verifier only; codegen, runtime requires checks, opaque inline and cost do not see the clauses). For every
  function, each parameter of type exactly `S` gets a synthesized precondition `INV[p]`, each `inout` `S` parameter a
  synthesized postcondition `INV[p]` on its final value, and a return type `S` a synthesized postcondition
  `INV[result]`. They are kept apart from the user's clauses and come before them. So the entry assumes `INV`,
  each call argument proves it, each return and inout exit proves it, and after a call the caller assumes it for the
  result and for inout arguments. Between field writes the value may break it. Nested positions (fields, elements,
  `Option` payloads) are not assumed. The z3 cost is one instance per boundary value, no quantifier over all `S`.
- Rejects: `type/invariant_decl` for a non-bool clause, `old()` / `result` in a clause, a generic struct with an
  invariant, and a parameter named `result` of type `S` (it would capture the rewritten clause);
  `type/entry_signature` for a host entry taking an `S` (callers outside are not verified). A broken clause is
  `verify/struct_invariant`; at a return or inout exit the clause's partial operations (index, `/`, `some_val`, ...)
  are proved first under the same code and message, and at entry the synthesized requires get the same domain
  handling as user requires. A quantifier variable named like the parameter is renamed before the rewrite.
- A contract call to a user function that takes an `S` does not prove `INV` for its argument: the call is expanded to
  the body (P06), which denotes the same value for every argument, and the partial operations that remain in the
  expanded expression are proved where it is used. So a body whose result relies on `INV` for a division or an index
  is still checked at the contract site (`B { a: A { n: 0 } }` with `invariant q(a) >= 0` and `q` returning
  `100 / a.n` is rejected). Operations the expansion drops (an unused `let`) are not checked there; the contract never
  runs `q`, so no run-time fault follows.
- The guarantee holds for verified builds and normal exits; safe mode (`--no-verify`) does not check invariants.
- Resize: the statement `x = resize(x, n, v)`, where `x` is a `let mut` local or a resizable / take `inout`
  array and arg 0 is a plain read of `x`, emits `{ let pruv_n: i64 = n; let pruv_v: T = v; <check>x.resize(pruv_n as usize, fill); }`
  in both compilers. Cost accounting, a moved/last-copy target and other targets keep the copying form.
- SPEC.md: section 6a (struct invariants) and the `resize` paragraph.
- Tests: `tests/runtime/lg16_inv_basic`, `tests/runtime/lg16_inv_store`, `tests/runtime/lg16_resize_inplace`,
  `tests/must_reject/lg16_inv_*` (13). The Store-like example (`lg16_inv_store`: slot offsets and sizes bounded by
  `end <= len(data)` under a `forall` over 8 slots, read through a modular slot index with no offset requires) verifies
  without a z3 timeout, so no Store encoding gap is open.

## Gaps

| Id | Gap |
|---|---|
| G-LG16-1 | LLVM `@pruv_resize` still allocates a new block and copies the prefix for `x = resize(x, n, v)`; LLVM arrays carry no capacity, so an in-place grow needs a capacity word in the array layout. |
| G-LG16-2 | Legacy single-file mode makes every function public without a host-entry check, so a host Rust caller can pass a struct value that breaks its invariant; the verifier assumes it at entry. Fix options: reject invariant structs in legacy public signatures, or require explicit mode for structs with invariants. |
