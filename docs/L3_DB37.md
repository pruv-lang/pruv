# L3 DB37: codex `write_span` split into two helpers, and a pre-executed fake exporter for opencode F08 (G-DB36-2, G-DB36-1)

Brief: restate `@turns::write_span` so it no longer sits near the solver timeout (no runtime check added, generated
code no slower), and find why the ts reference's F08 children die before their first statement under load, fixing it
in the test harness. No compiler edits (docs/L3_RESTRUCTURE_SPEC.md 7.5). Base: main c3709107. The rs compiler was
built once from this base (22:35 KST).

## What landed

- G-DB36-2 (`write_span`, `bench/l3/pkgs/turns/turns.pruv`): the body was `put_nl`, `copy_span` and four inline pad
  stores under `if pad == 4`, all proved against the full contract in one function (36 queries). It is now two calls
  to new private helpers with their own frame contracts:
  `put_nl_span(inout dst, at, sep, src, lo, n)` (the `sep` LF bytes then `src[lo..lo+n)`, everything else unchanged)
  and `put_pad(inout dst, p)` (the four UTF-8 bytes of U+10000 at `p`, everything else unchanged). `write_span`'s
  signature, requires and ensures are unchanged; it now only composes two frames.
  Base vs tree (codex, the py verified compile on its own, `pruvc.py bench/l3/codex/root.pruv`): base 68dec559 (a
  `/tmp` worktree, since removed) passed in 800 s at load 110 -> 27 (22:44-22:58 KST); this tree before the change failed
  in 526 s at load 22 -> 12 with the DB36 error (`solver gave up proving postcondition (line 837) in @turns::write_span
  (timeout)`). `write_span` is the same in both, so the old proof is not "broken on this tree" but
  sits close to the 8000 ms query timeout and loses or wins on load. After the change codex test_impl passed on all four
  pairs. One run at load 110 stopped before any solver error: the py pair's compile exceeded the 600 s wall limit in
  `bench/g2/run.py` (`rc -1, stderr timeout`); the rerun at load 5-38 verified (G-DB37-1).
- G-DB36-1 (opencode F08, `bench/l3/opencode/common.py`): stamps on the ts side (spawn time in
  `reference-primitives.mjs`, first-statement time in `fake_exporter.py`, both temporary and removed again) showed
  250-850 ms from spawn to the fake's first statement at load 6.5, while a plain `python3 -c pass` starts in 10-15 ms.
  The time goes to macOS's first-exec check of a newly written executable: `place_exporter` wrote a fresh copy of
  `fake_exporter.py` for every case, and the first exec of a fresh file took 180-420 ms on that host (seconds under
  heavier load), against about 10 ms for a hard link to a copy that has already been executed. With `rpcMs` 1000 in the
  hang cases that was enough for the deadline to fire before the fake installed its handler. `place_exporter` now
  hard-links each case's exporter to one per-process copy that is executed once at first use (`warm_exporter`), with
  the old write-and-chmod as the fallback if linking fails. The file the importer sees is the same regular file
  (same bytes, mode 0755). After the change the spawn-to-first-statement time was 109-509 ms at load 28 and F07+F08
  on the ts reference passed 25/25. Not a Pruv cause. `test_impl.py --only F08` then passed 18/18 on all four pairs at load 4.3-8.7
  (23:14-23:20 KST, codex and grok test_impl running alongside), and the full run passed F08 too (below).

## `write_span` numbers

Per-function py verifier counts on the codex program (`/tmp` scratch recorder, unchanged compiler):

| function | queries | time |
|---|---|---|
| `write_span` old | 36 | 0.13-0.67 s |
| `write_span` new | 23 | 0.07-0.08 s |
| `put_nl_span` (new) | 12 | 0.04-0.06 s |
| `put_pad` (new) | 16 | 0.02-0.03 s |

All queries unsat, no unknowns. The old function's spread is the load (2-110 on this host during the runs); its slowest
query is the frame clause at line 837 that timed out in DB36 when the machine was loaded.

Generated code: the old and new `write_span` were emitted by the py compiler into one crate and wrapped in
`#[inline(never)]` functions; `rustc -O --emit asm` gives the same 137-line function for both, differing only in local
label numbers (`Lloh*`). A 20M-call loop ran 0.66-0.77 s old vs 0.58-0.77 s new (noise, load about 100). No runtime
check was added (the helpers' requires are discharged statically at the call sites, like `put_nl`'s).
