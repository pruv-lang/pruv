# L3 LG12: LLVM layout for typed errors (E1, E2) and `?`

Scope: wave 1 of `docs/LANG_ROADMAP.md` (typed errors and `?`) on the LLVM backend, so that both backends give the
same results. Both compilers (Python `pruvc/`, Rust `pruvc-rs/`) change with the same output. No `bench/` fragment is
changed.

Status: LG12: G-LG10-2 closed (LLVM layout for every value E in both compilers)
Status: LG12: G-LG11-2 partial (LLVM `Result<T, String>` for T = `i64` / `bool` outside records and other generic types; the rest is G-LG12-1..5)
Status: LG12: G-LG11-4 closed (lg11_e2_string leaves `tests/llvm_pending.txt` and is measured with `g6_drop_balance` on LLVM)
Status: LG12: G-LG11-10 closed (Rust caller-side `__pruv_cost` argument `&pruv_cost_arg_0`)

G-LG11-1 (`?` only at statement level) was not touched and stays open.

## What landed

- LLVM layout for `Result<T, E>` with a value error type E (closes G-LG10-2). The runtime struct is
  `{ i1, L(T), L(E) }` and the contract struct `{ i1, Lc(T), Lc(E) }`; the host ABI words are the tag, the words of
  T, then the words of E, and the words of the inactive side are 0. These are the backend's own word layouts, not C
  layouts of the Rust types: the host bindings (`rs_ser` / `rs_de`) read and write the words field by field. For
  E = `i64` every helper produces the old `{ i1, L(T), i64 }` text, so the LLVM output and ABI of all `Result<T>`
  programs are unchanged; `Result<i64, i64>` keeps its old two ABI words (tag and active payload). The Err constructor, the `Err(e)` match binder, `to_c`, contract equality, `err_val`, the
  G9 helpers (walks, weight, equality) and ABI encode/decode handle E.
- LLVM `Result<T, String>` (owned String error, E2; G-LG11-2 partial). The layout is `{ i1, L(T), ptr }`; the String
  handle is null on Ok and after a move. The value is an owned aggregate: it travels through output storage and `ptr`
  parameters like other extended values. `Err::<T, String>(s)` moves `s` (its slot is nulled); a match on a local
  moves the handle out of the local, the `Err(e)` binder owns it and drops it at the end of the arm unless it is moved
  on; a local that is moved (`move r`, `?`, a call argument) is zeroed; every live handle is dropped at scope end, on
  an early return and on assignment. Supported for T = `i64` or `bool` as a local, parameter, result or temporary.
- `?` on LLVM for every laid-out E, including `String`: it is the existing `match` + `return Err`.
- Rust `codegen.rs` passes `&pruv_cost_arg_0` for a `take` parameter of type `Result<_, String>` in a caller-side
  `__pruv_cost` call, as Python does (G-LG11-10).

## Gaps

| Id | Gap |
|---|---|
| G-LG12-1 | LLVM rejects `Result<T, String>` with T other than `i64` / `bool` (`codegen/unsupported_type`; sample `tests/runtime/lg12_e2_struct_ok.pruv` in `tests/llvm_pending.txt`). |
| G-LG12-2 | `Result<T, String>` as a record or enum field or as an argument of another generic type is rejected on both backends by the checker (`type/foreign_owned_type`; as the error type of another `Result` it is `type/result_error_type`); the LLVM layer would also need a drop path through that type. |
| G-LG12-3 | A host entry with `Result<_, String>` in its signature is rejected on both backends by the checker (`type/entry_signature`): the owned handle has no C ABI. |
| G-LG12-4 | LLVM rejects `is_ok` / `ok_val` / `err_val` on a `Result<_, String>` in a runtime-checked `requires` (no i128 contract mirror of the String). |
| G-LG12-5 | LLVM also rejects `is_ok` / `ok_val` / `err_val` on a `Result<_, String>` in a `cost` clause that is kept (`--no-verify`; after verification the clause is erased), and the message says "in a runtime requires" there (the G9 message names only that clause). |

## Tests

- `tests/runtime/lg12_abi_struct_err` (struct E through the host ABI, both directions) and `tests/runtime/lg12_try_enum`
  (enum E with `?` twice) on both backends.
- `tests/runtime/lg12_e2_paths` (both backends, `g6_drop_balance`): an unused `Err` binder, `?` through two levels,
  an Ok local never matched, an Err local dropped by an early return before its match, a `bool` Ok type.
- `tests/runtime/lg12_cost_move` (both backends, `g6_drop_balance`): the caller-side cost call of G-LG11-10.
- `tests/runtime/lg12_e2_struct_ok`: Rust backend runs; the LLVM rows expect the G-LG12-1 rejection.
- `tests/runtime/lg11_e2_string` and the LG10 / LG11 value-E samples left `tests/llvm_pending.txt`.
