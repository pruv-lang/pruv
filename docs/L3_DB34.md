# L3 DB34: `JsonDocument` invariant, access checks, mutant texts, a2_root verify time (G-DB33-3, G-DB33-4, G-DB33-5)

Brief: give `JsonDocument` a struct invariant with the record-local tape facts and drop the per-member checks in
`access::field` / `find` / `find_ascii` that it proves; fix the replacement texts of `bench/l3/json/run_q_mutants.py`
so all 25 mutants run; attribute the py verify time rise on `a2_root` (34.5 s → 78.0 s in DB33). No compiler edits.
Base: 52c84fec.

## What landed

- `JsonDocument` (`pkgs/json/json.pruv:55`) carries five LG16 struct invariants: shape and bounds (`len(tape) % 6 == 0`,
  `6 <= len(tape) <= 6291456`, `len(source) <= 16777216`), kinds 0..7, spans `0 <= s < e <= len(source)`, skips
  `t < skip <= records`, and skip `t + 1` for scalars, strings and keys (kinds 0..4 and 7). These are the facts that
  `scan_document` ensures since DB33 and that `check_tape` pass 1 checks, so every builder proves them: `parse::parse`
  and `publication_ok` from the scanner ensures, `lines::parse_range` / `build_span` and the other `check_tape`
  callers from `check_tape`'s ensures. `pub pred fn doc_local` (`json.pruv:84`) states the same facts as a predicate.
- Handoffs inside an enum payload are nested positions where the invariant is neither assumed nor proved, so every
  function that returns a document inside `JsonParse::Parsed` or `Line::Object` ensures `doc_local` of the payload:
  `lines::parse_range` / `build_span` / `parse_span` (`pkgs/lines/lines.pruv:34,93,116`) and, outside the lane,
  `qwen/entry.pruv:10,30` (`parse_line`, `parse_line_span`), `grok/rpc.pruv` and `codex/rpc.pruv` `parse_line`. The
  four out-of-lane lines are proof-only ensures (no code change); without them the documents these wrappers hand to
  `access` fail the invariant at the call (D-DB34-2).
- Runtime checks removed from `pkgs/access/access.pruv` (each one is implied by the invariant for any document):
  - `valid`: the tape length bound `len(tape) > 6291456` and the lower kind bound `0 <= kind` (only `kind <= 6`, i.e.
    not a key, stays).
  - `raw_span`: the span check `s < 0 || e < s || e > len(source) || e > 16777216` (status -4).
  - `array_at`, `find`, `find_ascii`: the container skip check `stop <= id || stop > len(tape) / 6`, and `next <= j`
    (`next <= v`) per member.
  - `find`, `find_ascii`: the key skip check `tape[6j+3] != j+1` and the key span check
    `s < 0 || e < s || e > len(source) || e > 16777216` per member.
  - Kept (not record-local, so not in the invariant): key kind `!= 7`, parent `!= id`, `v >= stop`, `!valid(v)`,
    `next > stop`, `tape[6v+4] != id`.
- `run_q_mutants.py`: six replacement texts updated to the current sources (the parse mutants now target
  `scan_document`'s `failure(...)` forms, the old texts named the DB30 `done(...)` code; `surrogate_combine` and
  `first_wins` named code that had changed). All 25 mutants now match exactly once and run (see Tests).
- Source review (Codex gpt-6.2-astra, one pass): every removed access check is implied by the invariant, no
  observable result changes, 24 of 25 mutant texts are sound (`depth_bound` is the documented equivalent); one
  must-fix, the `trailing_comma` text (below).
- `trailing_comma` replaced the always-false `state == 1 && state == 4` (which only changed the error kind) with a
  `closing` condition that also takes states 1 and 4, so the mutant now really accepts a trailing comma (source
  review must-fix).
- a2_root py verify time (G-DB33-5): attributed per function; no source change (see Verification time).
