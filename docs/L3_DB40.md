# L3 DB40: codex reader writes the wire from `hb` spans, no `turns` store (G-DB38-2, G-DB38-1, D-R09-2, D-DB26-1)

Brief: drop the `turns` store copy in the codex reader by adding a store-less form to `bench/l3/pkgs/turns`
(additive), then bound what `absorb` adds to `hb` per page so `hb` grows once per page. Base: main 93205055. The rs
compiler was built once from this base (00:50 KST); no other compiler build.

## What landed

- `bench/l3/pkgs/turns/turns.pruv`: four functions appended (`new_refs`, `begin_ref`, `answer_ref`, `finish_ref`),
  +183/-0. Every existing function and contract is unchanged. The `_ref` form keeps per-turn offsets into a caller
  byte arena instead of a store, and `finish_ref` writes the selected turns into the wire straight from those spans,
  with the same `Placed` result and the same ok=false rule for an invalid span as `finish_into`.
- `bench/l3/codex/read.pruv`: `replay` no longer builds a `turns` store. `hb` stays live until `finish_ref`, which copies
  from `hb` into the wire. The 24-byte stamp is passed as an `hb` offset; `stamp_str` already copied those 24 bytes
  out of `hb` and only checked UTF-8, so the wire bytes are the same.
- `bench/l3/codex/measure_r09.py`: `median` -> `median_low`, so even round counts no longer crash on a non-integer
  median.
- G-DB38-1 stopped before any change (G-DB40-1): `util::str_at` only ensures a 50 MiB length cap,
  `access::string_text` only ensures 3x the token length, and `lib/json` gives no proof that the tokens of one page do
  not overlap. A per-page bound on `hb` growth from the page line length needs those three facts, and two of them sit
  in `bench/l3/lib/`, outside this lane. On paper (not proved): with disjoint tokens, decoded strings are <= 3x their token
  bytes by the `string_text` contract, folded replies are <= the raw reply bytes, stamps are 24 bytes per turn, plus
  the 48-byte slack of `grow_bytes`' `needed`; so a page adds at most 3x its line length + 24 per turn + 48.

Model use: the `turns` / `read.pruv` change was written by Codex gpt-6.2-sol (write delegation, one candidate,
reviewed and applied as is). The old runners were built by a command delegation from the base sources. The audit was
Codex gpt-6.2-astra ultra (correctness review). The bound analysis, the measurement and this doc were done here.

## Audit (Codex gpt-6.2-astra ultra, once)

No must-fix. Checked: the wire and `Placed` equal the old store path; codex cannot reach the `answer_ref` failure or
pad-write paths; the stamp is the same 24 bytes; no new allocation or quadratic loop on the per-turn path. It noted
that the new path still holds `hb` while the wire is allocated; the measurement below is the check of the peak.
No recheck (nothing to fix).
