# L3 DB44: codex reader writes the wire in place over `hb`; fixed-share probe (G-DB40-2, G-DB38-3, D-R09-2, D-DB26-1)

Brief: drop the `hb` + wire peak in the codex reader (G-DB40-2) by writing the wire in place over `hb`, with a new
additive `turns` form and its proof; then measure a one-read fixed-share probe per pair (G-DB38-3). Base: main
f3919ed2. The rs compiler was built once from this base; no other compiler build. G-DB40-1 and compiler changes are
out of scope.

## What landed

- `bench/l3/pkgs/turns/turns.pruv`: one function appended, `finish_inplace(st, sl, rf, inout buf, base, at)`. Every
  existing function and contract is unchanged. It has the requires of `finish_ref` and its ensures minus the frame
  clause, plus `len(buf) == len(old(buf))` and `result.ok ==> 0 <= at <= len(buf) && text_len <= len(buf) - at`. It
  writes kept draft j (newest first) at `at + p[2+j]` with `copy_within` (prompt, reply, created, completed). The
  per-draft need `plen + rlen + 24 cp + 24 dp` is checked against `p[3+j] - p[2+j]`, and each `lo` is bounded by the
  text length, so the sum cannot overflow. The proof is the verifier's; the caller fact that makes the left move
  safe (`at <= ht[0]`, turns packed newest first and contiguous by `absorb`, need <= source span) is written in the
  doc comment and checked by the caller, which passes `at = -1` (ok=false) when it does not hold.
- `bench/l3/codex/read.pruv`: `replay` moves `held` into `hb`, calls `finish_inplace` with
  `at = 8*(20 + 10*kept + 2*items) + base`, and truncates `hb` to `at + text_len` as the wire. No second text buffer.
- `bench/l3/codex/root.pruv`: `hb` reserves its first 36,864 bytes (`hs[1] = 36864`), past the largest header + base
  (8 x (20 + 2000 + 60) + 20,024 = 36,664), so the held turns always start at or after `at`.
- `bench/l3/codex/host/src/lib.rs`, `harness.rs`: the reply is streamed to a locked `BufWriter` (`render_wire_to`,
  `render_read_to` with `serde_json::to_writer`) instead of building the whole JSON string first. `render_wire` /
  `render_read` stay as wrappers. Output bytes are unchanged (test_impl compares every fixture with the TS oracle).
- `bench/l3/codex/measure_r09.py`: `--probe ROUNDS` runs E0 (empty stdin), E1 (one read of an empty thread) and M1
  (one read of the M thread), one process per sample, for hand, the new pairs and the `--base` pairs; every sample's
  stdout must equal hand's. The freshness check now also covers `harness.rs`.

Model use: the in-place design, the `turns` / `read.pruv` / `root.pruv` code, the host streaming and the probe were
written here (Claude Opus 5.5) in a scratch copy and copied into the tree (no write delegation was applied). Builds,
test_impl runs and the measurements ran as command delegations. The audit was Codex gpt-6.2-astra ultra (correctness
review, once).

## Audit (Codex gpt-6.2-astra ultra, once)

It found the in-place move safe on the real `absorb -> replay` path (no unread source overwritten, header region and
text region disjoint, 36,864 >= max `at` 36,664 with 200 bytes spare) and the streamed JSON byte-identical for valid
wires. Two must-fix were raised:

- the probe discarded the stdout of each timed sample, so a failed request could count as an RSS sample: fixed
  (every sample is compared with hand; M1 also checks that hand kept all turns). `--probe` now rejects < 1, and the
  freshness check includes `harness.rs` (both "should fix").
- on a corrupted wire the streamed renderer can write part of the JSON before it panics, where the old one panicked
  with no bytes for that request. Not changed (D-DB44-1).

No recheck: the probe fix is in the measurement script only and was exercised by the probe run below.
