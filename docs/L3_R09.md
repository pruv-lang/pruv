## 4. Gaps

| Id | Gap | Workaround |
|---|---|---|
| G-R09-1 | No little-endian word store/load primitive for `[u8]`. | `put_word`/`get_word` in `packet.pruv` loop 8 times with `% 256` and `/ 256`. |
| G-R09-2 | z3 times out proving a `held_ok(hs, ht, hb)` predicate across the replay allocation, the copy range and the feed precondition. | The runtime re-check at `read.pruv:181` stays. |
| G-R09-3 | The shared receive path requires `len(line) == cap`, and `vec_reserve` exists only on the Rust backend. | The 8 MiB `line` buffer stays a fixed `alloc(8388608, 0)` (`root.pruv:117`). |
| G-R09-4 | An array field cannot be moved out of a record (`col.text`), and the LLVM backend has no `take` for `[T]`. | `finish` copies `col.text` into the wire once instead of handing it over. |
| G-R09-5 | The LLVM backend has no `inout` state records, and root entries cannot take `inout`. | Read state stays as loose `[i64]`/`[u8]` arrays (`hs`, `ht`, `hb`, `pl`, `pb`, `fs`, `fb`) allocated per call in `codex_read_wire`. |

## 5. Debt

| Id | Cells | Cause (line level) | Fix |
|---|---|---|---|
| D-R09-1 | time, M and L, rs/rust and rs/llvm (1.67x to 1.88x) | Each read allocates two fixed buffers: `line` = `alloc(8388608, 0)` (`root.pruv:117`) and `hb` = `alloc(8700000, 0)` (`root.pruv:123`). From the second read in a process on, the allocator hands back the freed region, so the zero fill touches about 17 MB per read. The hand reader grows a `String` to the line size. The rest is the JSON tree walk in `read.pruv`. | Not tried. Making `line` and `hb` sized to the input needs new proofs for `len(line) == cap` (G-R09-3) and `len(hb) == 8700000` in every function that reads them, then a re-verify of all four pairs. That did not fit the time cap. |
| D-R09-2 | RSS, M and L, rs/rust and rs/llvm (10.9x to 12.9x) | The same two buffers. One read alone peaks at 7.3 MB (M) and 16.9 MB (L). From the second read on, the zero-filled reused region is resident, so the peak is about 35 to 39 MB. The hand reader stays at 2.8 to 3.6 MB. | Same fix as D-R09-1, not tried. |

The single-read and second-read RSS numbers come from separate runs. The allocator reuse is inferred from those numbers
and was not traced directly.
