# L3 R06 grok history (A + B + C)

Status: done with debt. B (one framing cursor, no event array) and C (one output copy for the read packet) are in and
pass every grok fixture on all four pairs with `--slow`. A (dense-event and ordinary history vs hand Rust) is a new
harness in `bench/l3/grok/perf/`. Its output check agrees word for word with hand on every row. Every M and L cell is
over hand: time 2.7x on ordinary history and 22-24x on dense tiny lines, RSS 1.18-3.13x. The proportional RSS slope is
1.00-1.03x hand; the rest of the RSS gap is a fixed part. These cells are debt rows D-R06-1..4. This file is for the
main conversation to fold into the spec (it does not edit §7.5).

## 1. What landed

| Piece | Where |
|---|---|
| B: `read::window` walks the window once with `framing::find_lf` from `framing::scan_start` and hands each event (line span or drop marker) straight to `event_step`. `framing::scan` and `put_event` (the event array) are gone. The event rules are unchanged: a line over 1 MiB is a drop marker over its first 8192 bytes, empty lines emit nothing, an unterminated fragment of at most 1 MiB is ignored | `bench/l3/grok/framing.pruv`, `bench/l3/grok/read.pruv` (`window`), commit 744bae8 |
| B: grow-and-retry of the collector buffer is done in `window` (`buf` is a local there), not in a helper that takes `buf` inout (G-R06-1) | `bench/l3/grok/read.pruv` (`window`) |
| C: `packet::result3(meta, rows, a, b, c)` validates and writes the read result packet (header, meta, rows, then the three text parts) into one allocation. `read::assemble` no longer builds the intermediate `packed` text buffer, and `put_str` is gone. `result_ok` delegates to `result_ok_n` (same body, length passed in) | `bench/l3/grok/packet.pruv`, `bench/l3/grok/read.pruv` (`assemble`), commit 3afefcf |
| A: perf harness. Pruv row = `perf_root.pruv::grok_history_window` (wraps `read::window`) compiled with the grok modules. Hand row = `hand_history.rs` (own byte scanner, no serde). Modes `check` (both rows on every file, omitted false and true, packets compared word for word), `time` (median per-call ns, rounds alternating pruv and hand) and `rss` (one call per fresh process, `/usr/bin/time -l` peak, median of 3). Writes `work/perf_cells.json` for `tools/perf_gate.py` | `bench/l3/grok/perf/` |

Rows: `hist-ord-64k` (S), `hist-ord-2m` (M), `hist-ord-8m` (L) are ordinary user/assistant/tool histories with
200-4000 byte texts, tool calls and mixed timestamp keys. `hist-dense-2m` (M) and `hist-dense-8m` (L) are dense tiny
lines: `0` and `{}` with one small user and one assistant object every 400 lines (about 800k events per 2 MiB).

Caveats about the hand baseline (it is a faster but narrower reader than the Pruv port):
- It compares raw key bytes (no escaped keys) and accepts only quoted 24-byte ISO timestamps.
- Nesting is capped at 128.
- The rows have no line over 1 MiB, so drop markers are not timed.

## 3. Debt rows (proposed for §7.5)

| Row | Cells | Line-level cause | Next |
|---|---|---|---|
| D-R06-1 | time dense-2m, dense-8m (24.3x, 22.5x) | Per line, `read::line_step` (`read.pruv:341`) calls `lines::parse_range`. That copies the span into a fresh owned array (`bench/l3/lib/lines.pruv:35` `alloc(n,0)` + copy loop), runs `validate_utf8` and `parse::scan` into a new growing tape, then drops the `JsonDocument`. `sample` on the dense-8m pruv row: about 80% of samples are in `calloc`/`realloc`/`free`/`memset` (and malloc's own clock reads) called from the inlined `event_step` body, including `RawVec::shrink` of the tape. Hand scans the line in place with no allocation. With about 2.5 bytes per line the fixed per-line allocation cost dominates | A borrowed-span parse in `bench/l3/lib` (G-R06-2), or a tape reused across lines. Outside this bundle's edit scope |
| D-R06-2 | time ord-2m, ord-8m (2.66x, 2.74x) | Inferred from the dense profile, not isolated (the ord sample came back empty): the same per-line copy + `validate_utf8` + tape build of D-R06-1, plus the generic field lookups (`json::access::field` shows up in the dense profile) where hand matches raw keys in one pass | Same as D-R06-1 |
| D-R06-3 | RSS ord-2m, ord-8m, dense-2m, dense-8m, fixed part (+5.5 MB ord, +8.3 MB dense) | Inferred, not isolated: the collector buffer grows in 65536-byte steps doubled by `need` and is bounded by 65584 bytes per kept slot (`len(buf) <= 13116800` in `read::window`), and the 1600-word slot table. Hand keeps exact-size turn text | One RSS probe per collector stage (state/slots/buffer) |
| D-R06-4 | RSS ord, proportional part (1.025x slope) | Inferred: the turn text lives twice while `assemble` runs, once as `Collected.text` and once widened to one `i64` per byte in the result packet (`packet::result3`, G-R06-3). Hand's text is also widened, so only the `Collected.text` copy is extra | Move `Collected.text` into the packet writer once a move/take of the record field is available |
| D-R06-5 | S: time and RSS hist-ord-64k (2.61x, 1.151x) | Same causes as D-R06-2 and D-R06-3 | — |

## 4. Gap rows

| Row | Gap | Workaround here |
|---|---|---|
| G-R06-1 | An `inout` array parameter cannot be reassigned as a whole (`inout parameter buf cannot be reassigned as a whole`), so a helper cannot grow the caller's collector buffer | The grow-and-retry is inlined in `read::window`, where `buf` is a local |
| G-R06-2 | No borrowed-span JSON parse: `lines::parse_range` must copy each line into an owned array before `parse::scan`, and every line gets a new tape. `bench/l3/lib/` is outside this bundle's scope | Kept the call; cost is D-R06-1 and D-R06-2 |
| G-R06-3 | Packet text is one `i64` per byte (as G-R00-4) | `result3` widens the bytes while it writes them; no intermediate buffer |
| G-R06-4 | `Collected` cannot hand its `text` array to the packet writer by move, and the step packet path (`p_finish` → `done_wrap` → step packet) copies the result packet once more. The second copy is on the I/O step path, not on the timed `window` path | Not changed in this bundle |
