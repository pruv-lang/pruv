# L3 DB10: entry byte pool, host side (D-DB8-1, D-DB8-2, D-DB8-4, D-DB4-3, D-DB4-4)

Target: entry RSS M and L at or below hand Rust 1.0x, and time at or below DB8 (M 1.046x, L 1.042x).

Result:
- Both targets are met, and every cell is now below hand Rust:
  - time M 0.927x, time L 0.849x
  - RSS M 0.766x, RSS L 0.693x
- The fix is in the host (`bench/l3/entry/host.rs`). No `.pruv` file changed.
- The Pruv-side steps of the brief were not done (byte-pool readers in `entry_api`/`ent_*`, dropping the root `wire_in`/`wire_out`). DB10 measurements showed they are not where the RSS goes. They stay as debt (D-DB10-1).

## Where the RSS went (L, 4000 sessions, before DB10)

| phase | RSS |
|---|---|
| after the JSON parse of the case line | 18.3 MB |
| after `encode_index` | 20.5 MB |
| after the input packet | 22.1 MB |

| process peak | 29.4 MB |

Hand Rust peaks at 20.1 MB for the whole run. Most of that is the `serde_json::Value` tree for the case line.
- The pruv host kept that tree and built the packets next to it.
- macOS malloc does not give the freed small-zone `Value` memory back to the large `Vec`s that come later.
- The Pruv-side pool expansion (`wire_in`) is about 1 MB at L.

## Changes

- `bench/l3/entry/host.rs`
  - Lean split for `bound_session_index` lines (`lean_split`, `encode_index_raw`):
    - A byte scanner (`ws`, `skip_value`, `members`, `elements`) finds the top-level members, the `args` members and the `sessions` element spans. It only finds boundaries.
    - Every span is still parsed by serde: the other top-level values, the other `args` values, and each session one at a time.
    - So the whole case `Value` tree is never live. Only one session `Value` is alive at a time.
    - Any line the scanner does not accept, any other op, and any run that returns an error or panics take the old path again (full parse, `run_case` with `None`). That keeps every error text as before.
  - Pool in `Pkt` is now `enum Pool { Words(&[i64]), Units(Vec<u16>) }` instead of an `i64` per unit.
    - `decode_pool` returns `Vec<u16>`.
    - The wire packet path keeps `Units`. The unit packet path (`parse_pkt_units`) borrows the section (`Words`).
    - `string_units` returns `Cow<[u16]>` and bounds-checks the slot ("string slot outside the pool").
    - On `Words` it range-checks each unit ("pool word is not a UTF-16 unit").
- `bench/l3/req/leaf.rs:1940`: builds `Pool::Words` for the new `Pkt` field (the req host `include!`s `entry/host.rs`).

The Pruv decoder (`ent_wire`) and the slot-bounds logic in Pruv are unchanged, so no audit was run (brief rule).

## Remaining debt

| id | cell | line-level cause (hand vs generated Rust) |
|---|---|---|
| D-DB10-1 | RSS M, L (Pruv working set) | `entry_api` and its ~216 reader sites still read one `i64` per UTF-16 unit, so the root `wire_in`/`wire_out` still expand and pack whole packets. That is about 1 MB at L. It is no longer above hand, so it was left for a later pass. Carries D-DB8-1. |
| D-DB10-2 | host pool | The host pool is compact `u16` but still decoded eagerly per packet (`decode_pool`), not per slot. Cost is 2 bytes per unit instead of 8. |
| D-DB10-3 | lean split | serde's recursion limit (128) counts from each span on the lean path, not from the line. A session nested 126-128 deep is accepted on the lean path but rejected by the full parse. The fixtures go nowhere near that depth. The fix is a depth check in `skip_value`. |
| D-DB10-4 | lean split | A lean run that fails is run a second time on the full path to get the old error text. If the error is a panic, the panic message is printed to stderr twice. Results are unchanged. |
| D-DB10-5 | time M, L | Measured at load 6-9 (7 rounds). A quiet-host run (load < 4) is still owed (carries D-DB4-4). |
| D-DB10-6 | wire canonicity | Not done. Whole zero words after the data (the `pad_to` exact-limit padding) are still accepted. Moving the padding changes the `exact_limit` packet expectation, and that is outside this lane. Carries D-DB8-4. |
