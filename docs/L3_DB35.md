# L3 DB35: turns span contracts as strong as the str forms (G-DB32-4, proof half)

Brief: state `clip_span` like `clip_bytes` and `write_span` like `write_piece` in `bench/l3/pkgs/turns/turns.pruv`,
prove them, and remove any caller runtime check the stronger ensures make provable (docs/L3_RESTRUCTURE_SPEC.md 7.5).
The UTF-8 precondition on `begin3` / `answer3` stays open (G-DB32-1). No compiler edits. Base: main 00b479bb.

## What landed

- `clip_span` (`turns.pruv`) now ensures, besides `0 <= result <= min(n, max)`:
  - `n <= max ==> result == n` (no cut when the span fits);
  - the char-boundary fact: `result == 0 || result == n` or `src[lo + result]` is not a continuation byte (not in
    128..191), the `[u8]` form of `is_char_boundary`;
  - the longest-prefix fact: unless `result == n`, every `t` in `result + 1 ..= max` is below `n` and
    `src[lo + t]` is a continuation byte, so no longer cut at most `max` ends on a boundary.
  On a valid UTF-8 span this is the cut `clip_bytes` (`pkgs/text/text.pruv`) makes. The loop carries the two matching
  invariants.
- `write_span` now ensures, besides the length of `dst`: the `sep` LF bytes at `dst[at ..]`, the copied bytes
  `dst[at + sep + k] == src[lo + k]` for `k < n`, the pad bytes F0 90 80 80 when `pad == 4`, and that every byte
  outside `[at, at + sep + n + pad)` equals `old(dst)`. This is what `write_piece` states for its `str` form.
- Both compilers verify the codex root with these contracts; no `turns` clause timed out
  there. The opencode root timeout on `@bytes::copy_span` (G-DB35-1) came from the base py verifier, not from these clauses.
- Removed check: `answer3` dropped `if piece > 32768 { return; }` (added in DB32) before `reserve`. `reserve` requires
  `need <= 32768`; on each of the four branches of `answer3` `piece <= room <= 32768` (all fits: the branch condition;
  separator does not fit: `piece = room`; body cut: `take <= room - sep` from `clip_span`; only the pad dropped:
  `sep + n <= room`). Honest note: this follows already from the old `result <= max` ensures; the check was
  redundant before DB35 as well, and the new facts are not needed for it. No path reaches it, so outputs are unchanged.
- Kept checks: codex `replay` keeps `span_ok` (`utf8_valid` per span, needs G-DB32-1); the `ht` bounds check and the
  `finish_into` ok check in `read.pruv` do not follow from the new `turns` ensures (they are about the host text and
  the wire layout). grok, opencode and qwen call no span form. No caller check other than the one above went away.
