# L3 DB55: line and tape copies in bench/l3/pkgs (G-DB54-1, G-DB54-3)

Brief: (1) G-DB54-1, move the no-copy line parse from codex into `pkgs/lines` and switch the line readers that parse a
whole owned line from position 0. (2) G-DB54-3, size the first tape in `pkgs/parse` from the input length, bounded by
the proved tape cap. Base: main 226faa93. One release `pruvc-rs` build from this base; no compiler or runtime change.

## What landed

- `pkgs/lines/lines.pruv`: new `pub fn parse_owned(take data: [u8], hi: i64) -> JsonParse ! alloc`, the body of
  `parse_range(data, 0, hi)` without the copy loop (the codex DB54 `parse_owned`, now in the package): same
  `requires 0 <= hi && hi <= len(data)`, same limit check, `validate_utf8`, `scan(subview(owned, 0, hi))`,
  `check_tape`, same `Failed` positions and kinds, same `doc_local` ensures. The document's source is
  `truncate(owned, hi)` and the tape is moved in. `parse_range` keeps its signature; its success path now moves the
  scanned tape into the document instead of `copy(tape)`.
- `pkgs/parse/parse.pruv`: new `first_slots(n)` = `n / 16` clamped to `[192, 4096]`, proved `192 <= result <= 4096`
  for `0 <= n <= 16777216` (the 4096 cap is the audit fix in d482027b); `scan` and `scan_document` start the tape at `first_slots(len(input))` instead of 192 slots.
  `widened` is unchanged, so denser input still grows the tape the same way and never needs more doublings than before.
  `scan_into` is unchanged.
- codex: `rpc.pruv` drops its local `parse_owned` and calls `lines::parse_owned`; `root.pruv` / `pruv.json` drop the
  `lex` and `parse` modules that only the local copy needed.
- grok `rpc.pruv` `parse_line` and mcp `root.pruv` (the line reader) hand their trimmed line buffer to
  `lines::parse_owned`. The length is bound first (`let tn = len(trimmed)`), because passing `len(trimmed)` in the same
  call as `move trimmed` is a `foreign_borrow` type error.
- Not switched: qwen entry, json `a5_root` / `q_root`, grok `read` parse borrowed ranges (the caller keeps the buffer),
  so they stay on `parse_range` / `parse_span`; claude framing only uses `jsonl_next` and its entry already moves its
  own tape; `mcp/perf` is a perf harness, not a line reader.

## Decisions

| id | decision | why | status |
|---|---|---|---|
| D-DB55-1 | first tape is `len / 16` slots clamped to `[192, 4096]` | codex L lines (25,347 B, 1,194 slots) and M lines (50,640 B, 2,334 slots) start at 1,584 and 3,165 slots and never widen; an empty or small input keeps the old 192 | kept |
| D-DB55-4 | cap the first tape at 4096 slots (32 KiB) | audit: without a cap a sparse line (one 1 MiB string) asked for 65,536 slots (512 KB) of tape it never fills; 4096 covers every line up to 64 KiB, longer dense lines widen as before | kept |
| D-DB55-2 | `parse_range` and `parse_owned` move the scanned tape into the document | the tape is a fresh local at that point; the copy only doubled the tape bytes | kept |
| D-DB55-3 | only callers that own a whole trimmed line from 0 switch (codex, grok rpc, mcp) | the moved buffer must hold exactly the line; borrowed-range readers keep `parse_range` | kept |
