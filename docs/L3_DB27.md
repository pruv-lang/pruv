# L3 DB27: entry RSS and time at or below base / hand, req refused-branch reserve, m8 cases committed

Base: main b7ed8ff4. Lane: bench/l3/entry/, bench/l3/req/, bench/l3/budget/m8_test/.

## What DB27 does

1. D-DB22-1 (entry RSS). Bisect per change on quiet windows (load 4-6). Measured peak heap with a counting
   allocator: head and the new build both peak at M 1,595,564 B / L 6,468,596 B. The peak sits in Pruv
   `ent_packet::mk_packet` (`ent_u16::zeros`) called from `ent_bound::index_complete`, the same in base and new.
   So there is no heap cause; the DB22 offset of 80-100 KB is page / layout noise of macOS maxrss (it moves by tens of KB
   with identical heap). A host change that did raise RSS was found and dropped: an ASCII fast path in
   `Pool::string_units` (faster, but +200 KB L RSS, from the bisect `su` vs `pt`). With the kept changes RSS is at or below
   base (table below).
2. D-DB22-2 (entry time). Host input split and output copy cut, no Pruv judgment moved:
   - `lean_split` scans the top object once; `args_at` scans `args` once and `elements_at` takes the `sessions`
     elements as raw slices. The serde `Value` tree for `sessions` is no longer built and walked twice
     (`members` / `elements` removed). Other members are still checked with `serde_json` (same accept / refuse set,
     last duplicate wins, a replaced duplicate is only skipped).
   - `pair_table` writes the two strings of a pair in place with `render_at` instead of building a `Value` per pair.
   - Allocations per request: M 37,137 to 31,131, L 148,147 to 124,141.
3. D-DB22-3. `req_list.pruv` `pack_bound`: when the slot length sum is saturated (`tot >= 1073741823`), `pack` refuses
   with an empty result, so that branch now reserves 0 instead of the clamped saturated size. Output bytes are the same.
4. D-DB22-4. `bench/l3/budget/m8_test/cases_q2.jsonl` (q_gen `--families Q2 --count 300`, seed 20261117) and
   `oracle_q2.jsonl` (`oracle.py`, checked deterministic) are committed; `run_m8.py` uses them by default, so
   `python3 run_m8.py q` runs without setup.

All accepted outputs are byte-identical: entry outputs for the M, L, L300, L1k request files are identical to the base
build, and the test list below is green.

No wire or boundary check changed (the host still rejects the same inputs; `pack_bound` changes only a reservation), so
no audit was run (brief: pure perf cuts need none).

per-round pruv / hand ratios. A first 7-round set (load 3.1 to 7.0) was too noisy for RSS (base L came out at 0.460 against
0.426-0.433 in every other window), so a 15-round set in the same window was used (load 8.4 to 8.3).

## Debt and gaps

| id | debt | next |
|---|---|---|
| D-DB27-1 | macOS maxrss for entry moves by tens of KB with an identical heap peak (layout / page noise), and one 7-round window gave base L 0.460. RSS at the 1-2 page level is judged only by 15 rounds with the base in the same window. | Gate RSS on measured peak heap plus a 15-round maxrss set. |
| D-DB27-2 | The entry heap peak is the Pruv packet build (`ent_packet::mk_packet` zeros, from `index_complete`), not the host. Lowering RSS further needs a smaller or reused packet buffer in `ent_packet` / `ent_bound`. | Reuse the input packet words or build the done packet in place. |
| D-DB27-3 | Time M 0.995 has a thin margin. Top costs (L x1000 profile): `index_complete`, malloc / free, host `skip_value`, render, serde check of non-session members. An ASCII fast path in `Pool::string_units` cuts time but adds about 200 KB L RSS and was not kept. | Cut `index_complete` n-sized arrays; ASCII fast path only with a measured RSS-neutral form. |

No language gaps were met (G-DB27: none).
