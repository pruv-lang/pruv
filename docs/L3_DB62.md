# L3 DB62: load-independent grok ACP fixtures, rpc-lines perf row with hand Rust (G-DB47-4, G-LG33-7, G-DB56-6, G-DB56-7)

Brief: (1) make the grok `acp-` timing fixtures independent of machine load, with the TS reference, the fake ACP and
the Pruv runner agreeing on the same expected block, shown under a parallel CPU load. (2) G-DB56-7, add an rpc-lines
perf row (M and L) that reaches `rpc::parse_line` and the jstr decodes, with a hand Rust counterpart. (3) Measure the
new row and hist-ord / hist-dense M/L on all four pairs against hand. Base: main 4ccd03a0. One release `pruvc-rs`
build; no compiler, runtime or `pkgs/` change.

## What landed

- Fixtures (`fixtures/acp.json`, `fixtures/verify.json`): the deadline under test no longer races process start-up.
  Both the TS reference (`withRpcChild`, one `setTimeout(options.timeoutMs)` armed at spawn) and the Pruv runner
  (`rpc::start`) run one overall timer from spawn, so `rpcMs` also covers the fake ACP start-up (`sh` wrapper, `exec
  python -B q_server.py`, imports). The product timer is unchanged (D-DB62-1); the fixtures whose expected block needs
  `initialize` to answer before the deadline get `rpcMs` 15000 instead of 3000:
  `acp-timeout-initialize`, `acp-partial-line-then-stall`, `acp-error-not-object-does-not-reject`,
  `acp-timeout-session-load`, `acp-p1-invalid-utf8-line`, `acp-p1-depth-129-response`,
  `acp-p6-premature-id2-same-write`, `acp-p6-float-id-token`, `acp-p6-exponent-id-token`,
  `acp-p11-stdin-closed-then-late-result`, `acp-p12-padding-then-premature-id2`, the three `acp-p7-*` fixtures and
  `verify-timeout-removes-target` (every 3000 in the fixtures is gone). The two always-at-`initialize` fixtures were
  first kept at 3000, but under load the deadline fired before the fake ACP had written its first log line or read the
  request (`acp-partial-line-then-stall` also before its 100 partial bytes), so the oracle saw the fake started on the
  TS side only (rs/llvm, load run 2 of the first series); they need the same start-up headroom (D-DB62-2). The
  stalls never answer, so 15 s still ends in the same `initialize` timeout. The `acp-p7-*` fake-server waits scale so
  the child still outlives the deadline: watchdog 45 -> 90 s; the `eof_no_exit` / `inherit_pipe` wait 4 -> 20 s; the
  SIGTERM-ignoring child's lifetime cap 12 -> 30 s (it may still exit earlier on stdin EOF); the fake's own 120 s
  emergency alarm is unchanged. No reference, fake-ACP or Pruv source changed. The expected blocks are read by the
  harness: by default it compares the TS result with `expected` and the oracle compares the Pruv result and the
  fake-ACP transcript with the TS run; with `--no-ts` the Pruv result is compared with `expected` directly.
- Perf (`perf/`): `perf_root.pruv` gains `pub fn grok_rpc_lines(win: [u8]) -> [i64] ! alloc` (`ensures len(result) ==
  15`): it splits the window on LF and runs each line through `rpc::parse_line` (trim to bounds, one copy, `lines::parse_owned`),
  then the pump's per-class work: kind 0 reads `method` and `params.update.content.text` with `util::str_at` (owned
  jstr decodes), kind 1 the `not_handled` bytes, kind 2 `error_detail` through `jstr::owned_text` and the raw
  `error.code` with `util::json_value`; 15 counters and modular folds are returned. `hand_rpc.rs` is the safe Rust
  baseline: one validating recursive-descent scan per trimmed line, no tape, no line copy, strings decoded into one
  reused buffer only when they hold escapes. `perf_driver.rs` dispatches on the `rpc-` basename; `run_perf.py` adds
  module `rpc`, packages `tail` and `transport`, rows `rpc-lines-64k` (S), `rpc-lines-2m` (M), `rpc-lines-8m` (L)
  (`gen_rpc`, seeded) and cells `grok rpc <row> time/rss`, and now compares the fold of every rss sample with the
  timed checksums as well (before, only `time` samples were compared); README documents the row and the scope limits.

## Perf

the final sources), 10 rounds, the side order rotated and reversed each round; per round and row every side runs
`time` (400 ms budget, median ns per call) and one `/usr/bin/time -l ... rss` peak sample, and every sample's checksum is
compared with the hand checksum of the same build (no mismatch). Fixed RSS is the median peak over an empty window;
proportional RSS is peak minus fixed. Alloc bytes / blocks come from a malloc / calloc / realloc / posix_memalign
interposer (deterministic, run twice per cell), empty-window counts subtracted; both sides count the input window

time-only cells near 1.0x (hist-ord) need an idle recheck before they are read as a cost. Cells:

## Decisions

| id | decision | why | status |
|---|---|---|---|
| D-DB62-1 | keep the single spawn-armed deadline in the product (TS `withRpcChild`, Pruv `rpc::start`) and fix the fixtures instead | the TS reference is the behaviour spec; arming the timer after `initialize` would change the product contract for every caller, while the fixtures only need start-up to fit the bound | kept |
| D-DB62-2 | every ACP-spawning fixture with a deadline gets `rpcMs` 15000, including the two always-at-`initialize` timeout fixtures | under load the fake ACP start-up took over 3 s: past-`initialize` fixtures turned into `initialize` timeouts, and the two `initialize` fixtures timed out before the fake had logged or read anything, so the transcripts differed between TS and Pruv; their stalls never answer, so 15 s keeps the same stage | kept |
| D-DB62-3 | `acp-p7-*` fake-server timers scale with the deadline (watchdog 90 s, child 20 s / 30 s) | those fixtures test the child outliving the deadline and being reaped; the relation child > deadline > 0 must hold after the bump | kept |
| D-DB62-4 | the hand rpc baseline scans each line once in place and decodes only the needed strings; it is not a port of the Pruv tape | hand Rust is the 1.0x floor: it is what a Rust author would write for the same counters, so the cells show the full cost of the tape and the copies | kept |
