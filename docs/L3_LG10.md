# L3 LG10: typed errors `Result<T, E>` (E1)

Scope: step E1 of the error-handling key point in `docs/LANG_ROADMAP.md`. Both compilers (Python `pruvc/`, Rust
`pruvc-rs/`) change with the same semantics and diagnostics. Front end, proof and Rust backend landed; the LLVM
backend rejects the new types (G-LG10-2). No `bench/` fragment is changed.

## What landed

- Syntax and canonical form (E1.F, SPEC.md §6c "Typed errors"). `Result<T, E>` takes a second type argument.
  `Result<T>` still means `Result<T, i64>`, and the single normalization point (`mk_result` / `GType::result`,
  `substitute`, `lower`) drops E when it is `i64`, so `Result<T, i64>` is exactly the old `Result<T>`: dumps, mangled
  names, Z3 names, Rust and LLVM output of every existing program are byte-identical. Arity other than 1 or 2 keeps
  `type/type_arity`.
- Allowed error types. E1 accepts `i64`, `bool` and value structs or enums (generic applications included) with no
  buffer, collection or owned field anywhere. Anything else (`String`, `str`, arrays, `Vec`/`HashMap`, records holding
  them, `Option`/`Result`, a type parameter, `u8`, unit) is rejected at the type position with the new code
  `type/result_error_type`. Owned `String` errors (E2) and error records with buffers (E3) are later steps.
- Constructors and match. `Ok::<T, E>(v)` / `Err::<T, E>(e)` type `e` against E; unannotated and one-argument forms
  stay E = `i64` (no inference of E). The `Err(e)` match binder and the contract selector `err_val(r)` have type E.
  `Result<T, A>` and `Result<T, B>` are different types (`type/type_mismatch`).
- Specialization encoding: unchanged `r`+enc(T) for E = `i64`, `e`+enc(T)+enc(E) otherwise (`typeinfo.py`,
  `gtype.rs`). The foreign/host scalar Result case only applies to E = `i64`.
- Proof (E1.P). One Z3 datatype per canonical Result type; the Err field sort is the sort of E, the recursive size
  `weight` adds the weight of E on the Err side as Ok adds the weight of T, and well-formedness checks the Err payload
  with wf(E). The per-term facts give a nominal Err payload of a `Result<T, E>` field the same size >= 1 fact as a
  direct nominal child, so recursion through a struct holding such a Result proves `decreases size(x)`. Match binder values and `err_val` in the Rust proof crate (`model.rs`, `symbolic.rs`) read E.
- Rust output (E1.R). Runtime type `Result<R(T), R(E)>`, contract type `Result<C(T), C(E)>`, conversion
  `map_err(conv(E))`, turbofish constructors with E in runtime, contract and G9 paths; the G9 helpers
  (`nominals_in`, `g9_weight`, `g9_walks`, `g9_eq`) cover E. For E = `i64` the text is unchanged.
- LLVM (E1.L, not landed). A program that uses a Result with E != `i64` anywhere is rejected with
  `codegen/unsupported_type` ("... which the llvm codegen layer does not support yet", fix "use the Rust backend").
  The three runtime samples with such types are listed in `tests/llvm_pending.txt`.

## New gaps

| Id | Gap |
|---|---|
| G-LG10-1 | Pruv has no `?` operator; propagating an error needs an explicit `match` and `return Err::<T, E>(e)`. |
| G-LG10-2 | The LLVM backend does not lay out `Result<T, E>` with E != `i64`; it rejects such programs with `codegen/unsupported_type` (samples in `tests/llvm_pending.txt`). |
| G-LG10-3 | A G9 conversion closure generated for some `Result<T, E>` contracts makes rustc warn `unused_parens` (cosmetic; the program compiles and runs). |
| G-LG10-4 | `type/result_error_type` points at the function or declaration (often 1:1), not at the offending type token; both compilers agree. |

## Tests

New runtime samples `tests/runtime/lg10_e1_{struct_err,enum_err,bool_err,i64_same}` (the first three run on the Rust
backend and are LLVM-pending; `lg10_e1_i64_same` writes `Result<bool, i64>` and checks the old `Err::<bool, i64>(`
spelling on both backends). New must_reject samples `tests/must_reject/lg10_err_{string,buffer_record,option,tparam}`
(`type/result_error_type`), `lg10_err_{mismatch,ctor_payload,binder}` (`type/type_mismatch`),
`lg10_result_arity3` (`type/type_arity`) and `lg10_err_false_ensures` (`verify/ensures`, a false
`err_val(result).code` postcondition). `tests/run_all_rows.txt` gains the 41 rows of these samples and nothing else.
The existing `g3`/`g6`/`kd` Result tests are unchanged.
