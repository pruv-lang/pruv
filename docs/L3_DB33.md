# L3 DB33: tape facts proved in the scanner, the `check_tape` rescan after `scan_document` (G-DB30-1, R03C-D32, D32)

Brief: prove the tape facts inside `scan` / `scan_document` and delete the `json::check_tape` rescan after the scan
(24% of L parse time); delete the per-member tape checks in `access::field` that the new ensures make redundant; any
fact that does not prove stays a runtime check with a gap row. Byte-identical output, no compiler edits, lane
`bench/l3/pkgs/{parse,json,access}/`. Base: 8fa9dce4.

## What landed

- `scan_document` (`pkgs/parse/parse.pruv:363`) now ensures, for a `Parsed` result, the record-local facts that
  `check_tape` pass 1 checked at runtime (`pkgs/json/json.pruv:182-188`): tape shape and length bound, input length,
  kinds 0..7, spans `0 <= s < e <= n`, skips `t < skip <= records`, scalar skip `t + 1` with count 0 (or 1 for
  strings and keys, which `scan_document` never writes; the ensures states 0), root parent -1 with skip = all
  records and kind not key, plus `len(source) == len(input)`. Of the parent fact (`json.pruv:189`) it proves the
  first half: the parent is an earlier container (kind 5 or 6) that starts before the child.
- Helper ensures that make the loop invariants prove: `string_token`, `token_at`, `comma_state`, `initial_state`,
  `value_state`, `value_increment` state their exact results; `write_record` requires the count slot it may write
  (0, 1 for kinds 4 and 7, negative for containers).
- `publication_ok` (`parse.pruv:485`) requires these facts and calls `json::check_subtrees` instead of
  `json::check_tape`. `check_subtrees` (`json.pruv:240`, new) has the proved facts as `requires`, checks the second
  half of the parent fact (child inside the parent's skip and end) in one loop, runs `check_tape`'s pass 2 verbatim
  (`scan_ok` per record) and has the same 13 ensures as `check_tape`, so `publication_ok`'s and `parse`'s ensures are
  unchanged. `check_tape` stays for its other users (`lib/lines.pruv`, `lib/parse.pruv`, `claude/entry.pruv`), which
  are outside this lane.
- `access::field` / `find` / `find_ascii` are unchanged (G-DB33-3).
- Source review (Codex gpt-6.2-astra, one pass): no pass-1 fact lost, `publication_ok` and `parse` ensures hold and
  are unchanged, the published tape is byte-identical, no other in-lane caller affected; no must-fix.

| id | decision |
|---|---|
| D-DB33-1 | An open container carries `-(depth + 1)` in its count slot (`parse.pruv:451`) from `write_record` until `close_record` overwrites it with the count. The marker ties each open record to its stack frame, so the invariant can say which records may still grow; every published tape has all containers closed, so the output is byte-identical (all fixture and equality suites below). |
| D-DB33-2 | `check_tape` pass 1 (record-local facts) is no longer run after `scan_document`; the facts are scanner ensures. Pass 2 and the containment half of the parent fact stay runtime checks in the new `json::check_subtrees`. `check_tape` itself is unchanged for its out-of-lane users. |

## Gaps

| id | gap |
|---|---|
| G-DB33-1 | Pass 2 facts (subtree containment `json.pruv:190`, array children not keys `:191`, object key parity `:192`, array and object counts `:193-194`) did not prove as `scan_document` loop invariants: the aggregate `count(k in t+1..skip: parent == t)` over a tape that the loop keeps writing, and the frame invariants that tie the open frame's running count and key parity to those counts, gave z3 `timeout` (preservation of the count invariants at the then lines 404-411 failed or timed out in a 421 s run). They stay runtime checks in `check_subtrees` (`scan_ok`). Closing it needs a count lemma the solver can reuse across a single-slot array update (a frame lemma for `count` over an unchanged range) or a ghost per-container counter the language can relate to `count`. |
| G-DB33-2 | The containment half of the parent fact (`t < skip(parent)`, `skip(t) <= skip(parent)`, `end(t) <= end(parent)` for a closed parent) timed out (z3 `timeout`, `scan_document` loop invariant preservation, then `parse.pruv:397`) when stated over closed parents only; open parents' skip and end are written later by `close_record`. It is checked at runtime in the first loop of `check_subtrees` (`json.pruv:264`). Closing it needs the same frame lemma as G-DB33-1 for the slots `close_record` writes. |
| G-DB33-3 | `access::field` / `find` / `find_ascii` (`pkgs/access/access.pruv:53,81,112`) take any `JsonDocument`; a `JsonDocument` carries no type invariant and `field` has no `requires` on the tape, so the new `scan_document` ensures do not reach it and its per-member checks (key kind, parent, skip, value bounds) cannot be dropped without making `field` unsound for documents built elsewhere. Adding a `requires` would change every caller (outside this lane). Closing it needs a type invariant on `JsonDocument` (or a refinement the parser's result can carry). |
| G-DB33-4 | `bench/l3/json/run_q_mutants.py` parse entries (`trailing_comma`, `wrong_colon_kind`, `record_bound`, lines 89-90, 93) no longer match `pkgs/parse/parse.pruv` exactly once (0, 0 and 3 matches on base 8fa9dce4 too), so the mutant run raises there; the script is outside this lane. Closing it needs the replacement texts updated to the current scanner. |
