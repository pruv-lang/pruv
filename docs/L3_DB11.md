# L3 DB11: content-sized turn store (D-DB5-3, D-DB5-4, D-DB7-4, G-DB5-3)

Scope: bench/l3/pkgs/turns (additive), bench/l3/codex and bench/l3/grok. The old fixed-slot functions stay for opencode.

## What changed

- `bench/l3/pkgs/turns/turns.pruv`: new `Store { data: [u8], off: [i64], stamp: [u8], end: i64 }` with `new_store`,
  `reserve`, `begin2`, `answer2` and `finish2`. The slot state `st`/`sl` and the slot rules (200 slots, 2 MiB publish
  limit) are the same as the old functions; only where the text bytes live changes.
  - `data` holds each draft's prompt then reply contiguously, in ordinal order. It starts empty; the first write
    allocates max(65536, 2 * needed) bytes.
  - When a write does not fit, `reserve` keeps only the drafts `finish` can still publish (newest first, up to the
    2 MiB total) and drops the rest. It packs them to the front in place when that leaves half the buffer free,
    else into a new buffer of twice the bytes needed. So `data` stays within twice the live text and each byte is
    copied O(1) times on average.
  - `off` (200 i64) and `stamp` (9600 bytes) are fixed and small.
- `bench/l3/codex/read.pruv`: `feed`/`replay` use the store. The jump to `alloc(13116800)` in grow is gone.
- `bench/l3/grok/entry.pruv`, `bench/l3/grok/read.pruv`: same change. The grow-and-retry path (`feed_user` returning
  1) is gone.
- `bench/l3/codex/measure_r09.py`: `--rounds N` (default 7).

The data layout keeps Pruv basic concept 4: text is bytes and records are structs, not flat `[i64]` records.

## Tests

All runs were under load 12 to 39 (other sessions plus these tests).

- codex `test_impl.py`: ts/oracle, py/rust, rs/rust 136/136; py/llvm and rs/llvm 135/136 with `read_server_requests`
  ("request log differs from TS"). Two reruns of that fixture with the same build: one passed on all 4 pairs, one
  failed on py/llvm only. It is a timing flake in the request log, not the store. `q.py` rc 0 with the same counts on
  every pair; `q_mutants.py` all killed.
- grok `test_impl.py`: 254/254 on py/rust, py/llvm, rs/rust; rs/llvm 251/254 (3 `acp-p7-*`), plus 2 reference
  fixture problems where the TS reference timed out at `initialize`. `q.py`: 23 unexplained, all ACP process timing
  (fake ACP started on one side only, or the reference timed out), none in turn content. `q_mutants.py`: the run was
  still going at the commit; every mutant seen so far was killed.
- opencode `test_impl.py` (old turns functions, unchanged): the full run failed 18 `F08-*` child-process timing
  fixtures under load; `--only F08 --jobs 1` passed 18/18 on 3 pairs and 17/18 on rs/rust, and the one failing fixture
  passed on rerun. `q.py`: no unexplained differences.

The ACP and F08 timing failures are the same class DB7 recorded under load. They were not rerun at low load in the
time cap (G-DB11-1).

## Debt and gaps

| Id | Cell | Cause | Fix |
|---|---|---|---|
| D-DB11-1 | store record offsets | `begin2`/`answer2`/`finish2` check each record's offset and length against `end` at run time and return unchanged when a check fails. The old functions proved slot contents; the new ones drop those content ensures. | Prove `off[k]` + sizes from `sl` stay within `end` as a store invariant, then remove the checks. |
| D-DB11-2 | codex M/L time and RSS, grok fixed RSS | After numbers were not measured inside the cap (load 12 to 39). Inferred: RSS should drop by most of the 13 MB fixed slot buffer, since data now grows from empty to about twice the live text. | Run `measure_r09.py` and `grok/perf/run_perf.py all --rounds 7` at load below 16 and record the cells. |
| G-DB11-1 | ACP and F08 timing fixtures | Under load the TS reference or the fake child times out on one side. This is a harness timing gap, not a language gap. | Rerun the timing fixtures at low load; give the harness a load-aware deadline. |
