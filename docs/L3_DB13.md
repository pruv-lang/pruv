# L3 DB13: entry/req slot coordinate on the byte pool (D-DB12-1, D-DB12-2)

Brief: move the string slot coordinate from UTF-16 units to bytes of the WTF-8 pool, in both hosts and the Pruv side
together, drop the whole-packet `wire_in` / `wire_out` expansion and packing, keep every observable output
byte-identical. Cells at or below DB12 (time M 0.931x, L 0.850x; RSS M 0.722x, L 0.646x), req no worse.

Result: design only. The new coordinate, the mapping of every consumer with cost bounds and a site inventory are below.
No code changed: the smallest unit that can land is entry, req and both hosts together (see "Why the move did not land
in DB13"), and D-DB12-2 depends on it. Debt D-DB13-1..3.

## New coordinate

### Pool

Section 0 keeps the DB8 wire form inside Pruv too, so there is no expanded copy:

`[nu, nb, W_1 .. W_m]`

- `nb` is the number of WTF-8 bytes, `m = ceil(nb / 7)`, `W_{i+1} = sum_{j=0..6} B[7i+j] * 256^(6-j)`, missing bytes 0.
- `nu` is the number of UTF-16 units of the pool read as one WTF-8 stream. It stays so that every size the old code
  measured in expanded words can still be computed in O(1) (see "Op 9 state numbers").
- With `nb` in the header the word count is exact: `l0 == 2 + ceil(nb / 7)`. Whole zero words after the data are no
  longer a valid encoding (D-DB12-2). The host's exact-limit probe then pads with unreferenced pool bytes (see
  "D-DB12-2" below).

### Slot

`[6, byte_off, byte_len]` into B.

- Each string is encoded on its own: a string's last high surrogate and the next string's first low surrogate are
  never joined into one 4-byte form. So no two slots share a byte, and a slot's byte range is exactly that string's
  WTF-8.
- Canonical pool: a lone high surrogate (3-byte form) directly followed by a lone low surrogate (3-byte form) is still
  rejected, because inside one string that pair must be the 4-byte form, and two encodings of one string would break
  byte equality. When a writer appends a string that starts with a lone low surrogate right after a pool that ends
  with a lone high surrogate, it first appends one unreferenced `0x00` byte. Unreferenced bytes are allowed (they were
  allowed as unreferenced units before DB8).
- Slot check (in Pruv, O(1) per slot, same error path as the old range check): `0 <= byte_off`,
  `byte_off + byte_len <= nb`, the byte at `byte_off` (if any) and the byte at `byte_off + byte_len` (if `< nb`) are
  not continuation bytes. With the strict pool decode, every slot is then a sequence of whole WTF-8 forms.

## How each consumer maps

| consumer | old (units) | new (bytes) | cost bound |
|---|---|---|---|
| entry host `Enc` / `mk_packet*` | WTF-8 of the joined unit stream, slot in units | WTF-8 per string, slot in bytes, separator byte rule above, header `[nu, nb]` | linear in total bytes |
| entry host `parse_pkt` / `string_units` | decode pool to `u16`, slice by unit slot | strict decode of the slot's bytes only (lazy per slot, closes D-DB10-2) | linear in the slot |
| req host `leaf.rs` | unit packets (`mk_packet_units`, `parse_pkt_units`) | the same byte packets as entry (one format) | linear in total bytes |
| `wire_in` (root) | expand to one word per unit (copy) | validate in place, pass the same array on (no copy); a rejected pool still becomes the poisoned packet | linear in pool bytes |
| `wire_out` (root) | pack units (copy) | identity | O(1) |
| readers (string equality) | unit loop | byte loop on the two ranges (WTF-8 is canonical, so equal units iff equal bytes) | linear in the shorter slot |
| readers (literal compare) | unit vs ASCII | byte vs ASCII (ASCII is 1 byte per unit) | linear in the literal |
| writers (append string) | append units | append bytes, `nu += units`, `nb += bytes`, separator rule | linear in the string |
| length in units (`.length` semantics) | slot length | scan the slot, 1 unit for 1-3 byte forms, 2 for 4-byte forms | linear in the slot |
| truncation at 200 units (`ent_dispatch`) / 80 units (`req_fill`) | `slice(0, N)` of units | scan bytes counting units; stop at the last whole form with `units <= N`. If the next form is 4 bytes and `units == N - 1`, the result is that prefix plus the 3-byte WTF-8 form of the high surrogate (`0xED, 0xA0 + (hi - 0xD800) / 64 ...`), appended as a new string; otherwise the result is the sub-slot `[6, off, cut_bytes]` (no copy). A cut after a lone high surrogate (its 3-byte form) is a plain boundary. | linear in the cut |
| `req_list` order (sort, binary search) | compare UTF-16 units | compare bytes; at the first differing form, if one side is a 4-byte form (code point >= U+10000) and the other is a 3-byte form with code point in U+E000..U+FFFF, the 4-byte side is smaller (UTF-16 lead unit 0xD800..0xDBFF < 0xE000). Lone surrogates (3-byte, U+D800..U+DFFF) vs a 4-byte form: compare the 3-byte code unit with the 4-byte form's lead unit; if equal (lone high == lead), the shorter-so-far side continues with its next unit, so fall back to the unit iterator for that pair. All other pairs: byte order equals UTF-16 order. | linear in the common prefix |
| op 9 state numbers | word addresses in the expanded packet | see below | O(1) each |

### Op 9 state numbers

The await and `progress` keep word addresses of the expanded packet (table start, pool high-water, expanded length)
and the compact/full and `InputTooLarge` choices compare them with limits. These choices are observable, so they must
not move. Rule: every size that was "words of the expanded packet" is now computed as
`len(packet) - l0 + nu` (the packet with section 0 counted as `nu` words, exactly the old expanded length), and every
pool position that was a unit index is now kept as a unit count next to the byte position. The limits are unchanged.
Each is O(1) from the header.

The await equality checks (`entry_api` 184-185, prev against emitted) are part of the ABI too. Today two wire arrays
that differ only in allowed zero padding expand to the same internal packet. With `l0 == 2 + ceil(nb / 7)` the wire
form is canonical, so raw word equality equals the old internal equality and the check can compare the arrays as they
are.

`st+13` (`raw`) is the length after `wire_in` and before `repack`; under the rule above it is `len - l0 + nu` of the
checked input. `st+12` / `st+13` in ordinary replay are physical blob / log word counts and stay physical.

## Why the move did not land in DB13

The coordinate cannot move one module at a time without a conversion boundary, and every boundary is a whole-packet
transform, which is what `wire_in` / `wire_out` are today. Entry cannot move alone either: `req/root.pruv` hands
internal unit packets to `entry_api` at 10 sites with no wire step, so an entry-only move would add two whole-packet
conversions per req call and make req worse. The smallest landing unit is therefore entry Pruv, req Pruv and both
hosts together (table above). That does not fit one 2 h cap with proofs and a green test list, and
a half-moved tree cannot be committed. So nothing in the slot coordinate moved; the code is unchanged and no cell can
have moved.

Staged plan for the next request (each stage keeps the test list green and lands on its own):

1. Write side behind helpers, still in units: one `ent_value` op that appends a string and returns its slot, one that
   copies a slot's range into another pool, one pool merge with slot rebase, and one logical-size accessor
   (`len - l0 + pool units`) used by every limit and op 9 number. Route `ent_*`, `entry_api` and `req/*.pruv` writers
   through them. No observable or cell change.
2. Readers behind `str_units` / `str_len` / `str_eq*` / one `slot_cmp` for `req_list` (already mostly true for entry;
   `req_value`, `req_list::scmp`, `req_child` and `req/root.pruv` still index the pool directly).
3. Flip the coordinate in the helpers, `ent_wire` (validate in place, identity out), `env_check` / `vs_ok`, the hosts'
   `Enc` / `parse_pkt*` / `leaf.rs` readers and `gen_wire.py` in one change; with stages 1-2 this is the helper bodies
   plus the hosts, not the call sites.
4. D-DB12-2 (below) after stage 3.

## D-DB12-2

Not done; it depends on the byte pool inside Pruv. The exact-limit probe (`host.rs` `pad_to`, used at 2191 and 2260)
must make a wire packet of exactly `M = 16,777,216` words that the oracle still accepts. Today it inserts whole zero
words at the end of section 0; `wire_in` drops them, so the internal packet stays under `M`. There is no other place
for slack: `input_check` / `comp_check` end with `all_claimed`, so every section from 2 on must be fully referenced,
and sections 0-1 have exact lengths per op. Padding inside the pool with real unreferenced bytes would be canonical,
but with the unit pool inside Pruv every byte expands to at least half a unit word, so the internal packet would pass
`M` and the probe would turn into `InputTooLarge`. After stage 3 the internal packet is the wire packet, so the probe
can pad with unreferenced `0x00` bytes (`nb` and `nu` grow, `l0 == 2 + ceil(nb / 7)` holds), `wire_in` can reject
trailing zero words by the length check, and the probe's expectation (oracle) stays.
