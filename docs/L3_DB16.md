# L3 DB16: claude window reader against hand Rust (D-DB1-1..6)

Brief: bring the claude window reader (`bench/l3/claude`) to 1.0x hand Rust or below on time and RSS for
D-DB1-1..6, with byte-identical output. Allowed scope: `bench/l3/claude/`, `bench/l3/lib/parse.pruv`,
`bench/l3/lib/json.pruv`.

## Profile split (py/rust, window op, macOS `sample`, LOOPS=200000)

The three inputs show the same shape (ring_wrap, about 3200 samples):

| share | where | note |
|---|---|---|
| ~37% | `entry::parse_line` body (the inlined `lines::parse_range` → `parse::scan` loop) | per-line scan, UTF-8 check, `check_tape` re-walk |
| ~16% | `access::field` (`find_ascii`) | linear member scan per key, last-wins, re-checks tape shape per member |
| ~30% | malloc/free/realloc/memset (`mach_absolute_time` sits inside `xzm_free`) | per-line `owned`, tape (grown from 192 words, copied on growth, shrunk by `truncate`), stack, `copy(tape)`, string decode |
| ~6-8% | `access::string_text` → `utf8_to_string` | one heap string per decoded field |
| ~5% | `access::string_is` | |

Hand Rust (`handrust/src/lib.rs`) spends its time in `Parser::string/object/value`, `BTreeMap` inserts and
`from_utf8`. It parses the borrowed line and keys members in a map once per object.

## What landed

- `bench/l3/claude/entry.pruv` `parse_line` no longer calls `lines::parse_range` (shared lib, outside this lane).
  It inlines the same steps over a borrowed view: `validate_utf8(data, start, end)` reads the input in place,
  `parse::scan(subview(data, start, end))` scans it without a copy (R-6g-5), and only an object line copies its
  bytes once (`alloc` + `copy_range`, moved into the document). Every non-InternalInvariant failure of
  `parse_range` mapped to `Skip`, so the inlined form drops the error-position build; `check_tape` failure maps to
  `Defect(0)` as before (`make_error(0, 18)`).
- Removed per object line: one byte copy loop before the scan, one `copy(owned)`. The tape still needs
  `copy(tape)` (G-DB16-1).

Quick compare (py/rust, window, 5 rounds, load 5.6-9.5, base = branch point 51c4cfde):

## Status of the DB1 rows

Status: DB16: D-DB1-1 open (scan_shortened must write `[]}` over the tail, so a borrowed view cannot replace its copy without a scan entry that takes a suffix; carried as D-DB16-3)
Status: DB16: D-DB1-2 open (ring reuse not attempted within the cap after the parse-side work; ring_wrap 1.63x→1.48x comes from the parse copy cut, not the ring; carried as D-DB16-4)
Status: DB16: D-DB1-3 partial (the per-line pre-scan copy and source copy are gone; the tape copy stays (G-DB16-1) and turns are still built after the parse; carried as D-DB16-1, D-DB16-2)
Status: DB16: D-DB1-4 open (removing `check_tape` needs tape-shape ensures on `parse::scan`, a proof job larger than the cap; carried as D-DB16-2)
Status: DB16: D-DB1-5 open (py/llvm block_arrays RSS not isolated; py/rust block_arrays RSS is 1.02x after the change; carried as D-DB16-5)
Status: DB16: D-DB1-6 open (fixed RSS part: pruv runner 577 KB vs hand 623 KB binary, so the +0.1 MiB small-input gap is heap, not code; ring sizing not attempted; carried as D-DB16-4)

## Gaps

| id | gap | workaround |
|---|---|---|
| G-DB16-1 | An array bound by a `match` arm (`Checked::Tape(tape)`) is borrowed and cannot be moved (`type/array_alias`: "parameter tape is a borrowed array and cannot be moved"), so the document must `copy(tape)` even though the `Checked` value is dead. | `copy(tape)` per object line |
| G-DB16-2 | `subview` cannot be a builtin argument (`copy(subview(...))`), so a view cannot be copied into an owned buffer directly. | `alloc` + `copy_range` from the original array |
