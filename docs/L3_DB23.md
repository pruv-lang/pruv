# L3 DB23: qwen turn store, span parse and arena fields

Base: f30c672a.

DB23 works on D-DB6-2 (qwen linear RSS) and D-DB6-3 (dense, dupbranch and collide time). It changes only
`bench/l3/qwen/`. Every change calls an existing `bench/l3/pkgs/` API: `turns::Store`, `lines::parse_span` and
`access::field` / `string_text`. No pkg or lib file changed. There is no new encoding or wire layout, so no audit ran
(the brief asks for one only when one lands). Accepted output is byte-identical (tests below).

## What DB23 does

- D-DB6-2, the share was measured first. The base runner peaks at 14.6 MB on linear M, while hand peaks at 6.7 MB.
  The fixed-stride `turns` buffer accounts for most of the gap: it grows to 13,116,800 zeroed bytes and is touched as
  text is written. The other copies are small:
  - The runner's `unwire` uses `text.drain(..hl)`, which works in place.
  - `col.text` and the wire each hold at most about 2 MB of selected text.
  - `import.pruv` now uses the content-sized `turns::Store` (`new_store` / `begin2` / `answer2` / `finish2`) in
    place of the fixed buffer.
  - This brings linear RSS down to 0.98x on M and 0.93x on L.
  - One copy is left: `finish2` builds `col.text` and `window_wire` copies it into the wire. Removing it needs a
    `turns` change, which is out of this lane. It costs at most about 2 MB and no cell fails on it.
- D-DB6-3, parse over a borrowed span:
  - The new `entry::parse_line_span` wraps `lines::parse_span` with caller scratch: a tape of 4,096 records and a
    516-slot stack. `chain::scan` and `window_wire` each allocate the scratch once per window.
  - The per-line owned copy from `parse_range` and the tape growth are gone. `build_span` still makes one exact
    source and tape copy, as `check_tape` needs.
  - The result is the same `Line` for every input. A scratch that is too small falls back to `parse_range`.
- G-R05-5 in `chain.pruv`: the new `put_field` decodes `uuid` and `parentUuid` straight into the arena with
  `access::string_text`, so the extra `str` copy from `string_field` plus `put` is gone. It keeps the old outcomes:
  - missing field or not a string: -1;
  - corrupt tape or invariant error: -2;
  - more than 50,331,648 bytes: -2;
  - no arena room: -3.
  A leaf candidate whose parent read gives -2 is still bad, and a zero-length uuid still adds no slot.
- What did not land:
  - Each line is still framed and parsed twice: once in `chain::scan`, then in the `window_wire` title and turn pass
    (D-DB23-1).
  - A view-only first pass, which would skip the document build in `scan`, was looked at and dropped. Keeping the
    same decision needs `json::check_tape`, and `check_tape` needs an exact-length tape. That means the same tape
    copy `build_span` already makes, so the gain would be small.
- D-DB6-1 was not started: items 1 and 2 are not both closed.
