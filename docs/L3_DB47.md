# L3 DB47: grok ord decode in the scan

Lane: bench/l3/grok/ (`line.pruv`, `read.pruv`). No change in bench/l3/pkgs/, the compiler, stdlib or SPEC.
Baseline: main 688192a3 (DB45: ord M/L 1.59x/1.57x hand, dense M/L 0.72x/0.71x hand).

## 1. Design (G-DB45-1)

DB45 left content decoding as a second pass: after the scan, `step` decoded the recorded content spans into a fresh `String`
per line with one short `string_push_str` per escape. DB47 changes the decode path as follows.

| Change | What | Why |
|---|---|---|
| Decode in the scan | `dstr(b, p, d, k)` finds the end of a content text string and decodes it in the same pass, appending to the valid prefix `d[0..k)` of a reader-owned `[u8]` buffer. Escape-free runs (between `"`, `\` and control bytes, found by `stop`) are appended with `copy_range` (SPEC R-5-1, lowers to `copy_from_slice`); simple escapes append a literal through `put` (the lg26 copy invariant). The decoded length goes to `f[34]`; `step` passes `subview(d, 0, f[34])` as the text. | one pass over the content, one memcpy per run, no per-line allocation |
| Reused buffer | `read::window` owns `dbuf: [u8]` (starts empty) and threads it through `line_step`/`event_step` to `line::step`; `step` grows it with `resize` to `len(line) + 256` only when it is shorter. | hand keeps one `Vec` across lines; no `string_clear`/`string_with_capacity` builtin is needed because the buffer is `[u8]` and the text is a `str` subview of its valid prefix |
| UTF-8 proof | `utf8_valid_span(d, 0, o)` is a loop invariant of `dstr`. A run copied from `b[q..e)` keeps the prefix valid because `b` is checked valid, `b[e]` is ASCII and the run start is checked once at run time not to be a continuation byte (run starts follow a quote or an escape letter). A negative check (dropping the continuation-byte test) makes verification fail at the `dstr` postcondition, so the proof is not vacuous. | no unchecked cast from bytes to `str` |
| Lazy UTF-8 check | `scan` checks `utf8_valid(b)` (one `from_utf8`) only before it first decodes content or enters an array, and records `f[35] = 1`; `step` checks it after the skip decision when the scan did not. A skipped line (user line with `skip`, non-user/assistant type) no longer pays the check. Invalid UTF-8 on a line that is not skipped still returns 3 (tape path), as before. | dense lines are mostly skips |
| First-byte fast path | Kept in front of the scan: a first non-whitespace byte that is ASCII and not `{` returns 0, a non-ASCII one returns 3 (tape path decides). | the v3 probe without it regressed dense to 0.83x |
| `str_end` run loop | String bodies outside content are skipped with `stop` (first `"`, `\` or control byte) and only escapes are examined, instead of a per-byte state loop. | shorter inner loop on every key and string value |
| Lazy tape | `read::window` starts the tape at the 256 words `line::step` uses as its field table; `line_step` grows it to 24576 words (4096 records) only on the first line that takes the tape path. | the full tape was zeroed per window even when no line falls back |

The result of `step` is unchanged by construction: the decoded text is the same bytes the DB45 second pass produced (same escape
set: `\n \t \r \" \\ \/`; `\b`, `\f`, `\u` and unknown escapes return -1 and the line goes to the tape path), and every new early
exit returns 3 (tape path) or a skip the tape path also takes. One intermediate return changes: a non-user/assistant line with
invalid UTF-8 and a `content` string (e.g. `{"type":"other","content":"<0xFF>"}`) now returns 3 instead of 0, because the lazy
check runs before decoding content; the tape parser rejects the line and it is skipped, so the read result is the same. No
behavior difference in the result is known; no D-DB47-n row.

## 2. Time and memory (rs/rust)

10 rounds, alternating old (main 688192a3) / new / hand per round with rotated order, `perf_driver time <impl> <row> 300`,
median of the per-round medians, [min..max] of the per-round medians. Load average 4.35-4.72 (1-minute, sampled per round).
`run_perf.py check` shows `pruv == hand` on every row for old and new.

| Cell | old ns | new ns [range] | hand ns [range] | old/hand | new/hand |
|---|---|---|---|---|---|
| ord M (hist-ord-2m) | 5465708 | 3651552 [3604354..3778750] | 3525479 [3482208..3549250] | 1.55x | 1.04x |
| ord L (hist-ord-8m) | 20231708 | 13302625 [13101250..13474250] | 13269229 [13167500..13403708] | 1.52x | 1.00x |
| dense M (hist-dense-2m) | 2984844 | 2383042 [2365896..2407459] | 4228541 [4086750..4388375] | 0.71x | 0.56x |
| dense L (hist-dense-8m) | 12081000 | 9674458 [9591333..9721709] | 16940218 [15743854..17626583] | 0.71x | 0.57x |

Ord M: the new and hand ranges do not overlap (new min 3604354 > hand max 3549250), so 1.04x is a real gap, not noise. Ord L: the
ranges overlap (1.00x). Dense is under hand and under DB45 on both cells.

Peak RSS (`/usr/bin/time -l`, median of 3, KiB):

| Row | old | new | hand |
|---|---|---|---|
| hist-ord-64k | 2496 | 2272 | 2240 |
| hist-ord-2m | 22816 | 22048 | 19776 |
| hist-ord-8m | 42176 | 41376 | 32432 |
| hist-dense-2m | 3952 | 3968 | 3824 |
| hist-dense-8m | 10192 | 10176 | 10000 |

RSS split (slope = RSS growth per input byte between M and L; fixed = M minus slope x M bytes):

| Shape | old fixed / slope | new fixed / slope | hand fixed / slope |
|---|---|---|---|
| ord | 15.98 MiB / 3.15 B/B | 15.24 MiB / 3.15 B/B | 15.19 MiB / 2.06 B/B |
| dense | 1.83 MiB / 1.02 B/B | 1.85 MiB / 1.01 B/B | 1.72 MiB / 1.01 B/B |

Ord fixed RSS drops 0.74 MiB (lazy tape) and is now within 0.05 MiB of hand; the ord slope is unchanged (G-DB45-2, outside this
lane). Dense M is one 16 KiB page above old and dense L one page below; the decode buffer is at most `longest line + 256` bytes.

Where ord M still spends (sampling profile of the rs/rust driver, 3817 samples): `window` self 2382, `from_utf8` 988, the
`copy_range` memmove 145, and 136 in a zeroed `[i64]` allocation per window (`RawVecInner::try_allocate_in` through
`xzm_segment_group_alloc_chunk`) plus 32 in `malloc_large`. After the lazy tape, the large zeroed `[i64]` arrays left per window
are the `turns` state created in `read::window` (`new_slots` 1600 words, `new_store` stamps 9600 words), so they are the likely
source (not isolated further); hand shows no such fixed cost. That fixed
cost is what keeps M at 1.04x while L (four times the work, same fixed cost) is at 1.00x (G-DB47-1).

## 4. Gaps

| id | what | status |
|---|---|---|
| G-DB47-1 | ord M is 1.04x hand (ranges do not overlap); L is 1.00x. The remaining difference is a fixed per-window cost: `turns::new_slots`/`new_store` zero large `[i64]` arrays per window (136 of 3817 profile samples on M, plus `malloc_large`). They live in `bench/l3/pkgs/turns`, outside this lane. Next step: size the store lazily or keep it across windows in `turns`. | open |
| G-DB47-2 | Each run copied by `dstr` checks at run time that its first byte is not a UTF-8 continuation byte. The check is always true after a quote or escape letter in valid UTF-8, but the verifier has no fact connecting `utf8_valid(b)` to "an ASCII byte is followed by a char boundary"; a lemma in the `utf8_valid_span` theory (compiler/SPEC, outside this lane) would remove it. Cost is one compare per run. | open |
| G-DB47-4 | Two ACP timing fixtures (`acp-error-not-object-does-not-reject`, `acp-timeout-session-load`) fail their `expected` block in the TS reference at load ~10 (the reference times out at `initialize`); the one rs/rust failure in the full run was the same timing and passed on rerun. Not caused by the history reader; the fixtures need a load-independent deadline. | open |
| G-DB47-3 | Item 2 of the brief (G-DB45-3: ord/dense time on py/rust, py/llvm, rs/llvm) was not done for time; only `pruv == hand` is checked there. | open |

No new builtin was needed (`string_clear` / `string_with_capacity`): the reused `[u8]` buffer with `resize`, `copy_range` and a
`str` subview of its valid prefix covers the decode.
