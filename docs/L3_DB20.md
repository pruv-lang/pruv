# L3 DB20: exact pool length (DB13 stage 4) and host pool checks for entry and req

Base: 76989723.

Stage 4 of docs/L3_DB13.md lands here (D-DB18-2, D-DB13-2). The host `decode_pool` now checks the 0xFF placement
and the exact unit count (D-DB18-6). Physical-limit probes are added (D-DB18-4, in part).

## What DB20 does

- The string pool `[nu, nb, W...]` must be exactly `l0 = 2 + ceil(nb/7)` words long. Extra zero words after the
  last packed word are refused.
  - Core: `ent_wire::pool_ok` (used by `wire_in` and by req `hdr_ok`).
  - Rust host: `decode_pool` in `entry/host.rs` (also used by the req host).
- `same_packet` no longer treats trailing zero words as equal. It compares length and words exactly, then runs
  `wire_in` on the second packet.
- Host `pad_to` stays. It pads whole sections, not the pool.
- `decode_pool` checks, in addition to the length:
  - `nu` in `0..=16,777,216`;
  - each 0xFF byte sits only between a lone high and a lone low surrogate (`pool_units`);
  - `nu` equals the decoded unit count exactly.
- No writer changes. Every writer (`encode_pool`, `pool_words`, req `mk`, the Rust encoders) already produced the
  exact length. Outputs are unchanged (all tests below).

## What changed

- `lib/ent_wire.pruv`: `pool_ok` checks `l0 != 2 + (nb + 6) / 7` (mutant point M17). `same_packet` drops the
  zero-word equality.
- `entry/host.rs`:
  - `decode_pool`: exact length, `nu` cap, `pool_units` (0xFF placement, exact `nu`);
  - test modes `extra_word` and `missing_word` (pool one word long or short, other length fields kept consistent);
  - physical probes `exact_limit_phys` and `oversize_phys` (`pad_phys`);
  - unit tests for malformed sections.
- `entry/forge_test.py`: extra and missing pool word cases, physical-limit probes.
- `entry/gen_fixtures.py`, `fixtures/P.json`: P10 (physical limit), P11 (kills M17); 156 fixtures.
- `entry/q_mutants.py`: M17 (drop the exact `l0` check).
- `entry/common.py`, `entry/test_impl.py`: run the new modes.
- `req/forge.rs`, `req/forge_test.py`: F62-F65, pool one word long or short in a received packet and in a
  `begin` pool: `InvalidPacket`.

## Audit, fixes and rechecks

One audit (Codex gpt-6.2-astra ultra) on the first DB20 diff found 4 must-fix items and 1 advisory item. All four
were fixed:

| ID | Item | Fix | Repro test |
|---|---|---|---|
| R1 | Host `decode_pool` did not cap `nu` | `nu > 16,777,216` is refused | `decode_pool_rejects_malformed_sections`: `nu` at the cap ok, cap + 1 refused |
| R2 | Test mode `missing_word` did nothing on an empty pool | On an empty pool it raises `nu` and `nb` by one, so the pool claims one byte and is one word short | entry `forge_test.py` missing-word cases |
| R3 | req F62/F63 counted a malformed core output as a refusal | `core_refused(..., strict=True)` counts only a reject record equal to `[5, 0]` (after the recheck; first fix checked the first two words only) | req `forge_test.py` F62, F63 |
| R4 | `oversize_phys` was also over the logical limit, so it did not isolate the physical check | Not fixed. The probe grows only the pool, and a grown pool adds more logical units than words, so it is over both limits. A physical-only oversize needs at least M-1 words outside the pool and a pool of at most two units; this probe does not build it (G-DB20-1). The comment in `pad_phys` says so | none |
| A1 (advisory) | The req host `units_at` calls `decode_pool` per string slot, so the full pool check now runs once per slot | Not fixed (D-DB20-2) | none |

One recheck (Codex gpt-6.2-astra) of the four places found R1 and R2 fixed and two items still open:
- R3: strict mode still took `[5, 0, 99]` as a refusal. Fixed: strict mode compares the record to `[5, 0]`, as
  `begin_pool` does. req `forge_test.py` ran again: 81/81, F62-F65 `InvalidPacket`.
- R4: the first comment said a physical-only oversize cannot be built at all. That is wrong: an empty pool `[0, 0]`
  with M-1 words outside it has physical length M+1 and logical size M-1. The comment and G-DB20-1 now say only
  that this probe cannot build it.

These two follow-up fixes were not rechecked: the audit and recheck budget is used up.
