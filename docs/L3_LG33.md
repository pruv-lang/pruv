# L3 LG33: move at last use for `truncate` (LLVM) and `str_from_utf8` (both backends)

Scope: G-LG32-5 (codex L RSS on LLVM: `wire = truncate(hb, m)` copies while `hb` is live), the compiler part of
G-DB54-2 (`str_from_utf8(b)` copies an owned `[u8]` that is dead afterwards) and, if time was left, G-LG32-3 (field
target regrow). No bench source (bench/l3/lib, bench/l3/pkgs, the Pruv sources of any piece) was edited.

Status: LG33: G-LG32-5 partial (both compilers: on LLVM `x = truncate(src, m)` / `let x = truncate(src, m)` with `src` an owned local array at its last use moves the block, shrunk with `pruv_shrink_v2` when more than half unused, instead of a fresh block plus copy; codex `read.pruv:254` takes the new path (emission compare); the codex L RSS re-measure on rs/llvm and py/llvm did not finish inside the lane time under load 9-18, G-LG33-5)
Status: LG33: G-DB54-2 partial (both compilers, both backends: `str_from_utf8(b)` of an owned local `[u8]` at its last use moves the block into the `str`, no copy; the pkgs/jstr switch to decode into an owned buffer is G-LG33-1)
Status: LG33: G-LG32-3 open (not started in this lane, time)

## Step 1: `truncate` move on LLVM (G-LG32-5)

The Rust backend already moved `truncate(x, m)` of a dead owned local outside `return` (R03L, `last_copy`); the LLVM
backend only moved it under `return truncate(x, m)` and lowered every other `truncate` to `pruv_copy_v2` (a fresh
block of `m` elements plus a copy) while `x` stayed live until its scope ended.

D-LG33-1: on LLVM, in a `let` or assignment whose value is `truncate(x, m)`, when `x` is an owned local array slot
(`owned_slot`: not a parameter, reference, pinned or borrowed binder), `x` is dead after the statement (`dead_after`),
`x` is not the target and the length argument does not name `x`, `move_src` marks `x` as moving. The lowering empties
`x`'s slot and keeps its block: `nc = (cap >> 1 > m) ? m : cap`, `p = pruv_shrink_v2(data, cap, nc, size, align)`,
the result has length `m` and cap `nc`. So a block left more than half unused is shrunk in place (realloc), as the
Rust backend's truncate move does; otherwise the block is kept with its cap. `pruv_shrink_v2` keeps the block when
`nc == cap` and frees it and returns NULL when `nc == 0` (empty array, cap 0). D-LG33-3: its default-mode
`realloc` failure is now `pruv_panic_arith("allocation failed")` instead of keeping the old block, because the move
records `nc` as the cap, so the block must really have `nc` elements (under `PRUV_RUST_ALLOCATOR` the host realloc
already aborts on failure). Both compilers emit the same IR (diff_rust, below).

Bench sites that take the new path (old-vs-new emission compare, below): codex `read.pruv:254`
(`wire = truncate(hb, ...)` in `read.replay`) and grok `path.pruv:237` (`let joined = truncate(jb, total)` in
`path.join`).

## Step 2: `str_from_utf8` move (G-DB54-2, compiler part)

`str_from_utf8(b)` copied `b` on both backends (`pruv_b.to_vec()` on Rust, `pruv_copy_v2` on LLVM) even when `b` was
an owned local never read again. D-LG33-2: when `b` is an owned local `[u8]` at its last use (Rust backend:
`last_copy`, `dead_after` or `return_next`; LLVM: `move_src`, `dead_after` and `owned_slot`), the Rust backend emits
`let pruv_v: Vec<u8> = <moved b>; String::from_utf8_unchecked(pruv_v)` (verified) or `String::from_utf8(pruv_v)` with
the same panic text (unverified), and the LLVM backend keeps the UTF-8 check and hands `b`'s block and cap to the
`str`. The test `tests/runtime/lg33_rt_move` checks `capstr` (an `alloc` of 10 bytes, `truncate` to 6, then
`str_from_utf8`) with `llvm_fn_absent: @pruv_copy_v2(, @pruv_copy(`: the function has no copy on LLVM, and the
output `6098` shows the truncated, moved block keeps its first bytes.

pkgs/jstr still decodes into a borrowed view and copies (G-LG33-1); the move only pays off once a package hands an
owned buffer to `str_from_utf8`.

## Measurements

Grok history ord/dense M/L (rs/rust, rs/llvm): the perf drivers built by `bench/l3/grok/perf/run_perf.py check`
with the old and the new pruvc are byte-identical on both pairs (`cmp`; 615,752 and 587,688 bytes). The perf root
does not reach `path.join` or any other changed site, so time and RSS are unchanged by construction and no
alternating run was made (`bench/l3/grok/perf/alt_perf.py`, added for this lane, is ready for the next one).

Codex L RSS (rs/llvm, py/llvm): not measured. The old-side runners (`measure_r09.py --save`, built by codex
`test_impl.py --only read_pages_40` with the old pruvc in a scratch worktree) were still compiling at the lane cap
(about 40 minutes of verify under load 9-18 from this lane's suites and another lane's codex and grok runs), so no
old/new pair exists; no time or RSS claim is made (G-LG33-5). The expected effect, from the LG32 alloc trace: the
945,570-byte `wire` block is no longer a second block next to the 1 MiB `hb`; `hb` itself becomes `wire` (shrunk
to `m` only when `m` is under half of its cap, which on read_pages_40 it is not, so the block is kept as is).

Old-vs-new emission compare (rs compiler, both backends, old = main b06dfe51 build, new = this lane's build): 14
bench roots (codex, grok, json a0..a5, claude a0..a4; grok `perf/perf_root.pruv` could not be compiled standalone,
"--manifest root does not match the input file"), 39 outputs compared, 2 differ, both LLVM: codex `read.replay`
and grok `path.join`. Changed line kinds: -2 `call @pruv_copy_v2`, +2 each `lshr`, `icmp ugt`, `select`,
`call @pruv_shrink_v2`, `store ptr null`, +4 `store i64 N` (slot emptying and the new cap); the rest is the same
lines reordered. No Rust-backend output changed. In tests/runtime, `lg33_rt_move`, `lg9_rt_utf8_ascii` and
`p3_n1_storage` changed IR, all with the same pattern (or the `str_from_utf8` hand-over without `pruv_copy_v2`).

## Known differences

| Id | Difference | Why | Kept |
|---|---|---|---|
| D-LG33-1 | on LLVM, `truncate(x, m)` in a `let` / assignment, with `x` an owned local array slot dead after the statement and not named by `m`, moves `x`'s block (shrunk by `pruv_shrink_v2` to `m` when more than half of the cap is unused) instead of a fresh block plus copy | the copy kept two blocks live (codex `wire = truncate(hb, m)`, G-LG32-5); the Rust backend already moved here (R03L) | kept |
| D-LG33-2 | `str_from_utf8(b)` with `b` an owned local `[u8]` at its last use moves the bytes into the `str` (Rust: `String::from_utf8(_unchecked)` of the moved `Vec`; LLVM: block and cap handed over after the UTF-8 check) | the copy doubled the bytes of every decode of an owned buffer (G-DB54-2) | kept |
| D-LG33-3 | `pruv_shrink_v2` (default mode) panics with "allocation failed" when a shrinking `realloc` fails, instead of returning the old block | the LLVM truncate move records the shrink target as the cap, so the returned block must have that size | kept |
