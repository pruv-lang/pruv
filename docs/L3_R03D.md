## What landed

### R03L-G3: user-named quantifier triggers (SPEC R-6-3)

`forall i in lo..hi trigger t1, ..., tn: e` (and `exists`) passes `t1..tn` to z3 as one multi-pattern. Triggers change
only which instances z3 tries, never the formula, so they cannot make a false contract true. Each trigger must be an
array read that mentions the binder (`type/bad_trigger` otherwise, and on `count`/`sum`/`max`/`min`). A trigger is a
term, not a value: no domain obligation. Without a trigger list the z3 query is unchanged. A trigger
must still mention the binder after calls in it are expanded (`a[zero(i)]` is rejected), and the verifier's
free-constant walk also reads pattern terms, so an outer binder used only in an inner trigger stays bound. Python
(`pruvc/vparser.py`, `vast.py`, `check.py`, `verify.py`) and Rust (`parser.rs`, `ast.rs`, `check.rs`, `symbolic.rs`,
`sys.rs`) in the same commit. Tests: `tests/spec/r6_3_trigger*.pruv`.

Why only array reads: a pure-arithmetic pattern such as `6 * t + 3` made z3 loop in a probe (2 min, no answer), while
`a[6 * t + 3]` instantiated at once.

### R03C-D32: not landed (gap G-R03D-1)

`check_tape` stays. Proving its facts inside `scan_document` needs the direct-child counts
`tape[6 * t + 5] == count(k in t + 1..skip: tape[6 * k + 4] == t)` to survive every later `close_record` /
`write_record` call. Neither verifier can carry an aggregate across an `inout` call, even one that changes nothing:
the probe below (requires `c == count(k in q + 1..j: tape[6 * k + 4] == q)`, calls an `inout` helper
whose `ensures` covers every untouched slot, then `assert` the same count) fails with `verify/assert` in both
compilers, also in the counterexample where the helper returns false and the tape is pointwise unchanged. The count is
an uninterpreted function of the array term; the new array is only pointwise equal, and there is no frame lemma.
R03L-G2 (count range split) does not help with this.

```
fn close(inout tape: [i64], r: i64, e: i64) -> bool
  ensures len(tape) == len(old(tape))
  ensures result ==> (0 <= r && 6 * r + 6 <= len(tape))
  ensures result ==> (forall i in 0..len(tape): (i != 6 * r + 2 ==> tape[i] == old(tape)[i]))
  ensures !result ==> (forall i in 0..len(tape): tape[i] == old(tape)[i])
{
  if r < 0 || r >= 1048576 { return false; }
  if len(tape) - 6 * r < 6 { return false; }
  tape[6 * r + 2] = e;
  return true;
}
fn probe(inout tape: [i64], q: i64, j: i64, x: i64, c: i64) -> i64
  requires 0 <= q && q < j && 6 * j <= len(tape) && len(tape) <= 6291456
  requires 0 <= x && x < 1048576
  requires c == count(k in q + 1..j: tape[6 * k + 4] == q)
{
  let ok: bool = close(inout tape, x, 5);
  assert c == count(k in q + 1..j: tape[6 * k + 4] == q);
  return c;
}
fn main() -> i64 { return 0; }
```

### R03C-D31 / R03L-D5: not landed (gap G-R03D-2)

Holding the source as a borrowed `[u8]` field needs a lifetime on `JsonDocument`, `JsonParse` and the types that carry
them, and Pruv has no lifetime syntax (a `[u8]` field is an owned `Vec<u8>`). Uses that a borrowed field would break:

- `bench/l3/pkgs/lines` and `bench/l3/lib/lines` parse a local `owned` buffer and return the document.
- `bench/l3/grok/rpc.pruv:142-150` and `bench/l3/codex/rpc.pruv:73-81` parse a local `trimmed` slice inside
  `parse_range`.
- `bench/l3/mcp/perf/perf_driver.rs:106-133` keeps documents in `Vec<Page>` after the loop-local byte buffer is gone.
- LLVM rejects a struct with a `[u8]` field as a host entry param (`pruvc/llvmgen.py:5503-5508`,
  `pruvc-rs/crates/pruv-core/src/bindings.rs:343`).

Changing this would change the public `pkgs/json` / `pkgs/parse` types, which the lane forbids.
