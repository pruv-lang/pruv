# L3 DB51: grok ord fixed RSS and the zeroed packet (G-DB48-3, G-DB47-1, G-DB48-1)

Brief: in `bench/l3/grok/`, (1) build the `[i64]` packet without the zero fill that DB48 profiled as about 4.5% of
the ord M window (G-DB48-3 / G-DB47-1), aiming at ord M time at or under hand; (2) cut ord fixed RSS (G-DB48-1),
where `turns::finish2` builds a separate text buffer before the packet; (3) only if time is left, ord/dense time on
the other pairs (G-DB47-3). Base: main 1a2221eb. One release `pruvc` build from this base; no other compiler build.

## What landed

- `bench/l3/grok/read.pruv`: `window()` no longer calls `turns::finish2` and `assemble`. The new `assemble_store`
  builds the rows from the Store's offsets (same run-time checks as `finish2`; a failed check stops later rows,
  which stay zero), proves the rows and meta with `packet::rows_ok` (falling back to `internal_packet(1)` as before),
  allocates the packet once, and widens each draft's bytes and stamps straight from `bk.data` / `bk.stamp` into the
  packet at the offsets `turns::text_layout` gives (newest draft at the end of the text, as `finish2` lays it out).
  The title and model are widened after the drafts. No separate text buffer is built, so the up to about 2.1 MB
  `finish2` text and its copy are gone. The `// MUT:M12` mutation line is kept on one line.
- `bench/l3/grok/packet.pruv`: `pub fn rows_ok(meta, rows, n)`, a wrapper of `result_ok_n` for callers that write
  the packet themselves.
- The packet is still allocated with `alloc(n, 0)` (calloc); see G-DB51-1.

`perf/run_perf.py check` (rs/rust): all five rows `pruv == hand`, same packet words and folds as the old path
(ord-2m 1,730,425 words, fold 5100153930953742342).

`tools/perf_gate.py` on the cells (`work/db51_perf_cells.json`, not committed): ord M time, ord M RSS, dense M RSS and

Profile (`sample`, ord M, new): about 3,030 samples; `__bzero` 103 (3.4%, the zeroed packet), memmove 107,

+65 KB (10.47 vs 10.40, every sample), which breaks "at or under the current value" for dense L.

## Decisions

| id | decision | why | status |
|---|---|---|---|
| D-DB51-1 | the packet is built straight from the Store (`assemble_store`) instead of `finish2` + `assemble` | drops the separate text buffer and one copy of the text; the packet words are the same as before (check rows and folds) | kept |
| D-DB51-2 | the packet stays a zeroed `alloc(n, 0)` | Pruv has no unfilled `[i64]` allocation on both backends: `Vec<i64>` borrowed as `[i64]` is Rust-backend only (R-6e-17) and `vec_extend_from_slice` is rejected by LLVM; adding one is a compiler change outside this lane | G-DB51-1 |
| D-DB51-3 | the pre-sized Store experiment was dropped | it cuts ord M RSS under hand but raises dense L RSS by 65 KB; the right fix is in `turns` (reserve / first size), outside this lane | G-DB51-2 |

## Gaps

| id | gap | cause | next |
|---|---|---|---|
| G-DB51-1 | the packet is still zero-filled (`__bzero` 3.4% of ord M); ord M time 0.97-1.05x hand depending on load | no unfilled `[i64]` alloc that both backends accept and that the prover can follow (write-before-read) | compiler / language lane: an uninitialized `[i64]` alloc with a written-prefix proof, or an owned `Vec<i64>` -> `[i64]` that LLVM accepts; then switch `assemble_store` to it and re-profile |
| G-DB51-2 | ord fixed RSS still above hand (16.03 vs 15.18 MiB; ord M 1.024x) | the Store data chain 64 K -> 136 K -> 279 K -> 561 K before DB48's 4,259,840 jump; pre-sizing in grok fixes ord but costs dense L 65 KB | turns lane: let `new_store` / `reserve` take a size hint from the window (only above 1 MiB of text), measure ord and dense M/L |
| G-DB51-3 | G-DB47-3 (ord/dense time on the other pairs) not started | the 1h45 cap went to items 1 and 2 | measure ord/dense M/L on rs/llvm, py/rust, py/llvm with old/new/hand rotation |
| G-DB51-4 | dense M / L RSS above hand (1.033x / 1.016x; fixed 1.84 vs 1.72 MiB) | unchanged since before DB51; not in the packet text path | find the dense fixed part (allocator trace as in DB48) |
| G-DB51-5 | `widen` / `widen_str` ensures only the length, not the copied words | the packet equality with the old path is checked by `run_perf.py check` and the audit, not proved | add per-word ensures (copied range equals source, rest unchanged) and re-verify |
