# L3 DB18: byte-pool slot coordinate (DB13 stage 3) for entry and req

Base: 0bde1605.

Stage 3 of docs/L3_DB13.md lands here for entry and req. Stage 4 (D-DB13-2: trailing zero words, host `pad_to`)
is not part of this change (D-DB18-2).

## What stage 3 does

- Entry and req string pools use the byte coordinate from docs/L3_DB13.md.
  - Pool `[nu, nb, W...]` with `l0 = 2 + ceil(nb/7)`. Bytes are WTF-8, packed 7 per word big-endian.
    `nu` is the logical UTF-16 unit count.
  - Slot `[6, byte_off, byte_len]`.
  - A 0xFF separator byte goes between a lone high surrogate and a lone low surrogate that would otherwise join.
    0xFF never occurs in WTF-8. It takes one byte and no logical unit, and the pool check allows it only between a
    lone high and a lone low. No string slot starts, ends or reads through it as content.
  - `wire_in` validates the pool in place and no longer copies it; `wire_out` is the identity.
  - The logical size of a packet is `len - l0 + nu`. A req packet that carries a child entry packet in section 5
    counts the child by its own logical size.
- D-DB17-2: `req/gen_wire.py` emits the byte-pool `req_wire.pruv`; the generated file matches the generator byte for byte.
- D-DB17-3: the `ent_bound.pruv` colon search goes through an `ent_value` helper (`pstr_find_byte`). The entry M14
  mutant pattern moved with it and is still killed (by V03).
- Outputs are unchanged (all tests below).

## What changed

- `lib/ent_value.pruv`:
  - byte-pool readers: `pool_bytes`, `pool_byte`, `span_ok`, `span_units`, `prefix_bytes`;
  - decoders: `decode_into`, `decode_span`;
  - string operations: `str_len`, `str_units`, `str_eq*`, `pstr_find_byte`, `encode_pool`, `pstr_cmp` (UTF-16 order);
  - separator edge helpers: `starts_low`, `ends_high`.
- `lib/ent_wire.pruv`: `wire_in` returns a validation result, `pool_ok` is the WTF-8 stream check with the exact unit
  count. `poison` turns an invalid packet into the existing malformed path.
- `lib/ent_packet.pruv`: `env_check_wire` validates the pool once at the wire boundary. `env_check` keeps the full
  check for callers that come in without the wire step, such as req calling `entry_api`.
- `lib/entry_api.pruv`: `entry_begin_with_env` and `entry_step_at` take that one check result.
- `req/req_packet.pruv`: `hdr_ok` (receive) and `mk` (send) add `child_extra`, the signed difference `child nu - child l0`
  of a section-5 child entry packet, so the child counts by its logical size.
- `req/req_fill.pruv`: `view_strs_ok` checks every slot of the call 33 view reply that the recipe relocates with
  `req_value::slot_ok` (tag the host reads; string slots in range, on WTF-8 boundaries, not over 0xFF).
- Other entry and req modules use the helpers. The req host and the entry host encode and decode the new pool.
  The truncation rule at 200/80 units keeps the 4-byte cut.

the base (new/base 0.999 M, 1.005 L); that is D-DB18-1. The 0xFF scan in `span_ok` shows no cost.
