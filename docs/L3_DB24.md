# L3 DB24: OpenCode R07 rs/llvm M/L cells

Goal: the R07 begin, step_checked and step_admitted rs/llvm cells at or under 1.0x of hand Rust on time and RSS
(D-R07-1..3). rs/rust already passed and is not touched.

## Step 1: generated LLVM vs generated Rust, per hot path

Read from the optimised IR/assembly of `work/rs_llvm/root_gen.ll` (`clang -O2 -mcpu=native`) against
`work/rs_rust/root_gen.rs` and `hand/begin_hand.rs`, in the order data representation -> language gap -> codegen.

- Data representation: both lanes carry the same flat `[i64]`/`[u8]` banks and the same 64-word control and
  116-word step packet as hand. No extra copy or boxing on the LLVM side.
- env refs-only loop (`cfg_ok` -> `env_ok`, 1000 rows per checked step): `ref_ok` is inlined, the loop has no
  bounds checks, four loads per row and the same compare chain as hand.
- `cfg_head_ok` is fully unrolled; `ctl_init` lowers to one memset plus constant stores.
- `step_body` prologue: six `stp` and one `sub sp, 928`; no stack probe.
- ABI entry: the eleven length checks fold into one OR on the fast path.
- Reject path: `done_internal(ctl, 28)` -> `done_simple` is a separate fastcc call, so its constant
  stage/cls/code range checks stay at run time (about ten compares, a few ns on a ~1 us step).
- Allocation: `alloc(116, 0)` -> `pruv_raw_alloc_zeroed_v3` -> free cache or Rust `alloc_zeroed`, the same
  allocator family as hand `vec![0; 116]`; the packet is returned through `Vec::from_raw_parts`.

No codegen defect was found that a compiler change would remove. The residual gap is within the run-to-run
spread of these cells.

## Step 2: source changes

None. The only candidate (a range-check-free `done_simple` entry for the constant stage 28 / cls 3 / code 6
reject) is worth well under the measurement spread and was not taken; the opencode sources are byte-identical
to base `43b8757c`, so every accepted output is unchanged by construction.
