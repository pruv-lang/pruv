# L3 R05 qwen (A + B + C)

Status: A, B and C landed. The gate holds: index, branch, cycle and duplicate semantics, and the collision bounds are unchanged.
Evidence: test_impl 26/26 on four pairs, q.py has 0 unexplained cases, q_mutants kills 12/12, and q_grid.py --check shows Pruv == hand on 33/33.
Perf does not hold. 8 of 16 M/L cells are above hand Rust 1.0x: dense, dupbranch and collide time, and linear RSS.
Those cells are debt rows D-R05-1..4 below. Linear time is now under 1.0x.
The main conversation folds this file into docs/L3_RESTRUCTURE_SPEC.md; this file does not edit the spec.

## 1. What landed

| Part | Change | Files |
|---|---|---|
| A matched grid vs hand Rust | Hand Rust crate (see A notes). Grid runner `q_grid.py` (see A notes). | `bench/l3/qwen/handrust/`, `bench/l3/qwen/q_grid.py` |
| B one document / chain transition | `scan` parses each line once (see B notes). `lookup` compares arena spans with no re-parse (see B notes). `select` takes caller-owned `inout marks` (see B notes). | `bench/l3/qwen/chain.pruv` |
| C selected-turn span handoff | `window_wire` writes the result wire directly (see C notes). `check_shape` validates once before writing. `put_word`/`get_word`/`wire_fail`/`wire_packet` are the wire primitives. `window_bytes` is the new C-ABI entry. `window_packet` stays, decoded from the wire. | `bench/l3/qwen/import.pruv`, `boundary.pruv`, `root.pruv`, `q_root.pruv` |

A notes:
- The hand Rust crate uses serde_json per line (pinned =1.0.154), a `HashMap<String, Vec<Entry>>` uuid index and `Window`/`Turn` structs.
- It has no unsafe code. Its timer covers `window_import` plus `record()`, through the finished record JSON.
- `q_grid.py` reads the same last-8-MiB IO for both sides. The Pruv timer covers entry, wire decode and `record()`, the same end point.
- With serde_json `arbitrary_precision`, an object keyed `"$serde_json::private::Number"` parses as a number. `parse_line` renames that key (same length, only when followed by `:`) before parsing. A `\u`-escaped spelling of that key is not covered.
- It checks fixtures and grids for equality, then runs 7 alternating fresh-process runs under `/usr/bin/time -l`.
- The grid families are linear (8192 B entries), dense (about 200 B), dupbranch (every 7th uuid duplicated, one off-chain branch, a 1→3 cycle) and collide.
- In collide, every uuid falls into 8 buckets of `chain.pruv bucket()` for that exact file.
- Sizes are S/M/L = 2/4/8 MiB.

B notes:
- `scan` decodes `uuid` and `parentUuid` into one byte arena.
- Each entry takes 6 slots: start, next, uoff, ulen, poff, plen. plen is -1 when missing and -2 for a defect.
- `lookup` follows newest-first buckets, marks every duplicate and takes the parent from the first match.
- A cycle stops when no new mark appears.
- With `inout marks`, the bitmap is no longer copied into or out of a result struct.

C notes:
- Words are 8-byte LE `v+1` with the top byte 0. Success is `[0, 14, nt, ntext, meta[14], turns[nt]]` + raw text. Failure is `[code, pos]`.
- This removes the intermediate `packed` [i64], `make_output`'s meta/turns/text copies, the second `check_output`, and the one-i64-per-text-byte widening.
- The old `window_packet` entry remains (decoded from the wire), so test_impl, q.py and the fixtures run unchanged.
- `q_mutants.py`: the leaf-parent anchor moved from the old text to `count > 0 { poff = f.poff; ... }`.

Review (Codex, one audit) found 5 defects, all fixed in the second commit:
1. hand `parse_line`: the `arbitrary_precision` number-key object above.
2. Timer asymmetry: Pruv's owned strings and UTF-8 checks in `Packet::get` ran after its timer, while hand Rust built owned `String`s inside its timer. Both timers now end after `record()`.
3. `q_grid.py check`: a collide mismatch found before a later timeout was lost on retry. Mismatches now accumulate across retries.
4. `q_grid.py check`: the denominator loop had no bound. It now fails once the denominator exceeds the L row count.
5. `q_grid.py --sizes`: an invalid value wrote `[]` and exited 0. It is now rejected.

## 4. Gap rows

| ID | Gap | Workaround here |
|---|---|---|
| G-R05-1 | The C ABI result can only be `[i64]`, `[u8]` or `i64`. Struct results are Rust-only and cannot hold `[u8]` fields, so a multi-buffer result (meta, turns, text) cannot cross the boundary. | One `[u8]` byte wire with a fixed header (`boundary.pruv put_word`, `import.pruv window_wire`) |
| G-R05-2 | A `[u8]` struct field needs `copy()` or a fresh alloc, so a local buffer cannot move into a result struct. | `select(..., inout marks)` keeps the bitmap with the caller; the wire is written in place |
| G-R05-3 | No `[u8]` → `str` conversion, so a `Vec<String>`-like turn output is impossible. | Text bytes go into the wire as spans |
| G-R05-4 | No shift or byte-word primitives (`to_le_bytes`), so little-endian words are written with `%256` / `/256` loops and an unrolled read. | `boundary.pruv put_word` / `get_word` |
| G-R05-5 | `entry.pruv string_field` returns `Field::Value(copy(v))`, a fresh `str` per field read, with no borrowed decoded span. | Copied into the arena once with `chain.pruv put` (a second byte copy) |
| G-R05-6 | Root entries cannot take `inout` parameters, so the caller cannot supply the output buffer. | `window_wire` allocates the wire and returns it |

## 5. Debt rows (cells above 1.0x)

| ID | Cells | Line-level cause | Fix direction |
|---|---|---|---|
| D-R05-1 | collide time M 17.6x, L 35.0x | `chain.pruv:148-176` `lookup` walks the whole bucket chain on every step, because every duplicate must be marked and there is no early exit. `chain.pruv:6-21` `bucket` is a fixed `h*257 % size` hash, so the grid can push every uuid into 8 buckets. The walk is then O(n) per chain step, O(n²) in total. Hand Rust uses keyed SipHash `HashMap<String, Vec<_>>`, which costs O(1) per step. | Keep a per-uuid duplicate group: link duplicates at insert in `scan` so `lookup` stops at the first match. Use a keyed or randomized hash, which needs a seed source (lib gap). |
| D-R05-2 | linear RSS M 2.81x, L 2.36x (time M 0.86x, L 0.92x passes) | On top of the input, `chain.pruv:197-199` allocates heads, slots and an arena of `len(data)` bytes, and `import.pruv:441` allocates `selected` at `len(data)`. `import.pruv:533` adds the wire, `hl + total`. These are 3 extra input-sized live buffers. Hand Rust keeps the lines borrowed and owns only the selected turn strings. The per-byte passes (`chain.pruv:189-196` newline count before `scan`, framing scanning each line again) no longer cost time here. | Size the arena to the uuid bytes (a pre-pass already exists). Turn `selected` into a line-index bitmap. Fuse the capacity pass into framing. |
| D-R05-3 | dense time M 1.15x, L 1.33x | Per line, `chain.pruv:80` `parse_line` builds a full JSON document, and `chain.pruv:83,95` `string_field` allocates a `str` copy for each field (G-R05-5). `chain.pruv:86` calls `field_is` up to 3 times on `type`, each with a fresh key lookup. The title/turn pass at `import.pruv:464-468` frames and parses every line a second time (`window_next` + `parse_line`), so B's "one parse per line" holds only inside the chain walk. Hand Rust parses each line once into a struct. | One `type` lookup compared against 3 literals. A borrowed string span from the entry lib (G-R05-5). Merge the chain scan and the title/turn pass into one framing loop (the chain must be known first, so keep line offsets plus parsed fields rather than re-parse). |
| D-R05-4 | dupbranch time M 1.11x, L 1.11x | Same causes as D-R05-3. On top of that, `lookup` follows each duplicate group in full (3 entries share one bucket). | Same as D-R05-3 and D-R05-1. |
