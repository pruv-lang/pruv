# L3 DB36: opencode F08 at low load, a real `--verify-only`, and fewer `scan_literal` queries (G-DB35-3, G-DB35-2, G-DB34-1)

Brief: run the opencode F08 fixtures at the lowest load we can get, make `test_impl.py --verify-only` verify the four
pairs, and restate `lex::scan_literal` so the py verifier issues fewer queries on claude `a2_root`. No runtime check
added, generated code no slower, no compiler edits (docs/L3_RESTRUCTURE_SPEC.md 7.5). Base: main 68dec559. The rs
compiler was rebuilt once from this base (21:16 KST).

## What landed

- G-DB35-3 (F08): `test_impl.py --only F08` passed 18/18 on py/rust and py/llvm at load 3.6-4.0 (21:22-21:26 KST).
  At load 4.5-6 with other runs going, all four pairs gave 13/18 with the DB35 failures, and they are ts-side failures:
  the ts reference sees the child end by signal 15 under the default disposition (record 37) and never runs the fake in
  `F08-give-up-script`. The impl side passes all of F08. Also: in the full opencode run
  (21:46 KST) the ts reference stage ran at load 17-21 (other sessions), and on `F08-hang`, `F08-term-exit`,
  `F08-kill-required` and `F08-close-overrides-timeout` (all `rpcMs` 1000, hang mode) the ts side's fake exporter left
  no `<exe>.log` at all. The log is written by the fake's first `flush()`, before any signal handling, and was still
  absent minutes later in `work/cases/ts/F08-hang/bin/`, so the child was killed by the 1000 ms deadline before Python
  reached that line. The impl side passed every F08 case in that run; the same 4 cases fail on every pair because the
  ts result is shared. Not a compiler cause. The bench-side cause (why the ts reference's child starts that slowly) was not found in the cap: G-DB36-1.
- G-DB35-2 (`--verify-only`): `verify_one` now does one verified compile per pair into a throwaway
  `work/verify/<compiler>_<backend>/` (the same `-o` / `--backend llvm --rust-bindings` command the drivers use, never
  `--no-verify`), logs it, and the run exits 1 if any pair fails, else 0. The old attempt (no `-o`, a flag no compiler
  has) is gone. The audit found that `--scope A|B|C|D` also failed before any verify: the temporary entry passed
  `--manifest` together with `--lib` (both compilers reject the pair) and its package name had an upper-case letter
  (`manifest_invalid`). The scope entry now gets copies of its own modules next to it, no `--lib`, and a lower-case
  name.
- G-DB34-1 (`scan_literal`, both copies `bench/l3/pkgs/lex/lex.pruv` and `bench/l3/lib/lex.pruv`, which claude reads
  through its symlink): the three `if c == 116 / 102 / 110` blocks are now one `if / else if / else` chain. The last
  arm is `c == 110` because the guard before the loop already returned for every other `c`. The inner `k` ifs stay
  independent. Same `want` for every reachable `(c, k)`, same contracts, invariants and `decreases`, and the
  generated Rust still uses `get_unchecked` with no added check. Only `scan_literal` differs in the generated a2 code.

## Measurements

py queries on claude `a2_root` (`qcount`: TraceRecorder around `verify.verify_program`, one count per solver query):

| lex | queries in `scan_literal` | `scan_literal` time | queries in all of `a2_root` | recorded wall |
|---|---|---|---|---|
| old (68dec559) | 13798 | 15.0 s | 25195 | 98.6 s |
| full else-if on `c` and `k` (rejected) | 244 | 0.29 s | 11641 | 73.1 s |
| landed (else-if on `c` only) | 532 | 2.4 s | 11929 | 129 s (heavy load) |

Wall time is load-bound (G-DB34-1); the query count is not. Old 13798 -> new 532 (26x fewer), all of `a2_root`
25195 -> 11929.

Verify-and-emit wall time of `a2_root`, old and new lex, alternating, `{"ok": true}` every time:

| compiler | load | old | new |
|---|---|---|---|
| rs | 5-7 | 41.58 s, 42.69 s | 37.12 s, 37.56 s |
| py | 6-14 (noisy) | 63.07 s, 63.58 s | 66.89 s, 45.27 s |

rs drops about 11%. The py wall time is inside the load noise (one new run above both old runs, one far below).

Generated code: the rejected full `k` else-if chain verified cheapest but rustc turned its nested `k` tests into
branches. On a periodic input (the same literals repeated) it measured 35.8 / 33.9 ms min against old 31.4 / 28.8 ms
(about 15% slower). The landed form (independent `k` ifs, which rustc lowers to selects) measured 32.0 / 29.1 ms, the
same as old within noise. On random input every form was 135-144 ms (noise). Two rounds per form, a micro-benchmark of
the generated `scan_literal` Rust built with `rustc -O`.
