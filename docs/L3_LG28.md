# L3 LG28: guarded `dom` right side, entry W in `obs`, per-mode `Vec` entry wording

Scope: G-LG27-7, G-LG27-5, G-LG27-6 and G-LG27-1 in both compilers (Python `pruvc/`, Rust `pruvc-rs/`). No `bench/`
file is changed. G-LG27-2/3/4, G-LG24-2, G-LG22-3, G-LG23-1, G-LG20-2/4/5, G-LG18-3, G-LG15-1, G-LG16-1, G-LG21-x,
G-DB30-2 and G-DB33-1/2 are out of scope and unchanged.

Status: LG28: G-LG27-7 open (implemented in the first LG28 commit and reverted in the second, see Python a2 flip below: the contract domain check `dom` reads the right side of `&&`, `||` and `==>` under g plus the short-circuit guard, both compilers; a W read there is now guarded; a read inside an opaque body unfolded there is still unguarded, as before (G-LG28-5); no test can be built, so the evidence is an SMT dump (G-LG28-1))
Status: LG28: G-LG27-5 open (implemented in the first LG28 commit and reverted in the second, see Python a2 flip below: the entry W of every `str` parameter is put in the state's `obs`, and a read whose W id is in `obs` adds nothing, both compilers; on the lg26/lg27 and r6b_3 tests the asserted clauses drop by 20-41% and the SMT text by 39-86%, queries unchanged, no flips on `tests/`)
Status: LG28: G-LG27-6 closed (SPEC.md 6a states per build mode which entries reject a `Vec` of an invariant struct; wording only)
Status: LG28: G-LG27-1 open (the automatic loop frame for a local `Vec` built by pushes needs three new analyses (G-LG28-2, G-LG28-3, G-LG28-4); the program still states the element clause as a loop invariant)

## What landed

Steps 1 and 2 were implemented and checked on `tests/` in both compilers (all green, below), then reverted: with
either step alone the Python compiler times out on the bench `bench/l3/claude` a2 postcondition of
`turns::plan_end` (G-LG28-6), which base verifies. The branch keeps the code in its first LG28 commit, so it can be
put back once that proof is made robust. Only step 3 (wording) stays at the branch head.


- Guarded `dom` right side (G-LG27-7). `dom` (`pruvc/verify.py`, `symbolic.rs`) builds the definedness formula of a
  contract. For `a && b`, `a ==> b` and `a || b` it now recurses into b with the path guards g plus `a` (plus
  `not a` for `||`), the guard it already wrapped the result in. A fact a read of b assumes (W of a `str`) is
  therefore guarded by the left side, as on the ordinary expression path.
- Entry W in `obs` (G-LG27-5). In a UTF-8-aware function `run()` assumes W of every `str` parameter unguarded at
  entry. The id of that W term now goes into the entry state's `obs`, and the read
  path (`assume_str` / `assume_str_utf8`) returns at once when the W term of the value is in `obs`. Before, the
  first read under a guard added `Implies(And(g), W)` for a W already on the path.
- Per-mode wording (G-LG27-6). SPEC.md 6a, see Rule decisions.

## Rule decisions

- Step 1 (G-LG27-7): pass `g + [l]` (`g + [Not(l)]` for `||`) to the right-hand `dom`, nothing else. The returned
  formula keeps its `Implies(guard, dr)`, so the obligation is unchanged in meaning; only facts assumed while
  reading b get the extra guard, which can only make them weaker. A must_reject test cannot be built: the leak
  needs a `str` value that is not valid UTF-8 and is read only under a false left side in a contract, but every
  `str` value is valid by type (W is assumed at entry and on every call result), and the only way to make a
  partial-character view, `subview`, is barred in contracts. The evidence is an SMT dump of
  `requires utf8_valid_span(b, 0, len(b)) && (false ==> 1 / len(p.label) == 0)`, `p: P`, `P { label: str }`: old
  7 asserts with W of `p.label` asserted under g only (93 mentions of `label`); new 6 asserts with that W under
  `(=> (and ... false) ...)` (50 mentions); the two obligations of `f` shrink from 24695/24763 to 18548/18616
  characters. The missing test is G-LG28-1.
- Step 2 (G-LG27-5): skip on the bare W id, not register the guarded key. The entry W is pushed with no guard, so it
  implies every guarded copy; a skip only removes a weaker, implied fact. The entry W is in the entry state's
  `obs`, which forks copy, so it is in `obs` exactly on the paths whose pc holds it. A loop havoc or an assignment
  makes a new term with a new id, which is not in `obs`, so that value is assumed again (as in LG27). The opaque
  state (`st0`) has no entry W and gets nothing. In Rust the ids are put in `run()`, which builds the entry state
  itself (`init_params` is only the sampler's path and is unchanged).
- Step 3 (G-LG27-6): from `check_entries` (`pruvc/check.py`, `check.rs`), host entries (`pruvc/modules.py`) and the
  Rust codegen `private()`. Explicit mode: a host entry (root `pub` non-generic function) with a `Vec<S>`
  parameter (read-only, `inout` or `take`) or result is `type/entry_signature` by the collection rule (only
  `Vec<i64>` and `Vec<bool>` results pass, R-6f-1), not by the invariant rule, since the invariant walk does not
  enter `Vec`. Child `pub` and private functions may take or return it. Legacy single-file mode has no
  host-entry signature check, and the invariant-parameter rule does not look inside `Vec`, so any function but
  `main` may take it (`main` with a collection is `type/entry_main` in explicit mode, `type/foreign_export` in
  legacy mode); the Rust backend emits every function with a collection in its signature as a private item, so no host
  caller can pass one (checked: `fn f(v: &::std::vec::Vec<S>)` without `pub`), and the LLVM backend rejects a `Vec` of a struct
  (`codegen/unsupported_type`; it has only `Vec<i64>` and `Vec<bool>`). So no host code ever passes or receives such a `Vec` and the entry fact rests on
  proved Pruv callers.
- Step 4 (G-LG27-1): not landed; the brief's rule is to stop at the next item that needs a new analysis. An automatic
  loop-head clause for a local `Vec<S>` needs (a) a body analysis that the loop writes the `Vec` only by
  `w = vec_push(move w, x)` (no `vec_at_mut`, no reassignment from another value, no `inout` call), (b) a candidate
  clause outside `--infer` that is dropped, not reported, when it fails at entry or preservation (today only the
  `--infer` candidates are dropped, so an added clause that fails would turn an accepted program into a rejected
  one), and (c) the proof that each pushed value satisfies the clause, which is a new obligation per push. None of
  these exists in either compiler; they are G-LG28-2, G-LG28-3 and G-LG28-4. `tests/runtime/lg27_elem_inv` (`fill`)
  still states the clause as a loop invariant.

## Gaps

| Id | Gap |
|---|---|
| G-LG28-1 | G-LG27-7 has no test: a `str` that is not valid UTF-8 cannot reach a contract (every `str` is W by type, `subview` is barred in contracts). Rule: when a contract can name a partial-character view (or a non-`str` fact read gets the same guarded path), add a must_reject test with that read under `false ==>` in a `requires`. |
| G-LG28-2 | Loop frame part 1 (G-LG27-1): no analysis says a loop writes a local `Vec` only by `w = vec_push(move w, x)`. Rule: a syntactic body walk (both compilers) that marks a `Vec` local as push-only when every write to it in the body is that form and it is not passed `inout` or to `vec_at_mut`/`vec_clear`/`vec_pop`. |
| G-LG28-3 | Loop frame part 2: a clause the verifier adds to a loop head is reported when it fails; only `--infer` candidates are dropped. Rule: a non-reporting candidate loop invariant outside `--infer`, proved at entry and preservation and dropped (with the same trace in both compilers) when either fails, so adding the frame clause cannot reject a program that verifies today. |
| G-LG28-4 | Loop frame part 3: the element clause of a push-only `Vec` needs each pushed value proved to satisfy the struct invariant at the push. Rule: at `vec_push::<S>(move w, x)` in a framed loop prove the clauses of S for x (the existing struct-argument obligation) and keep the forall over `0..len(w)` by the push axiom; land only if no test flips and a0-a4 grow by at most 20%. |
| G-LG28-6 | Steps 1 and 2 (G-LG27-7, G-LG27-5) each make the Python compiler time out on the `turns::plan_end` postcondition of bench/l3/claude a2 (base verifies; rs verifies either way). The proof is context sensitive (G-R08-2): it moves with unrelated earlier queries of the run. Rule: make `plan_end` robust on the bench side (outside the language lane: split the ring-index `forall` further or add a per-index hint) and confirm py a2 verifies 3 of 3 at base and with the first LG28 commit, then cherry-pick that commit's code. |
| G-LG28-5 | Found by the LG28 audit, not new in LG28: an opaque predicate whose body is unfolded at once (quantified argument) or a revealed one is evaluated by `opq_body` (`pruvc/verify.py`, `symbolic.rs`) with an empty guard, so a `str` read in that body adds its W without the caller's short-circuit guard, e.g. `forall i in 0..1: false ==> (hit(p, i) ==> ...)` with `hit` reading `p.label`. The reveal equation itself must stay unguarded. Rule: split the unguarded definition equation from the facts the body reads, and push the latter under the call site's guard, in both compilers; land with a must_reject test once one can be built (G-LG28-1). |
