# L3 LG18: `?` lowering leftovers (owned temporaries, inout, borrow before move) and LLVM `ok_val` of aggregates

Scope: G-LG14-1, G-LG14-2, G-LG15-1 and G-LG15-2. Both compilers (Python `pruvc/`, Rust `pruvc-rs/`) change with the
same rejects, messages and lowering. No `bench/` fragment is changed.

Status: LG18: G-LG14-1 partial (a Vec / HashMap / String call result or plain move passed directly to a user function's take parameter of the same type is bound to a temporary and moved; any other non-value operand, including one passed to a borrowed parameter, stays type/try_position)
Status: LG18: G-LG14-2 partial (a statement with inout binds earlier operands when no earlier operand and no `?` operand touches the inout roots or has an effect; a borrow before a move in another call is bound; a quantifier, subview, a move of a name used again or a non-value name shared with the rest of one call stays rejected)
Status: LG18: G-LG15-1 open (the && / || lowering is unchanged; lifting inout there needs its own order argument and a Rust build this lane had no budget for)
Status: LG18: G-LG15-2 partial (LLVM ok_val of a Result<T, String> parameter in a runtime requires or kept cost clause reads struct, enum, Option and Result payloads, same result as the Rust backend; the legacy-normalized Option<i64> / Result<i64> payloads stay codegen/unsupported_type, G-LG18-2)

## What landed

- Owned temporaries (G-LG14-1). An earlier operand of a type that is not a value may now be bound only when it is
  a `Vec`, `HashMap` or `String` that is a call result (not `subview`) or a plain `move x`, and it is directly an
  argument of a non-foreign user function for a `take` parameter of exactly its type. The call gets
  `move __pruv_try_tN`, so the temporary holds exactly the value the argument held and is consumed by the same call
  as before. Values the lifted call itself borrows while it runs (a `String` built in its own argument list) are
  dropped at the end of the `let` instead of the end of the statement; the recheck found this and it is G-LG18-4. A borrowed parameter is not
  lifted (its temporary would be dropped at the end of the block instead of the statement, which a host allocator
  could observe, G-LG18-3), nor a parameter of another type (`Vec<T>` to `[T]` coerces places only). Everything else
  of a non-value type stays `type/try_position`: a borrow of a live local, a field, an index, a reference, a type
  holding one, an argument of a builtin or a constructor, a foreign function argument.
- Inout statements (G-LG14-2 a). A statement that passes `inout` now binds its earlier operands when every inout
  argument is a local or a field of one, no earlier operand and no `?` operand of the statement mention an inout
  root, no earlier operand passes `inout` itself, and no earlier operand and no `?` operand call `print` or a function
  with an effect other than `alloc`. Those are exactly the facts the inout alias and effect checks (`inout_alias`, `inout_context`'s
  effect-before rule) would read from the earlier operand, so the bound statement gets the same verdict.
- Borrow before a move (G-LG14-2 b). An earlier operand that borrows a name the statement moves later is bound
  unless the borrow and the move sit in one call (nested calls share one borrow track, `foreign_borrow` unlowered).
  The check covers every temporary and every `?` operand: a non-value name it mentions may appear again in a call
  holding it only as a direct argument of a borrowed user-function parameter; an explicit move, an implicit move
  through `Err(x)` or a constructor argument, or any other use stays `type/try_position`. The temporary
  keeps the borrow before the move, as in the unlowered order. A move of a name the statement mentions again stays
  rejected: unlowered it is always a use after move or a borrow conflict, so no valid program is lost.
- `ok_val` on LLVM (G-LG15-2). In a runtime-checked `requires` and a kept `cost` clause, `ok_val(r)` of a
  `Result<T, String>` parameter now reads a struct, enum, `Option` or `Result` payload, not only `i64` / `bool`: it
  loads field 1 of `{ i1, L(T), ptr }` and converts it with `to_c` into the contract form, like the Rust backend's
  `pruv_to_c` of the cloned payload. The brief's `u8`..`u64` / `i8`..`i32` / `String` payloads do not exist: there
  are no scalar integer types besides `i64` (they are array element types only), a `String` payload is
  `type/foreign_owned_type`, and a recursive or array-holding `T` is `type/type_argument`. The legacy-normalized
  `Option<i64>` and `Result<i64>` payloads keep a different storage form and stay `codegen/unsupported_type`
  (G-LG18-2); no new mirror layout was added.

## Gaps

| Id | Gap |
|---|---|
| G-LG18-1 | With no temporaries, a `?` whose operand reads an inout root of the same statement (for example `Ok(use3(get(y)?, inout y))`) is accepted, while the unlowered expression would be `type/inout_context`; an effect call in the `?` operand before an inout call also escapes the effect-before rule (pre-existing since LG13; not fixed here; with temporaries both are now rejected). The same no-temporary path also accepts a borrow and a move of one name in one call when the borrow sits in the `?` operand (`Ok(eat(inspect(s)?, move s))`, unlowered `type/foreign_borrow`); main 75747c13 accepts all three too. |
| G-LG18-2 | LLVM `ok_val` in a runtime `requires` / kept `cost` of a `Result<Option<i64>, String>` or `Result<Result<i64>, String>` parameter (legacy-normalized payload storage) is `codegen/unsupported_type`, while the Rust backend reads it. Needs the legacy payload layout in `to_c`. |
| G-LG18-3 | An owned temporary for a borrowed parameter (`lend(mk(), f(x)?)`) stays `type/try_position`: lifting it needs a drop at the end of the statement (a scoped block around the lowered statement), not the end of the enclosing block. |
| G-LG18-4 | An owned temporary lifted for a `take` parameter (`Ok(eat(mk(string_from("a")), noisy()?))`) drops the values its own call borrowed (here the `"a"` `String`) at the end of the `let`, before the `?` operand runs, instead of at the end of the statement. Output is the same, but the drop moves before an effect, which a host allocator can observe. Main 75747c13 rejected this (`type/try_position`); both compilers now accept it. Fix: lift only when every argument of the lifted call is a value, a place or a `move`, which is a check in `try_owned_temp` / `try_temps` of both compilers (no Rust build budget was left in this lane). |
