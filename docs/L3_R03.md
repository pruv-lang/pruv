## 2. Hand lane (A)

`bench/l3/json/hand/hand_json.rs`: one grammar pass over borrowed input, tape filled as containers close (span, skip,
count), UTF-8 checked inside the string scanner, accessors walk spans and skips. Counters: allocations (count, bytes),
copied bytes, visited records. Equality (`bench/l3/json/run_r03_equal.py`): 0 mismatches over 116 A2 fixtures, 6344 A4
fixtures and 1200 seeded cases from 400 documents, both sides of the byte and record limits. On a grammar error the hand
parser scans the rest for invalid UTF-8 so error kind 4 keeps A2's priority.

Measurement (`bench/l3/json/run_r03_measure.py --root <root>`): inputs 64 KiB / 1 MiB / 8 MiB (S/M/L); parse, and
parse + a chain of 1 / 10 / 100 successful index/field steps; median of 7 in-process paired samples after one warmup;
peak RSS from a fresh process per lane and cell (`wait4` `ru_maxrss`; `/usr/bin/time -l` was blocked by the sandbox).

## 3. B: local Document / NodeId bounds from one root

`bench/l3/json/b_root.pruv` (manifest `b_root.pruv.json`, test `run_r03_b.py`) is a4's accessor path
(`pkgs/access/access.pruv`, unchanged, so its other consumers are untouched) as a local root, with the parse facts
lifted into flat `requires`:

- F0 `len(tape) % 6 == 0`, `6 <= len(tape) <= 6291456`, `len(source) <= 16777216`
- F1 kind in 0..7; F2 `0 <= start < end <= len(source)`; F3 `t < skip[t] <= m`
- F5 for `t > 0`: parent `< t`, parent kind 5 or 6, `t < skip[parent]`, `skip[t] <= skip[parent]`, span inside parent span
- array count fact (array_length only)

The only package change is one more ensures in `pkgs/parse/parse.pruv`: `Parsed ==> len(document.source) == len(input)`.

Removed checks (a4 -> b): `array_at` stop bound, `next <= j`, `next > stop`, valid(j); `find` / `find_ascii` stop bound,
`next <= v`, `next > stop`, key span checks; `raw_span` keeps only -3; `array_length` has no -4. `raw_span` and
`array_length` also require F1 (kind 0..7), so "kind > 7 -> -3" is a precondition, not a check. Kept: the per-step
-4 checks that the flat facts do not imply: key at j with parent id and `skip[j] == j+1` (single-record key), value at
j+1 with parent id and kind != 7 (key/value alternation). Proving them needs the nested subtree fact (G3) or a count
range split (G2).

Audit (Codex gpt-6.2-astra ultra, one pass): two MUST-FIX, both fixed. (1) `raw_span` / `array_length` lacked F1, so a
tape `[8,0,1,1,-1,0]` met the contract but returned span `[0,1)` / -2 where a4 gives -3. (2) `find` / `find_ascii` had
dropped `skip[j] != j+1` and the value `kind == 7` check, which no requires fact covers; on `{"a":0}` with key skip 2->3
or value kind 3->7, a4 gives -4 and b gave id 2. Neither tape can come from `parse` (check_tape rejects both), so the
published behaviour was already equal; the fix makes the contracts match a4 for every tape that meets them. After the
fix: verified, 6344/6344. No delegated recheck (the fix restores a4's own checks and adds one already-proved fact).

Excerpt, a4 vs b `find` loop body:

```
// a4 (pkgs/access/access.pruv:59-72)
if stop <= id || stop > len(doc.tape) / 6 { return -4; }          // before the loop
if doc.tape[6*j] != 7 || doc.tape[6*j+4] != id || doc.tape[6*j+3] != j+1 { return -4; }
let v = j+1; if v >= stop || !valid(doc, v) { return -4; }
let next = doc.tape[6*v+3];
if next <= v || next > stop || doc.tape[6*v+4] != id { return -4; }
if s < 0 || e < s || e > len(doc.source) || e > 16777216 { return -4; }
// b (b_root.pruv:88-92)
if doc.tape[6*j] != 7 || doc.tape[6*j+4] != id || doc.tape[6*j+3] != j+1 { return -4; }
let v = j+1; if v >= stop || doc.tape[6*v] == 7 || doc.tape[6*v+4] != id { return -4; }
let next = skip_of(doc, v);   // ensures next == skip[v] && v < next <= skip[id]
```

Hand (`hand_json.rs`) does the same walk with no -4 checks at all, trusting its own tape.

Verification: b verifies and compiles on rs/rust and rs/llvm; `run_r03_b.py` 6344/6344 A4 fixtures exact.

## 4. Generated vs hand excerpts (A)

1. Copies (`pkgs/json/json.pruv:75`): generated
   `JsonDocument { source: source.to_vec(), tape: tape.to_vec() }`; hand `struct Document<'a> { source: &'a [u8], tape: Vec<i64> }`
   (moves the tape, borrows the source).
2. Publication rescan (`pkgs/parse/parse.pruv:218` -> `check_tape`): generated `while r < m { if !scan_ok(tape, r) { return false; } r += 1; }`
   (descendant scan per record); hand writes span/skip/count when each container closes and never rescans.
3. Whole-input UTF-8 (`pkgs/parse/parse.pruv:259`): generated `validate_utf8(input, 0, n)` then `scan(input)`; hand
   checks `std::str::from_utf8` on each non-ASCII scalar inside the string scanner.

## 7. Language gaps (minimal repro and proposed root rows)

- G4 array value into a struct field without a copy.
  Repro (observed): `pkgs/json/json.pruv:75` written as `JsonDocument { source: source, tape: tape }` is rejected with
  `array_alias: an array value here must come from alloc(), copy() or a function call`; the minimal shape is
  `struct D { a: [i64] }  fn w(a: [i64]) -> D { return D { a: a }; }`. Proposed row: move (consume) of an owned array parameter into a record
  field, and a borrowed `[u8]` source field tied to the input's lifetime.
- G3 nested quantified tape facts time out. Repro: an accessor `requires forall t in 0..m: (forall k in t+1..skip[t]:
  parent[k] >= t)` (subtree fact) or `forall t: kind[t] == 5 ==> forall k in t+1..skip[t]: parent[k] == t ==> kind[k] != 7`
  makes the `find` loop VC time out; also the trigger `6*t+3` does not fire for `6*(j+1)+3` (worked around with the
  opaque `skip_of` helper). Proposed row: user-named triggers or a lemma form for array-index quantifiers.
- G1 no named invariant predicate / verified handle type. The same five flat facts are repeated on every accessor
  (b_root.pruv:16-19, 72-76, 100-104, 134-138, 174-178) and cannot be attached once to `JsonDocument` or a `NodeId`.
  Proposed row: named predicates over a record (`pred tape_ok(d: JsonDocument)`) or a refined type
  `JsonDocument where tape_ok`, established once by parse.
- G2 no count range split lemma: `count(k in a..c: P) == count(k in a..b: P) + count(k in b..c: P)` is not available,
  so `array_at` cannot prove `n == index` reaches the array count and keeps its -4 parent/kind check.
  Proposed row: built-in count split / monotonicity lemmas.

## 9. R03L: json language roots (G4, G1)

Main decision 2026-11-20: before R03 C, close the §7 gaps G4 and G1 in both compilers (G3 and G2 queued, see below).

- G4, rule R-6e-12 (SPEC.md): `move x` moves an owned array local or a `take x: [T]` parameter into a struct field,
  enum payload, local, assignment, return or `take` argument with no copy; a later read is `type/foreign_move`.
  `parse::scan_document` (pkgs/parse/parse.pruv) now builds the `JsonDocument` itself: the finished tape is
  `truncate`d in place and moved into the field (`tape: move done`). `json::wrap_document`, which copied both
  buffers, is deleted. The source is still copied once (`copy(input)`), because `parse` only borrows its input; the
  source handoff is R03 C.
- G1, rule R-6-2 (SPEC.md): `pred fn` names one contract expression. `pkgs/json/json.pruv` defines `doc_shape`,
  `doc_kinds`, `doc_spans`, `doc_skips`, `doc_parents`, `doc_array_counts`; `parse`'s `ensures` and the b_root
  accessors' `requires` use them. Each use is expanded to the body (nothing assumed), so `parse` still proves them
  from the code and every accessor call still checks them.

Rust truncate (both compilers): an in-place `truncate` that leaves over half the capacity unused now calls
`shrink_to_fit`, so the moved tape does not keep the 2x growth slack alive (LLVM keeps the source capacity; debt row).
