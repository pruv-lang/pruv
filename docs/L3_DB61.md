# L3 DB61: claude on bench/l3/pkgs, parse tape sizing, llvm allocation count

Brief: (1) G-DB60-1, move claude onto `bench/l3/pkgs`: add `access::fields_into` to pkgs, reconcile the parse tape
sizing, point claude's manifests at pkgs, drop from lib only what no remaining lib user needs. (2) G-DB60-3, explain or
fix the llvm allocated bytes far below hand. (3) claude M/L old (main 97fbe68f) vs new vs hand, four pairs, at least 10
rounds. Base: main 97fbe68f. One release `pruvc-rs` build in the worktree; no compiler, runtime, stdlib or test change.

## What landed

- `bench/l3/pkgs/access/access.pruv`: `fields_into` and its helpers `hit`, `slot_error`, `fill_error`,
  `field_if_used`, `last_match`, and the `find_ascii` prefilter (DB25/DB29/DB39 text from lib, unchanged).
- `bench/l3/pkgs/parse/parse.pruv`: `first_slots(n, lo)` takes the floor from the caller, `scan` passes 192 and
  `scan_document` 96 (lib DB39 sizes); `widened` grows to `2*len+6` (lib DB39) instead of `2*len+192`. The DB55
  `n/16` scaling and the 4096 cap stay for long lines.
- `bench/l3/claude`: the six symlinks into `../lib` (`access`, `json`, `jstr`, `lex`, `lines`, `parse`) are gone;
  `root.pruv.json`, `q_root.pruv.json` and `a0_root..a4_root.pruv.json` map the package modules; `test_a0..a4`, `q.py`,
  `q_measure.py` and `q_mutants.py` pass `--manifest`.
- `bench/l3/lib/access.pruv` and `bench/l3/lib/jstr.pruv`: `fields_into`, its helpers, `access::string_text_owned`,
  `jstr::string_text_owned` and `jstr::owned_text` removed. No remaining lib user calls them (grep over qwen, json,
  supervisor, mcp, budget, entry, req; the budget `owned_text` hits are local functions of the same name).

## Decisions

| Id | Decision | Why | Where |
| --- | --- | --- | --- |
| D-DB61-1 | G-DB60-3 explained, no fix: llvm's low allocated bytes are real fewer malloc calls, not missed requests | the llvm runtime's P3 per-thread free-block cache (`pruvc/runtime.c`, blocks up to 1024 bytes, 4 per 8-byte class, 64 KiB budget) hands freed blocks back to `pruv_raw_alloc_v3`/`pruv_raw_alloc_zeroed_v3` without malloc; claude's per-line tapes (old 768- and 288-byte callocs) never reach libc. Trace on turns200 head: llvm 41 blocks / 53,647 B, rust 7243 blocks / 2.81 MB (2400 calloc 768, 2400 calloc 288), hand 4831 blocks / 3.08 MB (4800 malloc 632). The interposer counts system allocator traffic, not Pruv allocation requests | `pruvc/runtime.c`; `bench/l3/claude/work/DB61/rows.json` |
| D-DB61-2 | pkgs parse first tape and growth take the lib DB39 sizes for short lines (`scan` 192, `scan_document` 96, `widened` 2*len+6), DB55 `n/16` up to 4096 stays for long lines | the DB55 floor 192 and +192 made claude's tapes larger than 1 KiB, so llvm lost the free-block cache (41 to 4840 blocks on turns200 head) and rust doubled bytes; time +10-25% on head/tail/window | `bench/l3/pkgs/parse/parse.pruv` |
| D-DB61-3 | lib keeps only what qwen, json, supervisor, mcp, budget, entry and req use; the claude-only functions moved to pkgs | one copy per function | `bench/l3/lib/access.pruv`, `bench/l3/lib/jstr.pruv` |
