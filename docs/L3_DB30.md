## Step 1 and 2: why the shape ensures and the borrowed scan did not land

`json::check_tape` proves 13 quantified facts on the finished tape, among them per-record count and
key/value alternation facts that hold only after the whole container is closed. Stating them as `ensures`
of the one-pass `parse::scan` needs a loop invariant over partially built containers whose counts are
split across a range (R03L-G2, count range split lemma) and triggers for nested index quantifiers
(R03L-G3). Both are open language items; R03 C (drop the `check_tape` rescan) is pending on them.
This is a language gap, not data representation, so it is recorded as G-DB30-1 and not attempted within
the cap. The per-member checks in `access::field` stay for the same reason.

`JsonDocument` owns its `source: [u8]`; a struct field cannot hold a borrowed `[u8]` (R03L), so the
scanned line must be copied into the document (`parse_line`) and `scan_shortened` must copy to write
`[]}`. The scan itself already reads the borrowed `subview`; only the document copy stays (G-DB30-2).
