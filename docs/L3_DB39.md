# L3 DB39: claude window reader on the DB33/DB34 document, and no shrink realloc per line (D-DB30-1, D-DB25-1)

Brief: remeasure the claude window cells (old = main c807fa6f, hand Rust = 1.0x), then remove per-line runtime work
that the `JsonDocument` invariant already proves (remaining `check_tape` passes, per-member shape checks, resize
copies), adding no runtime check. Costs that need a borrowed `[u8]` field (G-DB30-2) or the count frame lemma
(G-DB33-1/2) are recorded, not worked around. No compiler edits. The rs compiler was built once from this base
(00:10 KST, `pruvc-rs/target/release/pruvc`).

## What landed

- The claude reader compiles without manifests through the symlinks `bench/l3/claude/{json,parse,access}.pruv ->
  ../lib/*.pruv`, so the DB33 (`pkgs/parse`) and DB34 (`pkgs/json`, `pkgs/access`) work never reached it. This
  bundle ports it:
  - `bench/l3/lib/json.pruv` is now `pkgs/json/json.pruv` (LG16 `JsonDocument` invariant, `doc_*` preds,
    `check_subtrees`); `wrap_document`, used only by the old `lib/parse`, is gone.
  - `bench/l3/lib/parse.pruv` is `pkgs/parse/parse.pruv` without its `mod` header (`scan_document` +
    `publication_ok`, `parse`, `scan_into`), plus the two allocation changes below.
  - `bench/l3/claude/entry.pruv` `parse_line` calls `parse::parse` once. The old path was `validate_utf8`, then
    `parse::scan`, then `json::check_tape` (a full second pass over the tape), then `alloc` + `copy_range` of the
    source. `parse_line`, `scan_shortened` and `window_line` now ensure
    `is_variant(result, Line::Object) ==> json::doc_local(...)`, because the invariant is not carried through an enum
    payload (DB34).
  - `bench/l3/lib/access.pruv` drops the checks that DB34 dropped in `pkgs/access`. `valid` is now an id range test
    plus `kind <= 6`. Gone: the per-call span checks (`s < 0 || e < s || e > len(source) || e > 16777216`), the
    `stop <= id || stop > len/6` checks, the `next <= j` / `next <= v` halves of the skip checks, and the key checks
    `tape[6j+3] != j+1`. Exception: `fields_into` keeps `next <= v`, because without it its `decreases` proof timed
    out. The claude-only helpers (prefilter, `hit`, `slot_error`, `fill_error`, `field_if_used`, `last_match`) stay.
- No shrink realloc per line (`bench/l3/lib/parse.pruv`). The generated Rust for `truncate(tape, 6 * records)` calls
  `shrink_to_fit` when `capacity / 2 > len`. `scan_document` started every tape at 192 slots (32 records), and a
  claude window line has 8-13 records (82 864 lines of `window_8MiB`, median 12). So every accepted line paid an
  `xzm_realloc` + free at the end of the scan (`sample`: `RawVecInner::shrink` and `_xzm_free` under `parse_line`,
  `a4_pruv-82b9c604.rs:3573`). Now:
  - `scan_document` starts at 96 slots (16 records), so documents of 8-16 records keep their tape.
  - `widened` grows to `2 * len + 6` instead of `2 * len + 192`. A tape that grew is at least half full when it is
    truncated, so it never shrinks.
  - `widened`'s contract is unchanged; `scan` (used by `scan_into` callers) shares `widened` and still starts at 192.
- `bench/l3/claude/time.pruv`: `iso_of`'s 24-byte copy loop is a helper, `canonical_copy(b, p)`, with the
  `canonical_at` facts as requires.
  - With the invariant now assumed for every `JsonDocument` parameter, `iso_of`'s postcondition (line 325) timed out
    once in an rs verify at load 20-36.
  - Tree before the split: 82 s rc 0 at load 35. After the split: 57 s rc 0 at load 3.
  - The same split, no new check.

## Remaining gap vs hand (line level)

Hand, `bench/l3/claude/handrust/src/lib.rs:498`: `parse_line` is `str::from_utf8(line)`, then one recursive descent
into a borrowed `Object<'_>`. Each object is a small map whose strings borrow the line; there is no copy of the line
and no second pass.

Pruv, `parse_line` -> `parse::parse` (`lib/parse.pruv:513`) does:

- `scan_document` (`:360`): one pass that writes the 6-slot tape. Same order of work as the hand descent; it also
  stores skip, parent and count. This pass is the 627-sample top of the profile.
- `copy(input)` (`:408`): one `alloc` + `memcpy` of the whole line per accepted line. Hand borrows. This is G-DB30-2
  (a struct field cannot borrow `[u8]`).
- `publication_ok` (`:484`) -> `json::check_subtrees` (`lib/json.pruv:255`): a second pass over the tape at runtime
  (the `scan_ok` count and parity facts, and the containment loop). Hand has no equivalent. This is G-DB33-1/2 (count
  frame lemma).
- The tape `alloc(96)` (768 zeroed bytes) per line, plus a shrink realloc for documents of 7 records or fewer.
  Hand allocates a map per object.
- Access (`fields_into` 215 samples, `string_is` 122): the claude-side reads, the counterpart of hand's `m.get(k)`.

The remaining work items are G-DB30-2 and G-DB33-1/2, already open, plus the small-document shrink (G-DB39-1). They
need a language feature or a new proof analysis, so DB39 stops here.
