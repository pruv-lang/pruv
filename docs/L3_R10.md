# L3 R10 supervisor (A + B + C)

Status: done, with debt. A (hand lanes, matched startup/hash), B (local tail bounds proved, no runtime checks in the
generated core) and C (byte tail handoff) are in. Time cells over 1.0x are listed as debt rows D-R10-n. For the main
conversation to copy into `docs/L3_RESTRUCTURE_SPEC.md` §7.4 (this file does not edit the spec).

## 1. What landed

| Part | Files | What |
|---|---|---|
| C byte tail | `bench/l3/supervisor/btail.pruv` | Two WHATWG UTF-8 decoders (stdout, stderr) write into one `[u8]` buffer of valid UTF-8 (6T+4 slots) with a cached UTF-16 unit count. No code point is widened to UTF-16 units. When the units go past 2T (or the bytes past 6T), whole code points are dropped from the front down to T units and 3T bytes. The output is the longest suffix of whole code points with at most T UTF-16 units, which equals the old TS tail (policy P5). |
| C handoff | `supervise.pruv`, `a1_root.pruv` (+ `.json`) | The supervisor and the A1 root use `btail` (local module) in place of `pkgs/tail`. The pipe read slices go straight to `tail_push_range` (`[u8]`, no copy). |
| B | `btail.pruv`, `core_root.pruv` (+ `.json`) | Every buffer and state index is proved from `requires`, `ensures` and loop invariants (`len(ts)==13`, `len(buf)==6T+4`, `ts[0]<=6T`, `0<=ts[12]<=2T`), so the generated core has only `get_unchecked`, with no bound checks. `core_root.pruv` is the in-process core lane: `core(t, data, chunk) -> [u8]`, chunks alternate stream 1/2. It verifies on all 4 pairs. |
| A | `hand/core_hand.rs`, `hand/core_main.rs`, `hand/pattern.rs`, `hand/supervise_hand.rs`, `measure_r10.py` | The hand Rust core does the same algorithm in safe Rust with `copy_within`. The hand supervisor uses threads, `sync_channel` and a control socket. The shared harness and the input pattern match on both sides (startup and FNV-1a 64 hash). The measure script builds both sides, alternates runs, takes the median of 7, checks that outputs are equal and writes `bench/l3/supervisor/work/r10/perf_cells.json`. |

Bugs: none found.

## 4. Gaps (language / compiler / lib; worked around, not fixed)

| Id | Gap | Workaround |
|---|---|---|
| G-R10-1 | `copy_range` rejects aliased dst/src (SPEC.md:136-148), so there is no memmove. | `trim` moves the kept rest to the front with an explicit byte loop (`btail.pruv:77`). |
| G-R10-2 | The byte tail belongs in `bench/l3/pkgs/tail`, but that package is outside this bundle's lane. | It lives as the local module `bench/l3/supervisor/btail.pruv`. Moving it into `pkgs/tail` (and dropping the UTF-16 tail there) is left for the main session. |

## 5. Debt (time cells over 1.0x)

| Id | Cells | Line-level cause |
|---|---|---|
| D-R10-1 | rs/llvm core, all 8 cells (1.20-1.51x) | `put_cp` (`btail.pruv:105`) is not inlined by clang -O2. The LLVM object keeps `_pruv_m_f_2_5_btail_6_put_cp__pruv_body` out of line, called once per code point from `dec_byte` (`btail.pruv:172,181,190,208`). The hand side inlines its push. One fix try (one call site) did not change the inlining, so it was reverted. Likely fix: inline hints or a cost change in the LLVM backend (`pruvc*`, outside the lane). |
| D-R10-2 | rs/rust core chunk 65536 (M 1.023-1.024x, L T65536 1.069x) | From reading the code, not profiled: the decoder state `ts[base..base+5]` and the counters `ts[0]`, `ts[12]` are loaded and stored through the `ts` heap array on every byte in `dec_byte`/`put_cp` (`btail.pruv:157-210`, `105-150`; a design choice in this bundle, not a language gap). The hand core keeps them in struct fields that stay in registers across the loop. |
| D-R10-3 | whole lane, both pairs (rs/rust 1.07-1.10x, rs/llvm 1.22-1.30x) | The event loop in `supervise.pruv:217-253` (`ev_wait` / `ev_proc_read` from `bench/l3/lib`, outside the lane) does one poll round and a capture file write per 64 KiB read. The hand side uses blocking reads on 2 threads. rs/llvm also carries D-R10-1. |
| D-R10-4 | whole lane RSS 1.018-1.067x (about +1.3 MB) | Event buffers in `bench/l3/lib` (ev_ loop state) on top of the hand side's two 64 KiB thread buffers. The core RSS (+0.0-1.1%) is the `ts` array and the `tail_bytes` copy on output. |
