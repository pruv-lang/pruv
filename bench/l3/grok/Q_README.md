# Grok import Q (differential and mutants)

The scripts were written without a shell; the results below come from running the three commands below on 2026-11-17
(RESULTS.md section 136).

Run `test_impl.py` first: it builds `work/host`, `work/libpruv_str.rlib` and the four runners `work/{py,rs}_{rust,llvm}/runner`
that `q.py` and `q_mutants.py` reuse. All three need Node 26.4.0 (`GROK_NODE` overrides the default `/opt/homebrew/bin/node`) and
`GROK_TS_TRANSPILER=/path/to/typescript` (the reference transpiles `plan.ts` with it; there is no built-in default).

```
PATH="$HOME/.cargo/bin:$PATH" GROK_TS_TRANSPILER=... python3 bench/l3/grok/test_impl.py          # fixed fixtures, four pairs
GROK_TS_TRANSPILER=... python3 bench/l3/grok/q.py --cases 2000 --seed 20261116                    # random + fixed, TS vs pairs
GROK_TS_TRANSPILER=... python3 bench/l3/grok/q_mutants.py                                         # M01-M16 on rs/rust
python3 bench/l3/grok/q_mutants.py --check                                                        # which mutation variant applies (no build)
```

## What a case checks

Every case (fixed or random) runs once on the pinned TypeScript (`reference.mjs`) and once on each pair, each in its own freshly built
tree and fake ACP (`q_server.py`, argv exactly `agent --no-leader stdio`). `oracle.compare` then checks, with no relaxation except the
named policies:

| Area | Compared |
|---|---|
| result | status, rows, title, model, value, present, copySkipped, omittedBefore; error stage/class/code (+ OS facts for raw OS errors, raw code for RPC errors); numbers as binary64 (P10) |
| ACP transcript | argv, every request the client sent in order (ids, content, replies to server requests), recorded violations (`initialized`, ids, capability gate, env/cwd/GROK_HOME) |
| primitive trace | per-path order of readdir/lstat/realpath/open/fstat/read/close/mkdir/rename/rm/create/write/entropy, handles/dev/ino as relations, offsets as contiguous ranges, listing candidates grouped per candidate |
| final trees | bytes, kinds, modes and symlink targets of the whole source and target after the run (before/after snapshots) |
| concurrency | list fixtures with `concurrency`: peak outstanding requests and "E started before A completed" from the trace |

A difference passes only through the policy whose trigger is detected from the case inputs (`oracle.triggers`): P1 invalid UTF-8 / depth,
P2 lone surrogates and the 120-unit cut, P3 trailing U+FFFD after a clip, P4 unsupported date tokens (judged against a TS rerun of the case
whose date tokens were edited, `oracle.p4_case`), P5 growth past 16 MiB, P6 id token / premature id in one write, P7 lifecycle (watchdog
limit, never a success), P9 `num_chat_messages`, P10 overflowing number tokens, P12 read boundaries (P11 stdin half-close compares equal since transport adoption). P8 does not apply.
Fixtures with an `expected` block are also checked against the TypeScript result itself (a fixture that does not do what it says is a
fixture bug, reported as `ts/expected`).

## q.py

`--cases N --seed S` (we run `--cases 2000 --seed 20261116`). Case `i` is generated by `random.Random(seed * 1000003 + i)`, so a seed gives
the same 2000 cases every time (`--dump-cases FILE` writes them; diff two dumps to check). Families and weights: list 30, read 30,
copy 16, load 12, small-json 8, caller-cleanup 4. Random content: 0-70 sessions with valid/invalid names, fractions/exponents/garbage dates
(P4), missing dates and ties (sort schedule at sizes on both sides of 7/64), message counts (P9), titles at the 120-unit cut (P2), non-directory
entries, active-session files (ids, objects, empty ids, unreadable/symlink/oversize); histories with tags, synthetic reasons, prompt_index,
tool calls, junk lines, invalid UTF-8, oversized and boundary-size lines (1048577/1048578, CR), 200/201 turns, 32 KiB clips; copies with
random file sets, non-allowed and non-regular names, pre-existing targets, second-lstat races, temp collisions and injected faults
(mkdir/rename/readdir/lstat/create/write/read/rm); small JSON with raw tokens (`1e400`, `-0`, big integers), lone-surrogate keys and values,
size boundaries; ACP scenarios (capability variants, errors with every code type, notifications and server requests incl. null/string/overflow
ids, malformed lines, stderr flood, early exit, spawn failure, stalls with 300 ms deadlines on both sides, premature id 2). Stalls use equal
short deadlines and the fake never answers them, so no case races a response. Listing never gets live mutations (outside the equivalence domain).

The fixed fixtures run first in the same report unless `--no-fixed`. Output: `work/q-report.json` (seed, counts per pair by class
`exact` / `policy:Pn` / `note` / `unexplained`, the first 100 unexplained cases with their first differences, policies observed, wall time).
Exit 1 on any unexplained difference or any `expected` mismatch.

## q_mutants.py

Sixteen single-bug mutants (the spec's M01-M16), applied to **copies** of the `.pruv` files in `work/mutants/Mxx/` (manifest paths rewritten, the
originals never touched), built with the Rust compiler and Rust backend only (`rs/rust`), then run against the same fixtures and the
reference. Unmutated fixtures that already fail on the baseline `work/rs_rust/runner` are excluded first. Result per mutant:
`differential-killed` (a fixture differs from TS beyond the policies), `verifier-rejected`, `survived`, `build-error` (a tool error is not a kill),
`pattern-missing` (the edit did not apply). Crashes and watchdog kills never count as kills. Default: the fixtures mapped to the mutant run first
and the run stops at the first kill; `--full` runs everything. Report: `work/mutants/report.json`.

How an edit is found (variants in this order): **marker** line `<statement>  // MUT:Mxx => <replacement statement>` (the module owner adds one
per mutant; the whole line is replaced, indent kept), then a function-body injection (`fn NAME(` from DESIGN section 3) or a regex guess. Run
`q_mutants.py --check` after the modules exist: it prints the variant that applies, or `PATTERN MISSING`.

Intended edits for the markers (what the replacement statement does; one marker line per mutant, each on the statement that implements the rule):

* M01 `encode_folder` result is the raw UTF-8 bytes of `folder`. M02 the directory test of the lstat completion also accepts kind 3. M03 the identity
  comparison of the fstat completion against the lstat expectation is replaced by "equal". M04 the info.cwd folderKey comparison is replaced by "equal".
  M05 the "start the next candidate" test also requires fewer than 50 finished candidates. M06 in the comparator, a missing date makes `cmp` return +1
  (b newer) or -1 instead of 0. M07 the empty-id check that stops the fallback is removed. M08 the unwrapped text is trimmed. M09 the synthetic_reason
  test accepts only a string value. M10 the drop marker no longer detaches the draft / marks the next prompt clipped. M11 `turns::tool(.., 1)` instead of the
  array length. M12 `omitted = window_omitted` (the collector trimmed flag removed). M13 the allow-list test returns true. M14 the second-lstat success no
  longer raises grok-exists. M15 the post-verify-failure remove request is not issued. M16 the capability test is `!= null` instead of `== true`.
