## What a case checks

Every case runs once on the pinned TypeScript (`reference.mjs`) and once on each pair, each in a freshly built tree with the same closed SQLite
image(s) (WAL sidecars included) and its own copy of the fake exporter. `oracle.compare` checks, with no relaxation except the named policies:

| Area | Compared |
|---|---|
| result | status, mode, rows / turns, optional fields present or omitted, omittedBefore, title, model, lastPlan / present, value; error stage, class, code, native and raw code (cause facts), detail when `columns`/`json`/`shape` |
| primitive trace | the whole sequence per DESIGN section 5: SQL prepare/all/get with typed parameters and typed ordered results, connection/statement lifetime, admission calls, mkdtemp prefix/location, wx/0600, spawn argv/cwd/effective env/stdio, observe/kill/close/stat/read/rm order, schedule events |
| fake exporter | argv, violations (cwd, env presence/absence, fd 1 regular file, stdin/stderr `/dev/null`, process-group leader), bytes written, exit reason |
| final trees | kind, mode, size, sha256, link targets of `src`, `home`, `tmp`, `folder` (sidecars included; `-shm`: size and mode only) |
| cross-pair | in `q.py`: all pairs agree with each other on result, normalised trace, trees and exporter transcript |

Normalised: fixture roots, opaque handles, request ids, random temp suffixes (prefix/location asserted first), monotonic readings. Not
normalised: slashes, row order, failed calls, cleanup placement. A watchdog kill or a missing measurement is a failure, never a pass or a kill.

## q.py

`--cases N --seed S` (the plan: `--cases 2000 --seed 20261117`). Case `i` is generated by `random.Random(seed * 1000003 + i)`; `--dump-cases FILE`
writes the expanded list (diff two dumps to check determinism). Families (weights): read 44, list 26, plan 10, rows 8, dataDir 6, folderKey 6.
Generated variation: schemas (archive column present/absent, rare missing session/message columns), raw SQL storage classes for every column
and insertion order, invalid/non-text ids, directory slash variants, archived/child rows, message counts, `OPENCODE_DB` variants, DB faults;
export documents with unknown roles, summary assistants, blank/synthetic/ignored marks (boolean and non-boolean), model pairs, created/completed
tokens (supported and P4-unsupported), todowrite plans (status/blank/long/astral content, 0-34 items), tools, malformed messages/roots,
200/201-turn documents, invalid UTF-8, depth 128/129, lone surrogates and U+FFFD at clip boundaries; real child outcomes (nonzero exit,
self-signal, hang with TERM exit or TERM ignored), missing binary/temp root, injected faults at mkdtemp/open/spawn/close/stat/read/rm and SQL
phases. Only the list clock is frozen. Hang cases use `rpcMs` 300 on both sides, the 1.5 s / 1 s grace periods stay real, and all
timer-sensitive cases run serially; the real 20 s probe is the fixed slow fixture `F08-real-20000ms`. The boundary exports of 16 MiB and
above are fixed fixtures (F09), not generated.

Reports (written into `work/`): `q-report.json` (counts per pair by `exact` / `policy:Pn` / `note` / `unexplained`, the first unexplained cases,
fixed-fixture `expected` problems, cross-pair disagreements) and `q-policies.json` (per pair and policy: the cases an explained deviation
covers, kept apart from unexplained failures and from excluded-domain observations). Exit 1 on any unexplained difference, `expected` mismatch
or pair disagreement.

## q_mutants.py

Sixteen single-decision mutants on **copies** of the `.pruv` modules in `work/mutants/Mxx/`, built one at a time on rs/rust, then run on the named
killing fixtures (`--full`: on every other non-slow fixture too).

**Markers.** The owner of each target module adds exactly one line at the intended decision:

```
<the baseline statement>   // MUT:M07 => <replacement statement>
```

`q_mutants.py` replaces that whole line (indent kept) by the replacement. The marker text is the literal `MUT:Mxx`; `--check` requires it exactly
once among the `.pruv` files of this directory, inside one of the listed target files, syntactically a marker line, and the killing fixtures to
exist. There are no regex fallbacks. Result classes: `differential-killed`, `verifier-rejected` (both kills), `survived`, `build-error` and
`crash`/watchdog/harness error (never kills), `pattern-missing`, `baseline-failed` (the unmutated `work/rs_rust/runner` must first pass every named
fixture; its trace must contain no pipe-stdout spawn, the M10-only flag).

| # | Mutant | Target file(s) | What the replacement statement does | Killing fixture(s) |
|---|---|---|---|---|
| M01 | memory-means-default-db | `path.pruv` | exactly `:memory:` resolves to the default `join(home,"opencode.db")` instead of "no database" | `F01-db-memory` (no db_open) |

## Assumptions and open points (for the integrator)

Names this package imports from E's files (all present in the current `common.py` / `test_impl.py`; reconcile if they change):
`common`: `HERE WORK clean bytes_of logical_path normalize_trace TraceAssertion`. `test_impl`: `FIXTURES load_fixtures expand_case dump macro
run_reference run_pair judge check_expected impl_clean timer_sensitive configure host_artifacts compile_flags link_runner parse_pairs`.
`test_impl.run_reference` calls `oracle.baseline_cases(run)` and `judge` calls `oracle.compare(case, ts, impl, base)` / `oracle.unexplained(diffs)`.

Points to reconcile:

1. **Markers**: none of the mutation-target modules existed; every marker position and replacement in the table is derived from DESIGN and must be
   added by the module owners (`q_mutants.py --check` lists what is missing).
2. **Stage of decisions**: the reference reports `read-admission` for not-found (valid thread) and engine-missing after the DB close, `wait` for
   timeout / nonzero exit / child error, `parse` / `shape` for JSON failures, `input` for an invalid thread; `expected` blocks use those names. Pruv's
   result stages must match (DESIGN section 5 lists the numbers, not these decisions). P5's `InputTooLarge` is compared by class/code only.
3. **Cause facts**: error `native` / `rawCode` are compared for every error (wrapped DB errors carry the SQLite extended code and its `SQLITE_*`
   name, `ERR_OUT_OF_RANGE` with native 0, OS errors errno and `E*`). DESIGN says they survive wrapping; the packet's raw-code ref must carry them.
4. **Trace stages**: oracle ignores `stage` of `clock_now`/`observe` (16/17/18 by wait phase in the reference). Other records compare stages:
   realpath 1 then 3, lstat 2, open 4, schema 5/6, select 7, count prepare 8, count 9, close 10, wall clock 12, mkdtemp 13, open 14, spawn 15,
   kill TERM 17 / KILL 18, close 20, stat 21, read 22, rm 23.
5. **Environment `_`**: `/bin/sh` sets `_` for the exec'd program (node vs runner path); the oracle drops it from the recorded spawn environment.
6. **DB bytes after `db-exec`**: a mutation by the shim (Node's SQLite) and by the host (locked rusqlite) writes the SQLite version number into the
   header, so `F04-live-count-mutation` / `F05-count-zero` can differ in the `src` tree hash if the versions differ. Mask or equalise if so.
7. **Tape limit**: `F09-tape-limit` / `F09-tape-over` count tokens (values, keys, container starts/ends; no commas or colons) against 1,048,576. If
   Pruv's record count differs, the boundary fixture shows it.
8. **Disabled fixtures**: `F08-error-after-timeout-script` (needs scripted child events in the host) and `F09-grow-after-stat` (needs `@N` in
   action paths in `host.rs`).
9. `F08-give-up-script` uses injected `kill` errors on a real child that ignores TERM (both signals fail, give-up after 1 s); the child is killed by
   host/harness teardown, outside the passing trace.
